# 2026-10-22

## 备份配置：收藏备份仍被自动清理 的分析

- 保留策略在 `CSBackupStore -prune:`（Controllers/CSBackupStore.m:120-129），由 `CSBackupEngine -save:kind:error:`（CSBackupEngine.m:82）在每次成功发布后调用；前台/版本升级也会触发 `save:`。
- 配额：automatic 20、protection+upgrade 5、manual 0（永不清理）、导入项不清理、`favorite` 为真则跳过。计数只统计"非收藏且非导入"的项。
- 缺陷根因：收藏标记只存在 sidecar `<uuid>.meta`，不在快照本体、也不参与 contentDigest。`-metadata:`（CSBackupStore.m:82-86）读取上限 16384 且任何异常（缺失/损坏/超大/非普通文件）都返回 `@{}`，不返回 error。`prune` 于是把收藏备份当普通自动备份，排到第 21 份时删除；`save:` 还传 `NULL` 丢弃 prune 的错误。
- 写入端 `-setMetadata:`（CSBackupStore.m:87-90）无大小上限，与读端 16 KiB 不对称。
- `-remove:` 只删 `.wcbak`，遗留孤儿 `.meta`。
- 已存在复现：`docs/audits/backup-retention-2026-10-22/`（verify.sh 自行编译运行），本次重跑 417 checks / 14 scenarios 全通过，确认 automatic+corrupt/missing/oversize/nonregular 的 .meta 会导致快照被静默删除。
- 代码套数结论：现役只有一套 v2（Manager→Engine→Store/Codec/Registry/Assets/Scheduler/Bootstrap）。"两套"来自：① `CSBackupInfo.h/.m` 旧模型仍被 Makefile 通配符编译但零引用（死代码）；② `CSBackupLegacyReader` 只读解析旧 `Library/Backup/<uuid>` + `backup_info.json`；③ git 历史 1.5.x 的 1273 行旧 `CSBackupManager`（整目录复制 plist）已在 1.8-41（1109280c）重写。
- 修复方向：收藏失败即 fail-closed（读不到 metadata 一律保留并报 warning）；favorite 写进快照本体或可重建索引；读写大小上限对齐；prune 错误上抛到 UI；删除时清理 `.meta`。

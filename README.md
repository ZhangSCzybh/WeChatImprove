# WeChatImprove

面向 iOS 微信的 Theos 插件，提供聊天分组、列表圆角、界面定制和消息操作增强。通过 Objective-C / Logos 接入微信原生界面，各项功能在插件设置中分别配置。

**当前版本：`1.6-24`** · **编译架构：`arm64` / `arm64e`** · **最低编译目标：iOS 15.0**

## 安装与入口

1. 根据设备环境选择 Rootless 或 Rootful 的 `.deb` 安装包。没有安装包时，可按下文从源码编译。
2. 使用设备上适配该环境的包管理器或安装工具安装；如工具提示重新加载注入环境，按其提示操作。
3. 完全退出微信后重新打开，进入 **微信 → 我 → 设置 → 再也不会**。
4. 按页面提示完成首次使用声明和公众号关注验证，再按需开启功能。

默认入口名称为“再也不会”，默认位于微信设置页。进入插件后，可在 **入口设置** 中修改名称，并选择显示在“我”、微信设置页或已有的插件管理入口；插件管理入口依赖宿主环境提供 `WCPluginsMgr`。

本仓库的直接构建产物是 `.deb`，没有提供可直接安装的 IPA 或现成的重签名流程。仓库也没有 `install.sh`，安装时使用上述包管理方式。

## 聊天分组

### 开启与管理

进入 **插件设置 → 聊天分组**，打开“启用聊天分组”，返回聊天列表即可查看分组栏。

| 分组 | 显示内容 |
| --- | --- |
| 全部 | 保留完整会话视图 |
| 群聊 | 识别为群聊的会话 |
| 私聊 | 识别为普通联系人的会话 |
| 服务 | 公众号、订阅号、服务号，以及可识别的服务聚合入口 |
| 自定义分组 | 手动选入该组的会话；同一会话可以加入多个自定义组 |

公众号和服务号仍会出现在“全部”，也可以显式加入自定义分组；不会自动混入“群聊”“私聊”或无关的自定义分组。无法可靠判断归属的其他业务入口可能保留在各组，避免丢失原生入口。

- **添加分组**：在设置页点击“添加自定义分组”，创建后点击分组管理成员；可按群聊、私聊、标签或全部联系人选择。
- **排序**：点击设置页右上角“排序”，拖动后完成。
- **重命名与隐藏**：左滑设置页中的预设分组，可重命名或切换显示状态。
- **删除自定义分组**：左滑对应分组后选择删除，只移除分组配置，不删除微信会话或聊天记录。分组栏右侧不设置添加按钮。
- **过滤重复联系人**：开启后，已加入自定义分组的普通群聊或私聊会话会从对应预设组中移除；“全部”、服务归属和显式加入的自定义组保持各自规则。

分组成员、排序、隐藏项和选中状态按微信账号保存；字号、配色等通用外观选项沿用全局配置。如果设置页出现“导入旧分组到当前账号”，确认当前登录账号后再手动导入，旧分组不会自动复制到所有账号。

### 分组栏与搜索

在 **聊天分组 → 其他设置** 中调整：

| 选项 | 效果 |
| --- | --- |
| 分组标签字号 | 默认 `18 pt`，可设置 `12–28` 的整数，支持恢复默认并跟随系统动态文字缩放 |
| 显示分组栏搜索按钮：开启 | 默认开启；显示分组栏右侧搜索按钮，同时收起整块原生搜索头部区域及其占位高度 |
| 显示分组栏搜索按钮：关闭 | 隐藏分组栏搜索按钮，恢复原生搜索区域，分组栏显示在其下方 |
| 隐藏分组角标 / 隐藏全部角标 | 分别控制分组及“全部”的未读提示显示 |
| 指示器颜色 / 选中文本颜色 / 切换触感 | 调整选中效果和切换反馈 |

分组栏属于聊天列表头部，会随列表滚动。搜索按钮开启时，如果原生头部同时包含横幅等内容，也会一起收起；进入原生搜索或关闭分组后恢复原生头部。

**当前版本切换分组时只更新分组选择和会话列表，不会把页面顶部“微信”标题同步替换成分组名称。**

### 手势与原生会话菜单

打开“分组切换手势”后，以手指的**起始位置**决定本次操作：

| 起手位置 | 横向滑动行为 |
| --- | --- |
| 会话列表可视区域左侧 `80%` | 左滑切换到下一组，右滑切换到上一组；可直接在会话行上操作 |
| 会话列表可视区域右侧 `20%` | 保留微信原生会话左滑菜单 |
| 分组栏标签区域 | 支持横滑切组；标签超出可视宽度时优先滚动标签 |

手指中途跨越区域不会改变本次手势用途，`80%` 分界线归右侧菜单区域。切组到首尾不循环；搜索、编辑或会话菜单已展开时暂停切组。关闭分组切换手势后，会话滑动范围恢复原生行为。

聊天列表切组手势与“消息手势”是两个独立功能：后者作用于进入聊天后的消息气泡。

## 列表圆角

进入 **插件设置 → 列表圆角**，可设置圆角半径、左右边距、置顶/普通会话顶部距离，以及浅色和深色背景。

圆角与分组同时开启时，首行、末行和单行圆角依据**当前分组实际显示的会话**计算。卡片背景会复用遮罩与路径：尺寸、圆角和首末行角色不变时减少重复创建；微信重置背景或遮罩后仍会检查并恢复样式。

该优化减少重复绘制准备和属性写入。当前没有实机帧率、耗电或内存降幅的量化结果。

## 源码编译

### 准备环境

- macOS、Xcode 及可用的 iPhoneOS SDK。
- [Theos](https://theos.dev/docs/installation)，以及对应方案所需的工具链、签名和打包工具。
- 完整保留仓库中的 `Headers/` 和 `HeadersFile/`，编译会引用其中的微信接口声明。

```bash
git clone https://github.com/ZhangSCzybh/WeChatImprove.git
cd WeChatImprove

xcrun --sdk iphoneos --show-sdk-path
```

Makefile 当前包含开发机的固定 Theos 路径。下面通过命令行 `THEOS` 覆盖该值；示例假设 Theos 安装在 `$HOME/theos`，如安装位置不同，请替换为实际路径。

### Rootless（无根）

```bash
make package -j4 THEOS="$HOME/theos" SCHEME=rootless PACKAGE_VERSION=1.6-24
```

默认产物：`packages/com.wechat.improve_1.6-24_iphoneos-arm64.deb`。

### Rootful（有根）

以下为构建方法；本轮 `1.6-24` 交付仅包含 Rootless 包。

```bash
make package -j4 THEOS="$HOME/theos" SCHEME=rootful PACKAGE_VERSION=1.6-24
```

默认产物：`packages/com.wechat.improve_1.6-24_iphoneos-arm.deb`。

两种方案均配置编译 `arm64` 和 `arm64e`。包名里的 `iphoneos-arm64` / `iphoneos-arm` 是打包方案的架构标识，应按注入环境选择安装包，不能仅凭手机处理器名称选择。

| 方案 | 动态库安装目录 |
| --- | --- |
| Rootless | `/var/jb/Library/MobileSubstrate/DynamicLibraries/` |
| Rootful | `/Library/MobileSubstrate/DynamicLibraries/` |

Roothide 需要匹配的 Theos 方案支持，可通过 `SCHEME=roothide` 选择，但本 README 不将其列为已验证产物。

### 版本与产物核对

- `control` 的 `Version`：默认安装包版本。
- `Headers/CSUserInfoHelper.h` 的 `kPluginVersionString`：插件内显示版本。
- `PACKAGE_VERSION=...`：只覆盖当次打包版本，不会同步修改插件内显示版本。发布新版本时应保持两处源码版本一致。

安装了 `dpkg-deb` 的开发环境可检查包内信息：

```bash
dpkg-deb -f packages/com.wechat.improve_1.6-24_iphoneos-arm64.deb Version Architecture
```

项目的 `make clean` 会删除整个 `.theos/` 和 `packages/`。普通打包直接运行 `make package`；如确需清理，先将要保留的安装包移到其他目录。

## 开发说明

### 代码结构

```text
WeChatImprove/
├── Controllers/       # 设置界面、分组模型/适配器、圆角渲染和其他业务组件
├── Hooks/             # Logos Hook：接入微信原生类和生命周期
├── Headers/           # 项目公共声明、插件版本及辅助接口
├── HeadersFile/       # 微信私有接口头文件
├── docs/              # 分组重构及圆角实现说明
├── WeChatImprove.plist # 注入过滤配置
├── Makefile           # 架构、SDK、源文件和打包方案
└── control            # 包标识、版本和依赖
```

Makefile 自动收集 `Hooks/*.xm` 和 `Controllers/*.m`。新增实现文件放入这些目录后会参与编译。

### 分组与圆角的职责分工

| 文件或组件 | 职责 |
| --- | --- |
| `Hooks/SessionGroupHooks.xm` | 接入列表生命周期、搜索、原生索引边界和会话操作 |
| `CSGroupNativeBridge` | 读取微信会话快照、识别账号和服务类型、按身份重新定位会话 |
| `CSGroupProjection` | 根据分组生成显示列表、双向索引映射及角标 |
| `CSGroupPreferences` | 按账号保存分组配置与导入旧配置 |
| `CSGroupListAdapter` | 连接原生列表、分组栏、刷新、手势和原生菜单 |
| `CSGroupIndexScope` / `CSGroupInvocationMapper` | 区分显示坐标与原生坐标，处理已知回调的索引转换 |
| `WESessionTabContainerView` | 分组标签、选中指示器、角标和搜索按钮 |
| `Hooks/ListCornerRadiusHooks.xm` | 接入页面布局，确定卡片背景与当前分组的首末行角色 |
| `CSListCornerRenderer` | 复用卡片遮罩与路径，按实际属性变化更新样式 |

分组通过原生会话快照生成显示结果，不替换微信的底层会话数组。延迟操作按会话身份重新定位，避免切组、重排或切换账号后误操作其他会话。

消息合并重构见 [消息合并说明](docs/message-merge.md)；本轮气泡、防撤回定位与实机验收边界见 [1.6-3 重构交付说明](docs/bubble-revoke-1.6-3.md) 和 [1.6-4 原生定位提示](docs/native-highlight-1.6-4.md) 及 [1.6-5 引用与分段气泡修复](docs/bubble-segments-1.6-5.md)。

实现细节见 [会话分组说明](docs/session-groups.md)、[列表圆角优化](docs/list-corners.md)；设计背景见 [分组重构方案](docs/session-groups-refactor-proposal.md)。

### 配置与备份

分组配置按账号管理；多数外观和功能开关使用微信进程内的 `NSUserDefaults`。插件提供的配置备份会读取 `Library/Preferences` 下的 `.plist` 和相关 `WeChatImprove` 配置目录，因此备份可能包含微信偏好项；它不等同于微信聊天记录备份。

自动备份在插件检查到距上次备份已超过 24 小时时触发，依赖微信运行。恢复配置时遵循设置页提示，避免把其他账号的分组成员当作当前账号配置使用。

## 常见问题

| 现象 | 检查方法或当前行为 |
| --- | --- |
| 找不到插件入口 | 默认到微信“我 → 设置”查找“再也不会”；已改名时按新名称查找。仍无入口时核对安装方案与注入是否生效 |
| 开启分组后没有标签 | 核对“启用聊天分组”、账号登录状态及微信实际版本；退出搜索/编辑后返回聊天列表，必要时重新打开微信 |
| 原生搜索框消失 | “显示分组栏搜索按钮”默认开启，此时通过分组栏右侧按钮搜索；关闭该选项可恢复原生搜索区域 |
| 列表横滑切组，无法打开会话菜单 | 从列表最右侧 `20%` 区域起手左滑；关闭“分组切换手势”可恢复原生范围 |
| 切到群聊后顶部仍显示“微信” | 属于当前版本行为；分组名称显示在分组栏，顶部标题不随分组同步 |
| 切换账号后看不到原来的自定义组 | 分组配置按账号隔离；旧版无账号归属的配置需通过设置页手动导入 |
| 安装包版本与插件显示版本不同 | 检查 `control`、`kPluginVersionString` 和打包时的 `PACKAGE_VERSION` 是否一致 |
| 编译找不到 Theos 或微信头文件 | 显式传入正确的 `THEOS` 路径，确认 `Headers/`、`HeadersFile/` 完整，并检查 `xcrun` 使用的 SDK |

反馈问题时，请提供插件版本、微信实际版本、iOS 版本、Rootless/Rootful 等环境信息，以及开启的相关功能和复现步骤。界面问题可附上已遮挡个人信息的截图，崩溃问题可附对应日志。

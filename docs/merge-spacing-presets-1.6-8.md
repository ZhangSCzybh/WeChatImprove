# 1.6-8：连续消息间距档位与首次测量

目标环境：微信 8.0.78 / Rootless。本次构建的是待真机验收的测试包。

## 用户设置

“连续消息间距”改为正常、紧密、宽松三个选项，当前项带勾选。正常保留原生行高；紧密在内容和身份空间预算允许时减少外部留白；宽松增加连续消息的外部留白。合并范围、头像首条/末条的选项保留。

读取旧设置时，负数映射紧密、零映射正常、正数映射宽松。没有旧设置时默认为正常。旧数值不删除；新选择只写 spacing_mode，便于保留历史配置与回退。新模式优先于旧值，非法新值按正常处理。这是运行时读取迁移，本次未访问设备偏好或聊天数据库。

## 行高职责调整

1.6-7 的留白记录来自已显示 Cell，首次未知布局不能压缩。本次移除此依赖：从微信原生测量后的 contentViewSize 读取内容尺寸，结合群聊身份显示和时间配置，在第一次 tableView:heightForRowAtIndexPath: 返回之前决定实际行高。

不再 Hook CommonMessageViewModel 的 measure: 返回值。微信内容模型及其尺寸缓存继续保存原生数据，插件仅在列表最终行高出口投影一次间距。缓存命中和重新测量使用相同入口，避免原生缓存绕过插件，以及把压缩后的内容尺寸再次压缩。

Cell 仍使用微信的内容排版和气泡绘制，不缩放文字、气泡，也不移动原生点击区域。渲染阶段不再学习新的压缩量，只核对已计划的行高是否容纳实际子视图；布局契约不匹配时允许恢复空间，并记录不含消息内容/身份的诊断阶段 native-layout-contract-fallback。

普通滚动没有延迟收紧任务，没有额外定时器、CADisplayLink、全表扫描或离屏 Cell 预热。分组只读取当前消息与直接邻居，尺寸记录随消息模型释放；宽度、内容尺寸、原生布局失效或配置变化会使相应决定失效。

## 空间预算和适配边界

紧密档位的本轮预算：最多减少 6pt，内容占用之外保留 12pt；有头像的行至少预算 44pt，显示群昵称的行额外预算 24pt。这些是本轮保守策略参数，**不是从微信 8.0.78 二进制验证得到的统一布局常量**。真实内容边界仍通过显示布局检查保护，不能仅凭头文件和主机测试宣称所有消息都已适配。

- 精确类名单内的普通单 Cell 消息可使用首次测量，包括未拆分的多行文本。实际能收紧多少取决于原生已有留白和身份空间。
- 缺失、不兼容、非有限或不合理的内容尺寸不进行负向压缩。
- 引用/App 消息、展开翻译、接龙、折叠文本、来源视图等辅助内容不按普通气泡尺寸压缩。符合既有合并名单的单 Cell 消息仍可使用宽松模式增加空间。
- 分段长文本仍整体避开合并模块的模型重置与行高修改，保留此前防止空白消息的修复。其三个档位目前均保持原生布局。
- 显示头像下方时间的身份行、较大时间字体采用原生高度保护；隐藏头像的连续行按其实际配置决定。
- 实际视图超出预算时可能触发一次恢复高度。这是异常保护，不能保证所有第三方插件组合都绝对没有事后高度调整。

因此，本版实现了普通布局的首次档位生效和原生缓存隔离；尚未完成上一轮设想中“所有引用、翻译、分段长文本都使用统一紧密布局”的完整适配。需要真实设备验证布局契约后再扩大支持，不能把这些回退默认为已完成。

## 本地验证

- bash Tests/verify-message-merge.sh：53,202 项策略/数学断言、904 项实际合并适配/导航/时间生命周期断言通过。
- bash Tests/verify-bubble-style.sh：9,611 项气泡策略/像素/所有权断言和 38 项实际气泡适配生命周期断言通过。
- 覆盖三个档位的首次测量、缓存重复读取不累计压缩、群聊/私聊、首/末头像、普通多行高度、旧配置映射、无效内容尺寸、头像下时间、辅助内容回退、拖动/减速/停滑稳定性和安全恢复收敛。
- 原有分段内容保护、原生撤回高亮时序和消息时间检查通过。
- Rootless arm64/arm64e 构建，核对包内版本、路径和架构；详细摘要及 SHA256 见 merge-spacing-presets-1.6-8-validation.txt。

主机使用 UIKit/显示帧替身，不验证微信实际视图结构、原生动画或设备能耗。没有安装设备、修改数据库、切换微信环境、提交或推送代码。

## 真机验收重点

同一群聊和私聊分别选择三个档位，先对比普通连续文字的首次进入和首次加载历史，再反复上下滚动并自然停滑。紧密应在首次显示时出现差异，不应依赖第二次浏览。检查首条/末条头像、未拆分多行文本、头像下时间、消息发送状态和原生撤回高亮。

引用、翻译和分段长文本当前重点验证内容完整与气泡正常，不以其紧密效果作为已交付能力。若普通消息依然不收紧或停滑后扩张，查看聊天诊断是否出现 native-layout-contract-fallback，以区分预算回退与设置未应用。

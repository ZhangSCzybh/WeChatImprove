【问题事实（主机探针已量化，可直接引用）】
位置：Controllers/CSCloseFriendSessionPresentation.m 的 CSFoldedRenderNativeSummary（约 :130）与 CSFoldedNativeRenderState（约 :97）。
- 复用条件要求 cover.nativeRenderState 非 nil 且与当前状态相等；而 CSFoldedNativeRenderState 在 MMContext currentContext / MMThemeManager getService: / 任一主题取值（cell_headimg_left_margin、cell_headimg_size）读不到时直接 return nil。
- 于是 :153 的 removeQuoteMessageLabel 与 :155 的 quoteMessageLable:prefixText: 每次布局都执行一次，无条件重建。
- 探针（当前完整 production 正文 + 当前 item layout hook，预热后每组 600 次 layout）：
  - scoped 折叠入口 + 主题不可读：原生 layout 600、quote 600、remove 600、theme service 读取 600
  - scoped 折叠入口 + 主题可读且内容稳定：600 / 0 / 0 / 600
  - 普通非 scoped 行：600 / 0 / 0 / 0
- 该现象不是「分组 + 隐藏密友」两开关 AND 专有：privacyMasked=NO、关闭保护且名单空时同样 600/600。

【本轮要达成的目标】
主题 token 拿不到时，只要**真实可验证的输入**没有变，就不要 remove+quote 重建。
判定「真实输入」至少包括：item/message/prefix 的视图身份与 superview 关系、message 与 prefix 的实际文本、四个几何 frame、字体、文字颜色、背景色、高亮色、对齐、行数、换行模式、缩放属性、三个 traitCollection。
主题 token 缺失只能表示「主题值无法比对」，**不能等同于「内容变了」**，不能继续拿 nil 当每次必须重建的理由。

- 不许引入固定延时、定时轮询、N 帧后重试、降频节流。

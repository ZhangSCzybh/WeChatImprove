2.0-13 真机新反馈，请修复（附录屏，务必自己看）：

【现象】插件以「弹窗样式」显示时，进入 定时任务 → 编辑任务 → 发送到 → 点「选择」→ 弹出「文件传输助手 / 私聊 / 群聊」action sheet → 点「私聊」或「群聊」，原生联系人/群聊选择器没有弹出，反而整个插件页面被关掉，直接回到微信会话列表。

【素材】
- 原始录屏：docs/feedbacks/2026-10-26-scheduled-picker-dismiss.mp4（592x1280，30fps，8.07s）
- 时间轴拼图（每秒2帧，5x4）：docs/feedbacks/scheduled-picker-sheet.png
录像末段可见：点「私聊」后 action sheet 收起，随即插件页面消失，回到微信主会话列表，原生选择器始终未出现。

【我已定位的可疑代码，请核实】
Controllers/CSScheduledTaskSettingsViewController.m 的 -chooseTarget（约 195-205 行）：

    for (NSUInteger i=0;i<2;i++) [sheet addAction:[UIAlertAction actionWithTitle:i?@"群聊":@"私聊" style:UIAlertActionStyleDefault handler:^(__unused UIAlertAction *action){
        // The shared picker refuses a second presentation. Wait for the sheet's
        // actual dismissal completion instead of racing it with a timer.
        [weakSelf dismissViewControllerAnimated:YES completion:^{ [weakSelf presentTargetPicker:i==1]; }];
    }]];

我的判断：weakSelf 是 CSScheduledTaskEditor，它是被 push 进导航栈的，本身不是 presented。对一个非 presented 的 VC 调 dismissViewControllerAnimated:，UIKit 会沿 presentingViewController 链向上找到真正被 present 的模态容器——也就是「弹窗样式」下承载整个插件的模态容器——把它 dismiss 掉。所以插件页面整个退出，completion 里也没有机会再 present picker。这正好解释「只有弹窗样式才复现」：全屏/push 路径下没有可 dismiss 的模态容器，dismiss 近似 no-op。

同时注意 CSNativeContactPicker 内部是 UIModalPresentationFullScreen present 一个 nav（Controllers/CSNativeContactPicker.m:207-209），并有「shared picker 拒绝二次 present」的约束（CSNativeContactPickerRevalidate / PickerState），所以修复不能只是简单加 delay 或强行二次 present。

【方向建议，仅供参考，不要盲改】
1. 不要在 self 上调 dismiss。要等 action sheet 自身 dismiss 完成，再在确定的宿主上 present：例如 handler 里持有 sheet 引用，用 sheet 的 dismissal 完成时机（presentingViewController 或 transition coordinator）回调后再 present；或干脆把「文件传输助手/私聊/群聊」改成 push 一个独立的选择源页面，从根源上避免「sheet 之后再 present」的嵌套；
2. 明确记录并断言：presenter 必须是当前仍在窗口层级里的 VC，且 present 前检查 presentedViewController 为空，避免和 sheet 的 dismissal 竞态；
3. 检查同一模式是否也存在于其他「sheet 里再 present picker」的地方（例如 chooseRule / chooseWeekdays 之后、或密友/备份里的选择入口），一并按同一原则收敛。

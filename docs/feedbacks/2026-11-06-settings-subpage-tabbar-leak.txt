需求：插件设置子页出现悬浮底栏（原生 MMTabBar 泄露）
版本基线：当前工作树 2.2-18（录屏中「插件」页显示 2.2-18）
优先级：1（视觉遮挡 + 可能吞点击）

============================================================
一、现象与复现路径
============================================================

现象：从微信「插件」入口进入插件设置根列表后，再点进任意「界面定制」子页，
微信原生底栏（4 个 tab）会出现在子页底部，压在子页内容之上。
底栏带插件「底栏样式」的效果（悬浮胶囊、圆角、绿色描边、缩放），
微信图标上带真实未读角标「3」，「我」为绿色选中态。

录屏复现路径（视频见附件）：
  微信 → 我 → 设置 → 插件 → 「再也不会」→ 插件设置根列表
    → 点「头像设置」     → 底栏出现（第一次）
    → 返回根列表          → 底栏消失
    → 点「顶栏信息」      → 底栏再次出现

不出现的页面（对照）：
  - 微信「插件」页（第三方插件列表，f001–f037）
  - 插件设置根列表（f100–f119、f148 之后）
两处都稳定没有底栏。也就是说：根列表没有、push 出来的子页有。

实测（真实解码帧号，从 1 开始；fps_mode passthrough，不补帧）：
  底栏可见窗口：
    第一次 push  f073 – f095
    第二次 push  f120 – f143
  出现过程：f073 只在屏幕右缘露出（x 546–591），随后逐帧左移，
            f079 起稳定，f085 完全稳定。约 12 帧 ≈ 0.40s，
            与 push 转场同步，不是淡入。
  稳定态几何（592×1280 坐标）：
    外接矩形 x 88–507、y 1174–1251，约 419×78 px
    折算到 393pt 宽屏约为 279pt 宽 × 52pt 高，底部距屏幕下沿约 19pt
  消失过程：f095 → f096 单帧从有到无，没有渐变也没有滑出，
            而返回转场此时刚开始（前一页仍在屏幕右侧）。

测量方法（可复现）：ffmpeg 全帧导出 → rgb24 raw → 逐帧统计
y∈[1160,1270] 区间内满足 g>120 且 g-r>50 且 g-b>30 的像素数与 x 包围盒。
绿色描边是插件底栏样式的边框色，所以该区间只会命中底栏，不会误命中页面里的绿色开关
（绿色开关在 y≈993–1031，已单独核对）。

三、要求
============================================================

1. 先定位，再改。
   必须查清「为什么 push 出来的子页没有隐藏原生底栏，而根列表没有」，
   给出机制级结论（谁在什么时候设置了可见性、谁覆盖了它）。
   禁止凭现象猜一个地方加一行就交差。

2. 先在录屏对应的每个阶段打日志取证，再动手改：
   逐个阶段记录 MMTabBar 的 hidden / alpha / superview / frame / window，
   以及当前 VC 的 hidesBottomBarWhenPushed 取值、是否 modal、是不是子控制器。
   阶段至少覆盖：push 起始、push 中途、push 完成、pop 起始、pop 完成、
   根列表出现、退出插件回主界面。
   证据附在审计目录，不要只贴结论。

3. 修在正确层级。
   目标是「插件设置子页本来就不该显示原生底栏」，所以在决定可见性的地方修，
   不要在表现层补丁。
   明确禁止：
   - 直接给底栏 setAlpha:0 / setHidden:YES 了事（会影响主界面和其他 tab）
   - 在子页上盖一层不透明遮罩挡住底栏
   - 用截图/快照覆盖
   - dispatch_after、延迟 N 秒再隐藏
   - 改子页 contentInset、改滚动范围让内容「躲开」底栏
   - 关掉「底栏样式」功能或让它在设置页失效来「看不见」底栏
   - 改转场动画时长、速率或换成自定义转场来掩盖

4. 红点必须先红。
   测试要能抓住 push 中间态的底栏可见性 —— 这次底栏在 push 中途有约 12 帧滑入过程，
   只比较 push 完成后的终态同样能抓到，但只比较「进入前 / 返回后」会漏。
   要求：在未修改的 2.2-18 上跑出红，修复后跑绿，同一份断言与夹具，SHA256 一致。
   红档要保留生产代码全文、方法抽取、编译命令、运行前后源码哈希和全部样本。

5. 覆盖范围（不能只验录屏里那两个页面）。
   从插件设置根列表 push 出去的每一个子页都不能出现底栏，逐个列出并说明验证方式：
   账号信息、收藏验证、顶栏信息/顶栏头像设置、头像设置、触摸轨迹、界面简化、
   界面净化、气泡样式、列表圆角、底栏样式、布局设置、附件布局、
   密友设置（普通入口与头像五击快捷入口）、备份与恢复相关子页、AI 回复设置子页。
   如果某页本轮没法测，写清「未验证」，不要默认通过。

6. 反向不能坏（这部分权重和正向一样）。
   - 从子页返回根列表：根列表仍无底栏
   - 从根列表返回「插件」页：仍无底栏
   - 退出插件回到微信主界面：底栏必须正常出现，且底栏样式（圆角、描边宽度、
     缩放、自定义图标、隐藏文字、未读角标、「我」选中态）全部保持，不能变回默认样式
   - 主界面四个 tab 来回切换：底栏不闪、不残留、不重复
   - 从主界面再次进入插件再退出：底栏状态正确，不出现「一次进一次不出」的抖动
   - 底栏样式关闭的情况下重走一遍：同样不能出现底栏

7. 不许顺手重构、不许改与本问题无关的文件。
   改动范围在报告里逐文件列明，附前后 SHA256。

8. 版本与产物：
   版本号 2.2-19，产物目录 packages/2.2-19-settings-subpage-tabbar/
   交付 WeChatImprove.dylib、两个架构 deb、symbols.zip、SHA256SUMS
   deb 的 Version 必须是 2.2-19，dylib 必须是 arm64+arm64e fat

【现象】聊天分组切到「群聊」tab，列表里只有两条会话（苹果派3群、再也不会羊毛团），下面是新做的「折叠的聊天（1）」入口。问题有两个：

1. 「折叠的聊天（1）」这一行往下，整个屏幕下半部分是一整块浅灰色空白（约 RGB 242），一直铺到 tabbar 上方；而上面会话 cell 是白色（约 255）。列表背景色和 cell 白色不一致，形成明显断层，看起来像列表没铺满/加载失败。原生微信会话列表这个区域应该是白的。
2. 「折叠的聊天（1）」这一行只有标题和数量，没有摘要行，行高和视觉也跟原生会话 cell 不一样（原生聚合入口是有摘要的），看起来像一行裸文字贴在白色背景上。

【可能原因，仅供参考，不要盲改】
1. 折叠入口做成了 section footer / 单独添加的子视图（而不是真正的 cell），背景默认透明，露出的就是 table / collection 的背景色（systemGroupedBackground 一类），所以下部一片灰；
2. 入口行的行高按自适应文字算，没有遵循原生 cell 高度与分隔线规范，所以和上面的 cell 明显不同高度；
3. 因为我上一轮要求「摘要用中性标题、不得暴露其他分组的最后一条消息」，实现时把摘要整行去掉或高度压掉了，导致视觉上空；正确做法应是保留原生 cell 布局（同样的两行结构、同样的高度、同样的分隔线），摘要位置放中性文案（例如「N 个会话」或「折叠的聊天」），而不是把行压扁；
4. 只有当列表行数少于屏幕高度时才会看到灰色区域，所以之前用例没覆盖到「少量会话 + 折叠入口」这种短列表；
5. 另一个高度可能的解释：插件给过滤后的列表套了一层白色底容器（或给若干 cell 设了白色背景），但容器高度只按内容算、没有铺满可视区域，于是内容之下露出原生 table 的灰色背景。白色区域正好在折叠入口行底边整齐结束，这个形状很符合"按内容算高度的容器"，而不是原生 table 自身的背景不一致。请优先验证这条。

【修复要求】
- 折叠入口必须是原生观感的 cell：与普通会话 cell 一致的白色背景、一致的行高、一致的分隔线/内边距，左图占位（原生聚合入口的图标）也按原生保留或明确说明为什么没有；
- 摘要文字继续不得泄露其他分组的最后一条消息、时间、全局未读，但要用中性文案占住摘要行（不要留空、不要把行压扁）；
- 无论列表行数多寡，会话列表可视区域背景必须是原生白，不得出现大片灰色空白；短列表、空分组（入口隐藏）两种情况都要覆盖；
- 先补失败用例复现：①短列表 + 折叠入口时，列表容器背景色必须与 cell 一致（断言背景不是 grouped 灰）；②折叠入口行高/布局与普通会话 cell 一致，且摘要位非空；
- 改动收敛，只跑折叠/分组展示/列表外观相关回归，不要全量；
- 出 deb（rootful arm + rootless arm64），说明根因、修改点、回归数量与真机验收步骤（含短列表、空分组、深色模式）。

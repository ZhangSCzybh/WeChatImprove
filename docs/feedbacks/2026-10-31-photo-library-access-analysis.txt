【必须查清的问题（逐条给结论，给不出就写「静态推断」或「证据不足」）】
1. **插件是否注册了相册观察者或持有相册资源**：搜 PHPhotoLibrary、PHPhotoLibraryChangeObserver、PHAsset、PHFetchResult、PHImageManager、PHCachingImageManager、ALAssetsLibrary、PhotosUI、PHPickerViewController、UIImagePickerController 的实例化与调用点。逐个判断触发条件是人手点击，还是自动。
2. **是否有周期性或事件驱动的东西会间接触发相册访问**：NSTimer、dispatch_source、CADisplayLink、NSNotificationCenter 观察、KVO、CFNotificationCenter、后台任务、`viewDidAppear`/`layoutSubviews`/`reloadData` 里调用的路径。要给出具体文件:行与调用链，不许凭印象。
3. **hook 层有没有碰微信原生相册类**：搜 Hooks/ 与 HeadersFile/ 里与相册相关的类（例如 `MMAlbumDataProviderForPHAssetFramework`、`MMPHAssetCacheObj`、`MMPHAssetChangeInfo`、`MMUIImagePickerController`、`PHPhotoLibraryChangeObserver`、`MMAssetForPHAssetFramework`、`MJPHAssetsAnalyzer` 等），确认插件有没有 swizzle 这些类的方法，或在这些类的回调里做重活。若插件 hook 了相册数据源的方法（例如取相册列表、取缩略图、取资源），要指出会不会导致重复 fetch、重复解码或阻塞主线程。
4. **AI 图片链路**：`CSAIImagePreparer`、`CSAIMessageAdapter`、`CSAINativeSyncObserver` 处理图片时，图片来源是聊天附件还是相册；有没有把图片写入或读回相册（`UIImageWriteToSavedPhotosAlbum`、`PHAssetChangeRequest`、`PHPhotoLibrary performChanges`）。这几个 API 也要一起搜。
5. **设置页的自定义图片（底栏图标、导航标题、触点轨迹、联系人分隔线）**：保存时是落到插件自己的沙盒/偏好里，还是写进相册；这些页面有没有在打开时预加载或刷新缩略图。
6. **是否有代码在“没有用户操作”的情况下读取相册权限状态**（例如每次进入设置页、每次回到前台都调 `authorizationStatus`），这类调用本身不读照片但会触发系统相册状态查询，用户可能感知为“又在访问相册”。

【证据标准】
- 每条结论必须给 文件:行 + 静态调用链 + 触发条件（人手 / 定时 / 通知 / 布局 / 后台）。
- 区分「插件自己的代码」与「微信原生代码被插件 hook 后放大」。

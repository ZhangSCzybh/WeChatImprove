【这就是本次要修的问题】

注意：这是 2.2-1/2.2-2 上仍然存在的老问题，不是 2.2-2 引入的。2.2-2 只改了扫描次数，没有关闭「列出可见到隐私化生效」的时间窗。

【必须查清的根因方向（逐条给结论，不要跳）】
1. 帧 152/168 显示的是**转场开始时列表已有的内容**（且帧 168 的第 4 行与稳定态不同，说明是旧内容），不是本次返回后新建的 cell。所以问题在「列表变为可见之前，屏幕上已有的那套内容没有被隐私化」，而不是「新建 cell 时漏了过滤」。请确认是不是这个性质。
2. `Controllers/CSGroupListAdapter.m:652` 的早退分支：
   `if (!self.isActive && !privacy) { ... layout(); ... prepareForPublication(); return; }`
   这条路径会**跳过**逐行隐私判定、shield 与 hold，直接按原样布局。请确认小程序打开期间/返回瞬间 `isActive` 是否会为 NO，如果会，那么这期间任何一次布局都会把未过滤内容摆上去，返回时用户直接看到。这是当前最可疑的一条。
3. `Controllers/CSGroupListAdapter.m:1154`：`!self.isActive` 时走 `CSGroupWithNativeIndices`，同样会在原生索引域里出内容。确认返回瞬间是否命中。
4. `performSessionListLayout:` 只在**表格内容布局入口**被调用。若返回转场期间表格没有发生内容布局（只是重新可见 / 只是父容器动画），则整条隐私闸门一次都不会执行。请确认帧 133–168 之间表格是否真的走过这个入口；拿不到真机就明确写「静态推断」。
5. 数据刷新是**晚到**的：帧 168 仍是旧内容，帧 175 才换新。说明真正让隐私行消失的是「返回后的一次 refresh」，它发生在转场已经结束后。这解释了为什么闪一下才隐藏——闸门装在了错误的一端（事后），而不是事前。

【修复要求】
目标一句话：**列表在屏幕上一旦可见，第一帧就必须已经是隐私化后的内容**；不能靠「可见之后再隐藏」。

- 时机必须提前到「覆盖层开始消失时」，而不是「列表已经可见且发生布局时」。可用于提前的入口请自己找并说明理由（例如覆盖层 view 的 willMoveToWindow/dismiss、列表 VC 的 viewWillAppear、窗口 key 状态变化、小程序关闭回调等），但必须给出实际存在的类与方法，不许编造。
- 覆盖层可见期间如果 `isActive == NO`，也**不允许**把未隐私化的内容摆上去。上面第 2、3 条的早退分支需要收紧：只要「当前策略判定为需要隐藏」（privacy 为真）就必须走 shield/hold，与 isActive 无关。若你认为改这条会波及别处，先报告影响面再改。
- 不许引入任何固定延时（`dispatch_after` 等待、N 帧后修）；不许用 `performSelector:afterDelay:` 糊。
- 不许为了掩盖问题做整表 `reloadData` 硬刷；不许降低刷新频率。
- 允许新增「可见前置闸门」：在列表即将可见前主动校验一次并 shield/hold/中性化，之后仍走原有 refresh 恢复。这条是本次的主要改动方向。
- 隐私必须 fail-closed：任何键读不到、状态不确定，宁可空态/中性态，不许放行。
- 2.2-2 的隐私准入缓存的语义与计数特性不能被破坏：25 次稳定布局、32 行投影时，逐行隐私判定仍应只有 1 次（32 次查询），原生布局仍 25 次，新增刷新请求仍 0。改完后请重跑 `Tests/verify-privacy-admission-cache.sh` 与 `Tests/verify-privacy-admission-cache-events.sh` 并用同样口径给出计数对照。

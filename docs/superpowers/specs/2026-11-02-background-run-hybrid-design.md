# 后台运行混合调度设计

用户已于 2026-11-02 确认推荐方案并授权修改和编译打包。基线为当前 main 的 2.2-3；原 checkout、defaults、账号存储、历史产物保持。原生微信注入插件没有前后端端口或独立服务数据库，本次不操作设备。

## 目标与组件

采用有限 UIKit 后台任务优先、音频按需接力的状态机。CSBackgroundRunManager 管理生命周期、资源交接、业务能力和文案；新增 CSBackgroundRunRuntime 封装独立后台任务记录及可取消单次检查；CSBackgroundRunAudio 保留 8 秒/16kHz 全零 WAV、音频租约与通话避让。

## 策略

- 进入后台先申请有限任务；申请失败后允许一次音频兜底。
- 最多一个检查与播放器；任务交接时先申请新任务，再结束旧任务。26 秒轮换节点使用单调时钟，失败后本轮不周期重试。
- 有限剩余预算 <10 秒时接力；不足5秒且无法接力时收尾。系统到期必须及时结束自己的任务，不在到期回调中继续申请。
- 预算充足时按 min(预算到10秒边界，轮换节点) 调度；临界/音频退出观察窗口约1秒检查；不得补执行迟到心跳。
- 音频播放至少10秒，有限预算>=15秒连续3次、每次相隔至少1秒，才退出音频。极大值、NaN、负值清空恢复计数，不将自身音频带来的极大预算当作独立任务恢复。
- 旧任务到期或旧检查只能处理所属代次，不能修改新一轮资源。前台/关闭统一取消检查、停止播放器、结束任务。
- 系统中断/音频服务不可用/宿主接管时保留现有让出规则；失败不靠定时器反复重建。明确恢复事件可重新尝试，普通 defaults/路由通知不能刷新重试预算。
- 发布 canAttemptBackgroundWork（有效任务或实际持有的音频），与 backgroundAudioActive 分开。AI 使用前者并保留账号、授权和45秒节流。能力变化独立于文案触发通知。

# 密友设置：已确认设计

状态：用户于 2026-10-20 批准实现，并补充共同群聊资料页伪装。源基线 929d265b，插件 1.8-41；在当前检出目录的 codex/close-friends 分支开发。没有 Web 服务或测试数据库需要替换，不改微信真实数据库、不安装到设备。

## 用户契约

1. 密友、密群按当前微信账号和真实 userName 识别；昵称、备注不是主键。
2. 隐藏首页/置顶/分组/折叠群会话、转发各选人入口、通讯录、标签成员、谁可以看选择器、结构化搜索结果。
3. 隐藏密友朋友圈动态、点赞、评论、回复密友的互动、互动消息、对应头像/计数/红点。
4. 隐藏所有朋友圈部分可见/分组可见图标，而不是只隐藏与密友有关的图标；真实发布权限保持不变。
5. 状态广场、卡片翻页、资料直达状态均保护。
6. 消息正常接收、同步、保存，真实未读不清除。隐藏与临时解锁期间都静默。
7. 自动免打扰调用原生设置，记录先前状态与变更所有权；临时解锁不恢复；移出或停用时仅恢复仍由插件拥有的变更，外部修改优先。
8. 单聊和群通话分开适配。拒绝新的语音/视频邀请、抑制应用内浮窗与铃声、执行原生结束流程。不得丢弃 PushKit 必需 completion 或假造系统报告成功。
9. 临时解锁恢复微信原有列表，通知仍静默；拒接独立控制。重启、切账号、后台和显式隐藏失效临时授权。
10. 从共同群聊头像及其他入口打开隐藏密友个人资料，发消息/音视频入口替换为“添加到通讯录”。此为本机展示伪装，真实好友关系不变；点击伪装按钮不发送好友申请、不删除好友、不声称添加成功，可显示中性的“暂时无法完成操作”。解锁后恢复原生资料操作。隐藏状态下相关聊天/通话路由不得绕过保护。
11. 标签/发布范围展示副本不得覆盖原始成员或 ACL；无法安全保留隐藏成员的编辑在隐藏状态下要求先验证。转发选择中重新隐藏不能留下不可见收件人继续发送。
12. 普通群不因包含密友整体消失；聊天正文不篡改。结构化发送者匹配可用于通知和搜索过滤。

## 工程约束

- Objective-C/Logos、ARC、arm64/arm64e、iOS 15.0，遵循现有原生设置界面。
- 不全局隐藏 CContactMgr 对象、不删除消息、联系人、索引或互动记录，不通过标已读消除角标。
- 会话由现有 CSGroupListAdapter/CSGroupProjection 单一拥有者映射；密友过滤独立于分组开关。缓存包含隐私修订版本，全部角标不能直接使用泄露密友贡献的原生总数。
- 所有显示 count/cell/selection/preload/navigation 使用同一快照。异步结果带账号代次与策略代次，拒绝迟到旧结果。
- 普通备份未加密；密友名单、凭据和恢复日志不登记到普通 .wcbak。密友文件认证加密，Keychain 设备专用密钥；配置损坏/未来格式不得重置为空并解除保护。
- 密码至少 6 位数字或 8 位字符，随机盐 PBKDF2-HMAC-SHA256，限制尝试；不在搜索框输入密码，不持久化 unlocked。
- 密友认证独立于现有插件公众号授权。生物验证回调核对账号、代次和前台状态。
- 备份启动 gate 尚未就绪时不能先泄露敏感页；最小保护不在 ctor 执行服务发现/迁移。后台立即遮盖，配置/索引稳定后解除遮盖。
- 头文件只提供候选；安装 hook 前检查实际类/方法签名，不根据可被伪造的 CUtility.GetVersion 断言支持。能力列表区分接口发现、主机测试、设备验证。
- 当前只注入微信主进程。不能宣称被杀/挂起状态的 APNs、系统 badge、CallKit 全部无首帧；不拓展到系统进程注入。
- 红包/收款保持业务处理，含密友身份的自发摘要受隐私策略约束。
- 不执行 make clean；保留现有 packages 和 .theos。测试仅临时目录/内存配置，不写真实微信数据。最终打包新版本，附主机证据与真机验收表。

## 默认行为和状态

初始总开关关闭，未配置密码不能启用。默认保护各要求的展示入口、静默、自动免打扰及拒绝语音/视频；公开角标不含密友。隐藏入口、整插件入口、摇一摇默认关闭，避免首次配置失去入口。临时解锁 300 秒，可从设置调整。全局分组图标选项在功能开启时独立于临时解锁生效。

推荐页面入口为“账号与安全 → 密友设置”；长按首页导航栏触发独立验证并进入设置/解锁，保留原有触摸事件。用户主动隐藏时退出敏感页面，安全保留草稿。

## 模块边界

Foundation policy/crypto/store 为可执行主机测试核心；runtime manager/bridge 管账号、授权、数据发布和安全私有调用；设置/生命周期为 UI 层；会话、联系人/转发/搜索/资料、朋友圈/状态、通知/免打扰/通话分别适配。Native APIs 通过各自适配器调用，不在 policy 访问 UIKit、磁盘或服务。

## 验收

两个好友（密友/普通）与两个群（密群/普通）；同时收消息和来电；所有显示入口、切账号、后台/锁屏/终止进程、异步回流、转发锁定、标签/ACL 编辑、用户手改免打扰、配置损坏、不同分组状态、群内头像资料伪装及解锁恢复。验证消息完整、普通对象功能正常、拒接后普通通话可接。主机策略与真实模型代理测试不替代设备验收。

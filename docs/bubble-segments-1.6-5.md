# 1.6-5：引用正文、分段气泡与合并缓存边界

目标环境沿用微信 8.0.78 / Rootless；本次基于用户三张截图排查。图 1 显示引用正文仍是原生绿色；图 2 的多行气泡在左右两侧分段连接处有台阶；图 3 对应长文本正文与背景均不可见但仍占据空间。截图证明现象，不能单独证明私有接口的内部执行顺序。

## 实施内容

1. **引用正文气泡**：TextMessageViewModel 不只有普通文本类型 1，引用消息也使用文本视图。现在明确支持类型 49 且原生 subtype 为 57，或原生 `isReferMsgType` 确认为引用的文本消息。应用用户配置到正文气泡，不把其他应用卡片一并放行。引用摘要区域仍由微信独立绘制。
2. **分段接缝**：旧模板以原生图像全部非透明像素的外框为边界，会把首段尖角也计入正文宽度，后续无尖角片段则缩进。新文本模板依据重复出现的直边识别主体范围；保留背景视图本身的 frame，不移动文字。无法可靠识别时使用原外框，未知图像保持原生。
3. **短末段拉伸**：旧首/中/末段统一保留上下两组圆角尺寸，短末段可能放不下固定拉伸区域。现在首段只保留顶部圆角区域，中段使用平直连接，末段只保留底部圆角；圆角同时受实际背景尺寸约束。位置或尺寸变化使模板绑定重新计算。
4. **合并导致空白的缓存风险**：旧代码对多行分段跳过压缩，却仍会在 prepare/flush 中重置子模型缓存。TextMessageSubViewModel 与父模型共享内容，重置可能破坏已测量的分段内容。现在提前识别多行 section、父子模型或原生长分段标记，完全跳过合并缓存重置、头像隐藏和高度调整。它们同时成为合并边界，防止相邻消息按未参与合并的段落继续折叠身份。

这里的“分段”是微信把一条消息拆成多个行模型的情况，不是凡文本中有换行就关闭合并。普通非分段消息继续使用原有合并规则。此版本优先保证原生分段正文显示，暂不压缩分段长文本或合并其头像。

保留原生防撤回定位提示；没有修改导航、消息时间、头像偏好或聊天数据库。仍使用原有受限模板缓存，没有新增周期任务、全表刷新或逐帧扫描。主体图像扫描发生在需要重建样式时，重复布局使用绑定缓存。

## 本地验证与边界

- `bash Tests/verify-message-merge.sh`：7,008 项策略/数学检查、315 项实际合并/导航/时间代码检查通过。
- 新增真实独立 NSObject 子模型形状的回归；其 resetLayoutCache 会清空模拟正文并传递到父模型。私聊/群聊、启用/停用/重进/flush 四轮均确认子模型和父模型没有被合并模块重置，内容和原生高度保留。
- `bash Tests/verify-bubble-style.sh`：9,611 项配置/Core Graphics 像素/拼接/所有权检查、38 项实际气泡适配器检查通过。
- 新增带尖角首段与无尖角末段的原生形状样本；左右方向、1x/2x/3x、短末段与大圆角，按九宫格拉伸取样逐像素比较连接边界。并验证引用类型、普通卡片拒绝、同一模型位置变化、独立父子模型、关闭恢复、背景 frame 保持。
- Rootless arm64/arm64e 编译、版本和包内路径检查通过。

以上是代码与主机替身验证，不是真实微信截图比较。未在设备安装、未测量帧耗时或耗电；真实资源的阴影/尖角形状、微信缓存时序仍需用户原环境验证。图 3 的缓存问题属于已消除的代码风险，不能据此断言它是设备现象的唯一原因。

## 原环境验收

安装 1.6-5 并确认版本，使用截图中的同一聊天记录：

1. 引用消息正文应采用已配置颜色和圆角；引用摘要保持可点击。
2. 左右两侧多行气泡不应在首末段连接处出现台阶；检查末段只有一行与较大圆角。
3. 反复开关合并，退出重进，滚动离屏再滚回：长文本正文/背景应完整，不能出现占位空白。
4. 继续确认非分段消息合并、消息时间、隐藏头像及防撤回原生定位提示。

旧包保留；没有替换账号、设置或聊天数据库。包校验值、构建记录与源码指纹见同目录 validation.txt。

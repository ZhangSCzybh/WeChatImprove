# 1.6-17：实机顶部 inset 重复与诊断清空

后续实机反馈：本版仍有空白，重复量 103 不等于当时系统贡献 97.67，修正分支未触发。后续分析和修改见 [1.6-18](session-groups-inset-1.6-18.md)。以下保留本版实现与验证历史。

## 实测原因及上一版边界

用户在微信 8.0.78.34、iOS 27.0.1 安装 1.6-16 后确认短列表页面往返仍出现顶部空白。提供的诊断中，私聊短列表如下：

| 状态 | contentInset.top | adjustedContentInset.top | contentOffset.y | 内容高度 | 视口高度 | 显示表头高度 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 切换私聊后 | 0 | 103 | -103 | 226.83 | 932 | 98.8 |
| 再次出现前后 | 103 | 206 | -206 | 226.83 | 932 | 98.8 |

系统贡献 `adjusted.top - contentInset.top` 在两个状态下均为 103；原始 inset 多计入了一份相同贡献。显示表头和原生表头高度不变，reload/restore 前后数值也不变。日志证明本次残留空白来自顶部 inset 的重复量，而非 1.6-16 的锚点恢复再次写入偏移。日志未捕获最初写入原始 inset 的私有调用栈，不将某个未观测的方法认定为该写入者。

1.6-16 减少重复 reload 和短列表锚点覆盖的改动保留；其主机回归通过不代表已修复实机问题。本版继续使用原 checkout、Rootless 交付方式和原账号数据，不迁移或读取微信数据库。

## 分组修复

每张主表首次挂载时记录当时原始 `contentInset.top`，作为该表的观测基线。布局及实际 reload 后检查：

1. 分组投影生效、功能开启，表格已进入 window；非搜索、触摸、拖动、减速、编辑、侧滑、原生事务或表头更新过程。
2. 内容在扣除重复贡献后不足一屏，当前 offset 位于 adjusted 顶部边界。
3. 当前原始 top 与基线之差，等于 UIKit 实际增加的 top（容差 0.5 pt），且该增量为正。
4. 微信原生顶部区域未展开或处于展开/收起/高度变化过程。通过 runtime 核验四个已知 ivar 的名称和布尔编码，不猜测内存位置；字段不可验证时不修正。
5. 原生 `setTableViewContentInsetOffsetWithoutScrollWithContentInset:contentOffset:` 存在，且返回值及两个结构体参数签名匹配。

满足全部条件后，通过原生成对设置接口将原始 top 恢复到观测基线，并把 offset 同步增加重复量。其他 inset 边、水平偏移均保留。没有固定 103 pt 或视频像素补偿，没有全局清零 inset，也不更改自动安全区调整行为。重入有保护，后续正常布局不会累计补偿；下一次页面往返若再次重复计入，可再次匹配修正。私有方法不可用或抛出异常时退出并记录诊断。

新增诊断字段：`baseline`、`known`、`topState`。`topState` 的 0–3 位依次为原生顶部已展开、正在展开、正在收起、高度变化，第 4 位表示字段未知。只有 0 会进入修正。修正调用前后记录 `inset-repair-before/after`；接口不匹配或异常分别记录 `inset-repair-unavailable/failed`。

## 诊断清空按钮

「版本控制 → 查看诊断记录」页右上角同时提供「复制」和「清空」。清空调用与写入/读取共用同步锁的 `CSChatClearDiagnostics`，删除当前内存记录；刷新页面的 report 和文本视图，并回到顶部。复制使用更新后的 report，不会再复制清空前的快照。

不关闭诊断开关，不清理聊天、账号或插件设置。清空后返回复现场景即可重新记录，再打开诊断页查看/复制。此页仍为打开时的记录快照，没有增加轮询。

## 验证

- `bash Tests/verify-group-viewport.sh`：76 项通过。复用 1.6-16 生产方法进行对照时，10 项失败，包含本次实测重复 inset 的修复断言。
- 分组测试执行生产挂载、锚点和修正方法以及实际原生标志读取函数；覆盖不同系统增量、非零原生基线、反复页面往返、不重复补偿、长列表/搜索/拖动/顶部展开保护、未知 ivar、接口缺失/ABI 不匹配/异常和重入。宿主表格及私有 setter 为替身，不能证明真实 UIKit 或私有方法行为。
- `bash Tests/verify-message-merge.sh`：53,201 项策略检查及 2,892 项适配/导航/诊断检查通过。新增清空后无旧内容、关闭诊断时也能清空、开关不变及重新记录验证。
- 完整 Rootless 构建检查生产 UIKit 和 Logos 钩子；安装包验证结果见 `session-groups-inset-1.6-17-validation.json`。

## 设备复核

安装 1.6-17 并完全退出/重新打开微信，使适配器在原生初始布局时采样基线。打开兼容性诊断并进入记录页点「清空」，复现「私聊两条会话 → 上滑到正常顶部 → 通讯录 → 微信」。检查空白、原生下拉顶部区域和搜索往返。

若仍有空白，新的干净记录可判断保护条件是否未满足、私有 setter 是否可调用，以及修正后的真实 inset/offset。安装包未经本地连接的真实微信设备验收，不能将替身或编译结果当作设备效果确认。

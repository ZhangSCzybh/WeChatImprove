# 消息时间位置修复（1.6-23）

用户在微信 8.0.78.34 / iOS 27.0.1 / Rootless 的反馈：头像下方模式正常，关闭该模式后时间叠进气泡正文。截图中多条接收消息的时间位于白色气泡内。

## 原因与修复

1.6-22 使用实际气泡作为定位锚点，但定位函数仍直接读取锚点的 `frame`。该矩形属于气泡父容器，而时间标签属于消息视图；气泡嵌套在内容容器中时，遗漏父容器偏移。头像通常直接属于消息视图，因此头像下方模式可能正常。

`CSMessageTimePositionLabel` 现在显式接收标签所属消息视图，使用 `convertRect:fromView:` 将锚点的 `bounds` 转到统一坐标系。接收消息仍放在气泡右侧，发送消息放在左侧，底部对齐；头像下方模式保留原偏移规则，头像隐藏时沿用气泡旁回退。

气泡样式适配器修改背景图片，不写入气泡几何。合并适配器在隐藏头像后已有时间重新定位调用，紧密间距移动整个消息视图，标签随该视图一起移动。因此这次修复坐标转换，不修改气泡渲染、合并行高策略或原生定位高亮。

日志 `time: shown` 只表示标签可见。用户日志中布局回退的内容容器底部达到 61pt，时间标签对应的未知子视图底部为 56pt；不能把该回退直接归因于时间标签，也不应为此取消合并的内容保护。

## 回归与构建

新增嵌套容器测试在修复前失败：接收消息的时间横坐标未包含父容器偏移。修复后时间生产代码生命周期测试 138 项通过，涵盖发送/接收、非零父容器 bounds 原点、头像位置、隐藏头像、整行偏移、后续容器布局变化和点击范围。

消息合并/导航策略 53,201 项、原生适配/导航生命周期 2,892 项、气泡策略/渲染/所有权 8,269 项、气泡适配生命周期 111 项断言通过。这些是主机替身测试，不等同于运行微信真实组合 Hook 或实机截图验收。

Rootless 包 `packages/com.wechat.improve_1.6-23_iphoneos-arm64.deb` 编译成功，包内版本、Rootless 路径、arm64/arm64e 架构已核对。构建有 212 条警告，修改的时间源文件无警告。详见 [校验记录](message-time-1.6-23-validation.txt)。

## 实机复核

安装后重新启动微信，关闭「显示在头像下方」，检查群聊和私聊的接收、发送、长文字、图片与语音消息；分别开启气泡样式与紧密合并，检查时间是否始终位于气泡外。再检查头像下方模式、点击显示以及滚动历史消息后的复用。

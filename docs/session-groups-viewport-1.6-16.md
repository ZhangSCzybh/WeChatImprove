# 1.6-16：分组短列表返回页面后的顶部位置恢复

后续实机反馈：用户确认该版本仍有顶部空白。诊断证实原始顶部 inset 重复计入系统贡献，见 [1.6-17 修复](session-groups-inset-1.6-17.md)。以下保留 1.6-16 当时的实现和验证边界。

## 问题与证据边界

用户提供的两段视频中，主列表只显示少量会话时，从聊天详情、我或通讯录返回，会在搜索框上方留下空白。第二段视频约 13 秒，上滑后私聊分组的两条会话正常显示；约 15 秒切到通讯录，再回微信后，同样两条会话和搜索框整体下移约 140 个视频像素，而标题和加号正常显示。该像素差不作为布局补偿常量。

已确认的源码行为：`viewWillAppear`、`viewDidAppear` 均调用 attach；旧 attach 即使已挂载仍无条件 refresh，refresh 会 reload 并恢复行锚点。内容不足一屏时，旧锚点限制的上、下界重合，强制写入 `-adjustedContentInset.top`。微信原生另有顶部区域、inset/offset 和页面返回位置管理。

这些行为与视频一致，但没有目标设备的运行日志证明某个私有方法的具体调用顺序。本修复消除插件已确认的重复重载和短列表偏移覆盖，并保留数值诊断供实机复核；不宣称已经在真实微信中复现并验证消除了空白。

## 改动

- 已绑定同一主表的 attach 只布局，不因普通页面出现而重载。首次绑定、待发布更新、账号变化、分组开关变化或搜索状态变化仍刷新。分组设置通过已有 Darwin 通知继续刷新。
- 已被同步刷新消费的异步请求，不再额外重载一次；真正的新 dirty 请求仍发布。
- 空列表、短列表和刚好一屏的列表不保存行锚点，清除该组旧锚点；恢复时也不强制设置偏移，由 UIKit 和微信原生布局负责。
- 长列表锚点记录会话相对可视顶部的位置，包含采样时的 adjusted top inset；恢复时减去当前 inset，避免顶部遮挡变化造成位置漂移。
- 触摸追踪、拖动、减速、搜索、顶部越界回弹、未布局或无效几何时不执行锚点恢复。目标位置没有实际变化时不重复写入 contentOffset。
- 原生搜索表头的包装方式、分组成员规则、列表圆角、会话数据和数据库不做修改。没有固定负偏移、强制清零 inset、延迟定时器或全局滚动拦截。

## 诊断

沿用插件「版本控制 → 兼容性诊断」，默认关闭。开启后记录 `groups` 事件：

- `will-appear-before-native` / `will-appear-after-native`。
- `did-appear-before-native` / `did-appear-after-native` / `did-appear-finished`。
- 有真实刷新时记录 `refresh-before` / `reload-after` / `restore-after`。

记录 offset、原始及 adjusted inset、内容与视口高度、主表 frame Y、显示 header 与原生 header 的 Y/高度以及生效/搜索/dirty 状态。没有聊天正文、联系人、账号标识或对象描述。可据此判断异常发生在原生出现方法、列表重载还是锚点恢复阶段。

## 验证

运行 `bash Tests/verify-group-viewport.sh`：39 项检查通过。

同一测试使用修改前的生产方法时，39 项中 21 项失败。覆盖普通页面反复出现、首次和替换主表、dirty 合并、开关/账号/搜索变化、空/短/刚好一屏列表、长列表重排和 inset 变化、滚动范围、无变化时不写偏移、触摸/拖动/减速/回弹保护、锚点删除及无效几何。

测试动态提取生产 `attachToController`、刷新排队和锚点方法，使用内存中的 Foundation/CoreGraphics 宿主替身执行。完整 refresh、布局、微信运行时及 UIKit 渲染并不在这些替身测试覆盖范围内；生产模块及 Logos 钩子通过完整 iOS 构建检查。历史文档中的 `Tests/verify-session-groups.sh` 不在当前 checkout，本轮没有将历史 378 项结果当作重新通过。

构建使用当前 checkout 和独立的 Theos 临时输出目录，Rootless 安装包版本为 1.6-16，包含 arm64 与 arm64e。旧安装包保留。没有安装到设备、重启微信或读取/修改微信数据库。

## 设备验收

1. 安装 1.6-16 Rootless 包，完全退出并重新打开微信。
2. 开启分组，选择只有两到四条会话的分组，上滑到正常顶部。
3. 连续进行「微信 → 通讯录 → 微信」「微信 → 我 → 微信」以及打开聊天后返回；确认顶部不再新增空白。
4. 切换空分组、短分组与长分组；检查长列表滚动后切组再回来仍保留会话位置。
5. 检查搜索进入/退出、原生搜索框显示开关、正常下拉顶部区域、侧滑菜单和新消息刷新。
6. 若仍出现空白，开启兼容性诊断后只复现一次页面往返，立即在版本控制页查看或复制记录。诊断会区分原生布局产生的偏移与插件刷新产生的偏移，避免继续猜测固定补偿值。

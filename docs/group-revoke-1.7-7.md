# 群聊防撤回修复（1.7-7）

用户反馈群聊撤回后原消息未保留。沿用已知目标微信 8.0.78.34 / iOS 27.0.1 / Rootless；本次未获得新版本号确认、失败通知原始数据或真机调用栈。源码基于当前主分支 `2ac42b7e`（1.7-6），保留该版本的原生设置宿主与赞赏功能改动。

## 已确认的代码缺陷与修复

1. 原解析器只接受完整 XML。带 `member:\n` 群成员封装前缀的撤回通知解析失败，处理函数返回 NO，Hook 随后执行原生撤回。本次主机回归直接执行生产处理函数，在旧代码上复现这一失败。现在仅剥离长度有界、由账号标识字符组成的单层前缀，再执行原严格 XML 解析；不从任意正文里搜索 XML 片段。
2. 会话归属判断原先将所有消息端点限制为“当前账号或会话”。群消息采用“成员→群”端点时被拒绝。现在群会话要求端点中包含准确的目标群，拒绝其他群混入，并继续核对原消息服务器 ID；私聊校验规则保持原样。共享规则同时用于原文定位校验。
3. 原逻辑在解析前使用撤回通知的 `isSender` 跳过事件，不能据此确认原消息作者。现在使用已解析的本人撤回文案，并在找到原消息后核对其发送者和群聊实际发送者；群聊实际发送者是当前账号时保留原生撤回行为。

删除被替代的字符串截取/CDATA 解析和旧本人判定函数。保持重复通知去重，提示插入失败不放行已验证原消息的撤回。没有新增定时器、历史扫描、消息备份数据库或后台轮询。

这些测试证明代码缺陷和修复结果，但尚不能证明用户本次真机失败一定走了这些分支，也不确认全部微信原生撤回入口都已覆盖。

## 验证

- `bash Tests/verify-revoke-interception.sh`：53 项生产撤回处理与四个 Hook 分支断言通过。测试提取生产函数与 Hook 方法体，用服务替身替代微信消息管理器，将 `%orig` 映射为原生放行信号；不验证 Logos 安装或真实数据库。
- `bash Tests/verify-revoke-reference.sh`：74 项撤回事件、持久化链接和会话校验断言通过。
- `bash Tests/verify-message-merge.sh`：53,201 项策略断言及 2,881 项原生适配/导航生命周期断言通过。
- 覆盖群成员前缀、群/私聊、通知方向误判、本人群聊消息、不同群/错误消息 ID、缺失原消息、缺失账号、无 XML 会话时的群会话提示、提示插入异常、重复通知及关闭开关。

本次构建将 Theos 中间文件放入单独临时目录，复用用户现有源码和构建配置，输出到原 `packages` 目录；不覆盖工作区原有 `.theos` 中间文件。没有安装到手机，未修改账号、设备设置或聊天数据库。

安装包：`packages/com.wechat.improve_1.7-7_iphoneos-arm64.deb`。构建与哈希校验见 [验证记录](group-revoke-1.7-7-validation.txt)。

## 实机复核与诊断

安装后完全退出并重新打开微信，开启防撤回，让另一位群成员发送新消息再撤回，确认原消息保留、提示可定位。再检查私聊和自己主动撤回。已被微信删除的历史原消息无法通过本修复恢复。

如仍失败，在“版本控制 → 问题排查”启用现有诊断，复现一次并复制记录。新增的低频状态仅记录阶段名称，不含正文、群号或用户标识：

- `event-unrecognized`：通知内容未通过撤回 XML 解析。
- `account-unavailable`：无法取得当前账号，未放宽跨账号校验。
- `original-not-validated`：原消息未找到或未通过服务器 ID / 会话校验。
- 原有 `original-preserved` 和提示插入结果：处理函数已拦截；仍需以真实界面和重新进入会话后的结果确认。

未重新启用已清理的合并、气泡或时间高频调试日志。

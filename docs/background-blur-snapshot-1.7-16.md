# 返回闪烁优化 · 1.7-16

2026-10-17，用户实机确认“现在正常了”。后续代码检查与整理见 [1.7-17](background-blur-cleanup-1.7-17.md)。下文保留实现和当时的验证记录。

## 录屏观察

分析用户提供的 `ScreenRecording_10-17-2026 21-19-20_1.MP4`（约 8.66 秒），先查看总览，再检查约 4.05–4.85 秒、6.65–7.45 秒的两次返回。

两次返回都经历：较亮的完整模糊卡片放大，随后内容在少量帧中快速显露，背景同时由偏白恢复灰色。取页面中部稳定的 200×200 像素区域，解码亮度均值从约 245–246 降至 234，与画面变清晰同时发生。没有从这些帧中确认“清晰→再次模糊→清晰”的反复切换，不能仅归因于重复生命周期回调。

这表明此前统一 0.22 秒与去掉末帧重复赋值仍未改善用户看到的变化。现有普通模糊材质到 nil 的过渡同时改变模糊和材质亮度；本版更换正常返回的呈现方式，避免继续只微调时长。

## 实现

完整模糊状态恢复活跃时，对当前整个窗口调用 `snapshotViewAfterScreenUpdates:NO`，获得包含已渲染模糊的临时视图。只截取 UIVisualEffectView 本身可能缺失它采样的背景，因此以整个窗口为范围。

先把快照放在原模糊层上方，再隐藏原实时模糊层，整个准备过程不播放动画。对普通快照视图做 0.22 秒 EaseInOut 透明度淡出，让下面的清晰页面逐渐显露。正常完成后在保持原实时模糊层隐藏的情况下移除两层，不重新激活模糊材质。

- 全程不调整实时模糊视图的 alpha；普通快照淡出也不需要把实时 `effect` 动画到 nil。
- 已在播放的进入动画遇到取消手势时仍直接反向衔接；进入动画正常完成后再返回才使用快照淡出。
- 返回淡出中再次失活，反转同一个快照动画。反向完成后先恢复下方完整实时模糊，再移除快照。
- 真正进入后台时取消过渡，立即恢复完整实时模糊并释放快照。
- 关闭、配置重置、隐藏／移除窗口、断开场景以及管理器销毁均清理两层视图与动画。
- 快照不拦截触摸，跟随窗口尺寸；每次正常返回最多捕获一次，重复激活通知不重复捕获。
- UIKit 返回 nil 时回退到原有模糊效果过渡；系统开启减弱动态效果时保持直接切换，不生成快照。

快照仅驻留内存，不写磁盘，过渡完成或取消即释放。沿用现有配置域和开关。版本及内置更新说明同步为 1.7-16。

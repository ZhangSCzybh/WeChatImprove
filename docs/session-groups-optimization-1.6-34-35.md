# 聊天分组两步优化：1.6-34 / 1.6-35

2026-10-17。按用户确认的方案依次完成实现、检查和打包，分别保留 Rootless arm64 / arm64e 安装包。以 GitHub 的 `217f297b`（1.6-33）为基础。未连接 iOS 设备，不把主机检查当作实机流畅度验证。

## 第一步：1.6-34

- 导航任务记录所属账号，刷新准入和调度前淘汰失效账号的排队任务，防止残留队列绕过离屏暂停。账号变化时保留当前账号的有效导航展示请求。
- 发布期间收到原生导航时记录 dirty，外层发布完成后安排一次后续处理，避免任务排队后没有唤醒。
- 待执行的回顶部操作也检查独立的分组手势状态；分组手势结束、取消或失败后唤醒待处理更新。
- 未读数字/红点不变时不重设文字、不请求角标布局；复用标签通过 tabId 字典查找，标题、字体未变时不重复赋值；一次分组栏布局只测量每个标签宽度一次。

351 项回归全部通过：业务行 27、分组选择 30、交互 112、视口 72、表头 46、指示器 23、生命周期 33、角标外观 8。

第一步保持原来的全量数据刷新与选择保存路径，便于与第二步分别对比。构建完成后才开始修改第二步的生产源文件。包内 dylib 与独立构建输出一致，构建期间输入未变化。

## 第二步：1.6-35

### 会话快照复用与失效

适配器缓存原生读取后的不可变 Foundation 行值，不持有私有 session/contact 对象。缓存由账号与模型代次限定。

- 仅选择分组时复用当前快照，仍重新生成目标组投影和正确的路径映射。
- 原生事务开始、刷新请求、设置变化、搜索进入及页面离开使快照失效。未知刷新保守按数据变化处理，不冒险复用。
- 构建过程中模型代次或账号变化，拒绝缓存该结果，走已有的安全空投影/有限重试机制。
- 页面离开时释放完整快照，避免为了隐藏列表持续保留额外全量数据。
- 继续保留操作时的账号/会话身份复核和匿名业务行验证，缓存不代替这些安全检查。

测试中，初始化后的 10 次无数据变化发布没有再次读取原生快照；原生变化、搜索退出和账号变化均重新构建。

### 禁用、搜索与原生导航的轻量路径

分组关闭、正在搜索或账号未知时，不创建分组快照/投影，不更新隐藏分组栏。退出投影模式时执行必要的一次原生恢复重载；已经是原生模式时不额外重载。显式原生导航也不再为获取原生坐标构造无用的分组投影。

继续保留正确的原生 header、代理坐标作用域和搜索恢复行为，未直接删除代理或全局 Hook。

### 独立保存选中分组

新增按账号隔离的小记录 `com.wechat.enhance.chat_group.selection.<account>`，内容仅含版本和 tabID。切换选择不再规范化整份成员列表、备份完整 profile 或强制 synchronize；相同选中值不写入。NSUserDefaults 使用系统的常规异步持久化，读回失败或异常时保留/恢复上次选择，不承诺进程突然终止前尚未落盘的最后一次变化一定可恢复。

配置对象在底层 profile 未变化时复用已规范化的标签。真正修改名称、成员、顺序、隐藏状态等仍经过原来的完整校验、备份、同步和冲突保护。

- 旧版配置直接兼容读取，不自动重写或删除历史分组数据。
- 设置编辑期间只改变选中分组，不再被误认为整份定义冲突；保存定义前读取最新选择。
- 删除或隐藏已选分组时回退到合法可见分组，完整保存后将选择合入旧格式 profile 并清理小记录。
- 未知账号不可写，未知未来版本不可覆盖。
- 降级回 1.6-34 时旧版不会读取独立选择记录，可能恢复到旧 profile 记录的选中项；分组名称、成员、顺序等定义数据仍保留。对比建议先测 34，再升级测 35。

### 被动通知合并

对新消息、会话内容更新、未读总数和会话变化通知使用固定 **40ms 首事件合并窗口**。不会因连续通知不断推迟到最后一条。

原生删除、结构变更、主动选择/跳转不走该等待窗口；直接刷新请求可以提升已排队的被动任务，旧定时任务以代次检查退出。用户切组的同步发布也会消费待更新状态，不被旧定时器重复重载。系统主线程繁忙或正在进行手势时仍会遵守原有交互保护，40ms 不是设备忙时的严格显示延迟上限。

未将未知变化冒险改成局部插入/删除；没有在后台线程读取 UIKit 或微信可变私有对象。

## 验证与量级

1.6-35 共 387 项回归全部通过：业务行 27、选择 30、交互 112、视口 72、表头 46、指示器 23、生命周期 46、角标外观 8、配置保存 23。

新增检查抽取实际生产方法与账号重置分支，覆盖：旧账号导航淘汰、有效新账号导航、重入任务唤醒、手势期间回顶部、缓存复用/失效/构建中变化/离屏释放、禁用与搜索跳过构建、通知合并/直接请求提升/旧任务过期、选择恢复/失败回退/账号隔离/删除与隐藏/编辑冲突/未来版本保护。

相同 M4 主机上，分别编译第一步归档源码和第二步源码，运行相同构造数据、内存 defaults 基准；每阶段预热 3 次，采样 21 次。选中组保存中位数：

| 构造会话 / 总分组 / 成员关联 | 1.6-34 | 1.6-35 |
| --- | ---: | ---: |
| 500 / 4 / 0 | 0.0358 ms | 0.0032 ms |
| 2,000 / 14 / 4,000 | 5.1402 ms | 0.0040 ms |
| 10,000 / 24 / 20,000 | 25.1150 ms | 0.0049 ms |
| 2,000 / 34 / 60,000 | 68.3107 ms | 0.0056 ms |

这反映的是移除成员规范化和全量配置保存的 CPU 开销，**不含真实 defaults IPC/磁盘成本、UIKit 布局、微信私有 getter 或 iPhone FPS**。基准中的 `refresh_data_no_UI` 始终重建原生快照和 Preferences，不包含新适配器的缓存复用，不能用它直接衡量第二步切组总耗时。适配器缓存和通知合并由生产方法回放验证调用次数。

新版本仍需计算目标组投影及重载显示列表；超大列表或大量成员重叠时，剩余投影/布局成本仍需实机测量。没有宣称所有场景的卡顿已彻底消失。

## 安装与对比

- `packages/com.wechat.improve_1.6-34_iphoneos-arm64.deb`：第一步边界修复与重复计算减少。
- `packages/com.wechat.improve_1.6-35_iphoneos-arm64.deb`：包含第一步全部修改及第二步优化；最终工作区代码为此版本。

# 聊天消息合并重构方案（待评审）

日期：2026-10-16。分析基线：当前工作目录，HEAD `c52ccc80`。

用户已确认的症状：滑动不流畅、疑似额外耗电、防撤回提示点击后不能准确定位原文，以及合并后的间距不合理，尤其群聊与私聊布局不同。前两项需要性能测量，后两项必须加入正确性验收，不能只作为视觉优化处理。

本文是源码与头文件审查后的设计提案，不表示功能已实现或通过实机验收。现有未提交的聊天分组修改及 Tests 目录不属于此次设计变更。未启动、重启或安装任何服务/插件，未访问微信数据库。本项目交付对象是 iOS 微信注入插件，没有可作为本次交付地址的网页 URL、前后端端口或本地聊天数据库。

## 1. 结论和边界

推荐保留微信原生消息、section/row、Cell、菜单与数据存储，建立会话内的消息合并上下文，统一决定头像/昵称可见性、组间边界和安全间距。以原生测量与布局为基础，按消息事件增量失效，按实际变化更新视图。

同时修正防撤回的定位入口：消息身份解析与滚动坐标分开，原文未加载时走原生定位加载流程，完成布局后校验真实消息与可见范围。这项修正应在消息合并关闭时也生效。

“合并”定义为连续消息的视觉归组：每条消息继续独立支持长按、引用、删除、转发、发送状态和无障碍操作。不拼接消息内容，不替换微信消息数组，不把多条消息变成一个新 Cell，不改写聊天记录。

不承诺未经实测的“绝对不卡顿、零耗电、全版本完美”。交付必须满足后文正确性不变量与性能门槛；未知私有布局恢复原生表现，不能以裁切内容换取紧凑。

## 3. 当前实现的具体问题

| 问题 | 源码证据 | 后果 / 证据级别 |

| 按时间二分后只搜索前后 20 项 | BubbleStyleHooks.xm:505–540 | 同秒消息较多时存在确定的漏查路径；节点数组包含非消息节点或乱序时不满足二分前提 |

| 设置通知只重载全局标量 | BubbleStyleHooks.xm:268–278 | 不更新当前合并上下文/原生高度缓存/可见行；回调函数签名还通过强转掩盖了不匹配 |
| 气泡绘制每次重新生成位图并写多条日志 | BubbleStyleHooks.xm:198、300、315、322、324、376 | 与合并同时使用时增加热路径 CPU、分配和日志开销；useCache 未用于插件自有缓存 |

相关模块还有两处必须协同修正：

- AvatarHooks.xm:153–167 完全替换 isShowHeadImage 的原生返回值，且会话类型来自全局变量。需要按当前模型所属会话计算，并将原生能力、用户隐藏设置、合并策略组合为同一规则。
- MessageTimeHooks.xm:604–691 向后台队列捕获可复用 Cell，再读取视图/模型，返回主线程后未检查绑定身份。时间显示位于头像下方时，还没有针对合并后的头像可见性和边界高度作协调。

当前消息合并代码没有周期轮询或常驻 DisplayLink；省电改进主要来自消除同步调度、重复查找/绘制、无效布局和热路径日志，而不是删除一个不存在的合并计时器。

### 3.1 防撤回定位专项发现

- RevokeHooks.xm:525–574 用主屏幕尺寸、固定 44pt 导航栏和 50pt 输入框推算可见区，未依据真实聊天表格、键盘、输入框展开、横屏或页面容器。
- 同一函数在 559–561 行把 calculateOffsetWithMsg:marginTop: 的返回结果重新作为 marginTop，随后 642/722 行传给 scrollToMessage。这是非常可疑的“内容偏移量与可见区顶部留白混用”；头文件确认两个接口存在，但返回值的确切运行时语义仍需目标版本验证，不能只靠方法名断言已证实根因。
- 两条点击链分别取提示消息 toUsr 或控制器当前会话，没有一个统一的账号/会话/目标 ID 校验入口。onClickMsg: 在所检头文件中声明于 BaseMsgContentLogicController，而当前 Hook 放在 BaseMsgContentViewController；是否继承或转发可达必须核实，不能认为备用链必然执行。
- 原文查询成功不等于原文已在当前表格内。现代码发起 scrollToMessage 后即返回，没有核对目标是否加载、长文本是否定位正确分段、最终高亮是否对应同一消息，以及原生定位与插件锚点补偿是否互相覆盖。
- handleRevokeMessage 在候选 session 中查到原文后没有把命中的 candidateSession 赋回 session（414–429 行），提示仍插入首候选会话（483 行）。该错误路径需要修复；对已有提示兼容读取，不能搬移或重写历史消息。
- 原文摘要直接插入链接富文本（472–476 行）未转义，正文含 `<`、`>`、`&` 时存在破坏链接结构的风险。新提示应做文本转义；保留旧 revoke_jump_ID 链接兼容。

定位偏差至少需要分别检查“目标身份不正确”和“目标正确但坐标不正确”，并在合并开启/关闭两种状态回归，不能把所有定位问题都归因于消息合并。

| 方案 | 优点 | 问题 | 建议 |

## 5. 交互规则与不变量

### 5.1 默认行为

保留已保存的开关、生效范围、首条/末条头像选项和连续间距数值。未保存的范围统一为运行时当前使用的 3（全部）；读取设置不写默认值。旧连续间距继续解释为“相对原生间距的调整量”，0 是有效值，不偷偷改成绝对间距。负值必须被安全几何下界限制，界面说明会明确这一点。

头像归属按首条或末条**逻辑消息**选择，保留该消息原生合法的头像锚点；末条为多行长文本时，不擅自把头像搬到最后一个分段行，也不在滚动时复制/吸附头像。群昵称跟随既有首/末条选择语义，昵称、身份说明和文字状态作为身份区统一处理；若目标类型无法验证完整身份区，则保留原生身份显示。

用户设置隐藏头像与昵称合并分别计算，不能因为头像本来不显示就跳过昵称分组。全局隐藏头像优先，消息合并不能把它重新显示。

### 5.2 相邻消息可合并条件

必须同时满足同账号、同会话、同方向、相同且可靠的真实发送者，以及相邻节点均属于支持合并的普通消息。接收群消息必须取得真实成员标识；缺失时断组，不能用群 ID 代替成员身份。

按原生节点顺序判断，不按时间重新排序。时间节点、系统/撤回/拍一拍提示、未读分割线、折叠历史、未知节点构成边界，即使其他功能把它们隐藏为零高度，也不擅自跨越。首版不额外引入新的时间阈值，避免无需求依据地改变现有语义；如果目标版本缺少时间边界，需要在兼容适配中明确补充规则后测试。

文本、图片、表情、语音及普通视频逐类验证。金融卡片、直播/互动卡片、带特殊动态区域的消息不能仅因“有 messageWrap”就获得压缩能力。头像归组能力与间距压缩能力分开声明；无法安全压缩可以保留原生高度，无法判断身份则完全断组。

### 5.3 正确性不变量

1. 分组计算不改变原生消息条数、顺序、ID 和数据库。
2. 原生不允许显示的头像/身份元素不会被插件强制显示。
3. 每个 Cell 的结果绑定会话、逻辑消息、分段位置与 generation；旧任务不能更新新绑定。
4. 长文本内部行不承担逻辑消息之间的间距调整；每条逻辑消息的外部边界最多处理一次。
5. 可绘制且应参与交互的内容不会超出压缩后的合法区域；原生允许的特殊溢出须单独适配，否则禁用压缩。
6. 同一输入重复布局得到同一结果，不累积修改 frame、transform 或高度。
7. 关闭功能、切换范围、退出页面、复用和版本降级均能恢复原生布局，无残留隐藏或 alpha。
8. 未支持的类型、身份歧义、布局接口不匹配时回退原生；不吞异常后继续用半旧状态。

## 6. 组件和数据结构

推荐新增以下小组件，并从 BubbleStyleHooks 中移出合并逻辑：

| 组件 | 职责 |
| --- | --- |
| CSMessageMergePreferences | 读取/校验现有配置，生成不可变配置与 revision；提供正确签名的通知入口 |
| CSMessageMergePolicy | Foundation 层纯计算：相邻关系、分组角色、头像/身份区策略；不依赖 UIKit、defaults 或 runtime |
| CSMessageMergeContext | 由一个真实聊天控制器拥有，维护会话身份、generation、节点描述、受影响邻接边与待发布更新 |
| CSMessageMergeNativeBridge | 运行时能力校验，父/子模型归一化，真实控制器/表格校验，原生测量与安全几何适配 |
| CSMessageMergeRenderer | Cell 绑定、原生布局后的差量应用、恢复与重入保护；不搜索整段历史 |
| CSMessageNavigationCoordinator | 防撤回点击的统一身份校验、原生历史定位、布局完成校验及一次性纠偏；不依赖合并开关 |
| Hooks/MessageMergeHooks.xm | 只连接已确认的原生绑定、测量、数据变更和页面生命周期 |

不持久化额外消息数据，不复制正文、图片或语音资源。逻辑消息描述仅保存账号/会话键、内部稳定键、ID 别名、发送者、方向、类型、分段和布局 revision。

身份不是直接选择“有 server ID 用 server ID，否则 local ID”：发送中的消息会补齐 server ID，这样会产生无谓换身份。上下文维护内部稳定键，将经校验的 `(账号, 会话, local ID)` 和 `(账号, 会话, server ID)` 映射为同一消息；两种 ID 都缺失时使用本代临时身份，跨代不猜。重复/冲突 ID 取消该节点合并，不任取一条。ViewModel 指针只作本代绑定加速。

避免多个上下文同时污染一个共享模型：绑定包含 owner/scene，发现模型属于多个场景或不在主聊天表格时返回原生。不在整个进程里无条件覆盖 CommonMessageViewModel 的测量结果。

## 7. 绑定、更新和复杂度

### 7.1 绑定流程

在控制器可确认的 makeCell:indexPath: / cellForRow 流程内取得真实上下文和逻辑节点，再绑定原生 cellView；在 willDisplay 校验身份。具体选择哪个入口以目标版本实际调用顺序为准，不同时盲目重复 Hook 所有入口。

由于 setViewModel 可能发生于 %orig 内部，使用有作用域、可嵌套、退出必清理的绑定上下文，或已建立的模型归属映射，让 setViewModel/measure 提前拿到策略。禁止以全局窗口兜底定位聊天对象。访问其他 table 或子场景时直接走原生。

所有 UIKit 读写和原生可变节点读取在主线程。对于微信可能在后台创建/测量的 ViewModel，只允许读取已经发布的不可变策略；不能为取得主线程数据 dispatch_sync 回主线程。不满足测量协议时返回原生，待主线程完成绑定后通过正常失效流程更新。

### 7.2 更新入口候选

头文件中已存在 addMessageNode、addChatViewModel、replaceMessageNode、removeObjectsFromMessageNodeDatas、removeAllObjectsFromMessageNodeDatas、reloadNodeWithMessageWrap、reloadMessagesInternal 等接口。以运行时验证后最小充分入口集接入，使用嵌套事务深度防止一个事件被多次发布。

只用数组 count 无法识别等数量替换或重排。数据版本由真实增删替换/重建入口推进，并在行绑定时核对局部真实节点身份；发现不一致即停用旧代结果，在安全时机重建。

原生数据修改与表格事务必须使用匹配的策略代：进入修改先标记失效；若 %orig 内同步请求新高度，用当时有效节点及邻接信息计算。不能等 %orig 返回后才让新行使用新规则。原生表格更新期间不再嵌套 beginUpdates/reloadData；额外邻居刷新在事务完成后合并执行，并再次确认路径与身份。

### 7.3 增量范围

- 尾部新增消息：新节点、旧尾节点及必要边界；末条头像模式立即更新旧尾。
- 头部补历史：新加载的 k 个节点和原来的首个邻接边界。
- 删除：被删节点的旧邻居及删除后产生的新邻接边。
- 替换、撤回、翻译、图片尺寸更新：目标节点的布局 revision；若身份/类型/分段改变，连同前后邻边失效。
- 配置、字号、宽度、账号、会话变化：新 generation；在安全时机重建相关策略并清理旧缓存。

合并关系局部更新为 O(k + 受影响邻边)，稳定滚动时 Cell 查询 O(1)。首次加载/确需全量重建为 O(n)。如果实现选择平铺 section 索引，头插或中间删除仍可能使索引维护成为 O(n)，必须如实测量，不把它宣传为 O(1)；应让原生数组提供当前 section，插件优先保存稳定消息与邻接边，减少全量重编号。

正常事件用一个待执行标记合并到下一次主队列可执行点，非定时轮询、非每条消息提交多个任务。持续消息流不能无限重设延迟而饥饿更新。只有不可变快照的纯计算可以考虑后台执行；未经测量不为小规模邻居比较增加线程切换。

## 8. 布局适配：首先保证内容完整

### 8.0 群聊与私聊分别建模

不能以“群聊就乘二”近似所有布局。布局键至少包括会话类型、收发方向、原生身份区可见性、头像策略、消息类型、分段、宽度、字号与内容 revision。

| 场景 | 需要保留/测量的布局 |
| --- | --- |
| 私聊接收 | 左侧头像列、气泡、原生顶底留白、时间/状态区域；无群昵称区时不能扣除虚构的昵称高度 |
| 私聊发送 | 右侧头像/气泡和发送状态；状态按钮不能因为缩短行高被裁切或与上一行重叠 |
| 群聊接收 | 群昵称、成员身份说明、文字状态、头像、内容；按真实身份区几何收紧，不能只隐藏一个 Label |
| 群聊发送 | 以原生实际身份可见性为准，不能仅凭 realChatUsr 为空就判定发送方向或将间距翻倍 |
| 任一场景的引用/翻译/语音展开 | 附加内容计入原生测量；异步展开使旧几何失效，已压缩的空间需重新验证 |

发送方向优先使用已核实的原生 isSender；群真实发送者标识用于比较成员，二者不混用。几何的 pt 数不预先编造，来自目标版本的原生测量适配。

### 8.1 统一测量结果

优先让经验证的原生 measure/layout 链路消费合并后的身份区可见性，再由同一布局方案派生 rowHeight 与 sectionHeight。保持原生左右气泡对齐和头像预留列，隐藏头像不自动扩大文字宽度或改变左右位置。

不能仅在 heightForRow 返回更小的值，原生内容却保留旧位置；也不能独立修改多个高度入口造成重复减距。每种支持类型只选一个权威测量入口，其他入口消费其结果。resetLayoutCache 只对受影响模型执行，并设重入保护；在 layoutSubviews 中禁止刷新列表或递归 layoutIfNeeded。

必须实测 isShowHeadImage / isShowChatRoomDisplayName 是否参与目标版本原生 measure；头文件声明本身不能证明。若目标版本无法通过原生链路安全收紧身份区，保留该部分占位，而不是猜昵称高度或乘以 2。

### 8.2 安全间距

从适配后的原生几何取得允许压缩的边界留白 slack，计算：

```text
requestedDelta = 已有连续间距设置
appliedDelta = max(requestedDelta, -verifiedSlack)
finalHeight = nativeMeasuredHeight + appliedDelta
```

verifiedSlack 必须来自当前类型、宽度、字号、分段、内容 revision 下的测量结果，包含气泡、文字、引用、翻译、身份区、头像、发送状态、来源和插件消息时间的占用及必要触摸间隔。它不是固定 20pt，也不是只取气泡高度。跨行的目标间隙还必须满足下一条内容/状态控件不发生几何冲突。

只有逻辑消息最后一个原生 row 的外部尾部间距可承受本项调整；已被原生测量移除的昵称空间不能再次扣除。行高请求早于可见 Cell 布局时，必须使用已验证的模型测量适配；没有可靠几何就令 verifiedSlack=0，禁用负向压缩，不能为测高批量创建离屏 Cell。

Renderer 在原生布局完成后做有界几何校验。发现不满足约束时，撤销该类型/实例的压缩能力并通过一次受控失效恢复原生高度；不能在布局回调内形成不停重试的反馈循环。

### 8.3 恢复与其他模块

Cell 保存自己实际覆盖过的属性和绑定代次。复用/重新绑定前撤销本插件覆盖，再由原生完成新绑定；不在 %orig 之后统一写 hidden=NO/alpha=1。原生会动态更改的状态优先通过原生重算恢复，不用旧快照覆盖其他模块新值。布局时仅在目标值与实际值不同才写属性，兼顾原生重新创建子视图的情况。

头像最终可见性应为：原生允许 AND 用户没有隐藏 AND 合并策略允许。修正 AvatarHooks 的返回组合和会话上下文是必要联动，不依赖 Hook 注册先后来“碰巧”正确。

消息时间模块在主线程捕获消息身份、时间戳与绑定 token；后台最多格式化纯数据；回主线程验证 token 后应用。头像下方时间在头像被合并隐藏时改用当前消息的气泡侧边锚点，保留每条消息的时间可达性；所有模式的时间占用参与压缩校验。长文本仍只在原定逻辑位置显示时间，不重复生成。

不移动整条 Cell 的 transform，避免破坏已有消息侧滑手势；保留头像点击/长按/拍一拍原生目标，不创建透明头像占位按钮。无障碍继续按原生消息读取发送者与内容，不能因隐藏视觉昵称丢失语义。

## 9. 滚动、生命周期和功耗

### 9.1 防撤回原文定位流程

1. 将 SystemMessageCellView 链接入口及经验证的普通提示点击入口汇入同一个协调器。严格解析完整 revoke_jump_ID，拒绝空、负数、溢出、非数字尾缀；同一点击避免重复导航。
2. 从实际所属聊天控制器取得账号与会话，核验提示消息会话，再按 server ID 查询原消息。优先用已加载上下文找到对应原生节点；需要时调用微信 CMessageMgr 的查询接口。此查询只由点击触发，不在滚动/布局热路径执行。
3. 原文不在当前节点数组时，调用已验证支持历史加载的原生 scrollToMessage / returnToOriginalMsg 路径。不能只拿一个不存在的 indexPath 直接 scrollToRow，也不能在当前会话查不到后跨其他会话“猜一条”。
4. marginTop 仅表示目标在真实可见区内的位置；不把 calculateOffsetWithMsg 的结果回灌为 marginTop。以当前 table.bounds、adjustedContentInset 和转换到同一坐标系的输入工具条/实际遮挡求有效可见区，避免重复扣除已体现在 table frame 或 inset 的键盘/安全区。
5. 短消息优先完整可见并合理居中；长于可见区的消息定位到逻辑消息首个内容分段顶部，让用户从原文开头读起。头像在哪一条显示不改变跳转目标。
6. 为本次导航记录账号、会话、消息身份、generation 和请求 token。利用已验证的原生加载/滚动/布局完成回调，按最终 rect 检查目标身份、可见性和高亮对象；必要时做至多一次无动画位置修正。连续翻译/媒体尺寸变化期间只在明确稳定的布局完成点校验，不添加轮询或无限纠偏。
7. 在导航请求存续期间，合并模块不执行普通“保持旧滚动锚点”或自动贴底，避免把用户刚发起的跳转拉回。切换页面、账号或用户重新拖动时取消旧请求；定位完成后恢复正常滚动策略。
8. 未找到原文、已删除、原生加载失败或该版本不支持定位时，给出可理解的失败提示，停留当前会话；不能高亮相邻消息冒充成功。完成回调不可用时不安排反复尝试，回退到经确认的原生定位能力并记录兼容限制。

本项不迁移或重写历史防撤回记录；新提示记录实际匹配的会话并安全转义摘要，旧链接继续解析。仅定位支持需要新增协同，防撤回拦截策略本身不在此轮全面重写。

### 9.2 常规滚动和功耗

原生滚动逻辑仍是唯一主控。仅对插件主动改变布局的事务记录 `(逻辑消息身份, 分段, 行内偏移)` 锚点。确认原本贴底且没有用户拖动/搜索定位时才延续贴底；浏览历史保持原消息位置，不能每次收消息都滚到底部。

多选、长按菜单、文本选区、原生跳转或动画事务期间，延后插件额外的几何刷新；新绑定仍须校验身份，不能展示旧代错误头像。交互结束合并提交一次；若原生结构更新已让旧几何不安全，则该次回退原生，不冻结宿主更新。锚点消息被删时选最近存活邻居。

页面不可见时不发起额外 Cell 刷新；返回时按当前数据恢复。销毁上下文取消待发布工作，弱引用 owner，清理观察者。账号变化使旧任务 token 失效，不在多个聊天间共享可变视图状态。

省电约束：

- 不新增 timer、CADisplayLink、常驻后台任务或按帧遍历。
- layoutSubviews 不查完整消息数组、不创建 NSInvocation、不调用 defaults、不写常规日志、不重建缓存和图片。
- 稳定绑定的可见 Cell 只进行 O(1) 状态查询及少量属性比较，无额外同步队列。
- 气泡图用有界 NSCache，键包含实际绘图所需的尺寸/scale、position、方向、明暗、颜色/透明度、圆角及样式 revision；可验证后再使用统一拉伸模板减少尺寸种类。内存警告清理，不无限保留历史图像。
- 气泡色彩/圆角与合并配置分开 revision，避免改头像位置导致所有位图重绘。红包身份识别按消息内容 revision 缓存，不每次布局扫描全文。
- 诊断仅在调试开关开启时聚合采样，使用 signpost/计数器记录耗时，不记录聊天正文或高频逐条日志。

## 10. 验证与交付门槛

先验证纯策略和适配边界，再编译，最后在原有设备环境实测。编译成功不能证明微信 UI 正确；头文件不能证明当前安装版本兼容。

### 10.1 自动回归

- 同秒大批量消息（覆盖超过 41 条及大于 100 节点的场景）、时间乱序、插入非消息节点。
- 相同消息重建 wrap，local ID 补齐 server ID，重复/缺失 ID，未知群发送者。
- 首/末头像，A/A/B/A 序列，头插、尾插、删首尾/中间、撤回替换、等数量重排。
- 长文本 1/2/N 个 row：身份归一、唯一头像锚点、仅末行调整外部间距。
- 同 Cell 无 reuse 重新绑定、关闭功能、切范围、原生原本隐藏、不同账号/会话 token。
- 几何属性测试：有限非负结果、内容下界、无重复扣减、重复应用幂等、异常类型恢复原生。
- 嵌套原生更新、更新中查询行高、过期异步时间回调、后台测量、重入保护和释放。
- 防撤回链接严格解析、实际匹配 session、富文本转义、原文未加载/已删除、旧提示兼容、同一点击去重、账号切换取消；margin 与 contentOffset 不混用。

UIKit 替身只验证协议、状态与几何约束，不能用它证明真实微信视图的尺寸和调用顺序。新消息合并测试放在独立文件，不改写正在进行的聊天分组测试。

### 10.2 实机场景

普通私聊与群聊，双方消息，首/末头像，大字号，浅/深色，横竖屏；长文本及引用，文字/语音翻译展开，图片加载与失败，视频/表情，金融卡片回退；上拉历史、连续收消息、撤回/删除、键盘切换、首条未读定位、搜索跳转、长按多选、消息侧滑；头像隐藏、消息时间、界面净化同时开启；进出多个会话与账号切换。

每项检查头像/身份区、实际可见内容、背景/遮罩、发送状态、命中区域、滚动锚点和 VoiceOver。特别验证关闭功能后无需退出微信即可恢复当前页面。

防撤回必须覆盖：原文已加载及远距离历史、同秒连续消息、合并组首/中/末、长文本、提示在另一屏、键盘收起/展开、群聊/私聊、合并开启/关闭。验收以最终高亮消息的 server/local ID 与真实可见区域为依据，不能仅凭“屏幕滚动了”判定成功。短消息在可行情况下完整显示；长消息首段起点进入有效可见区域。

### 10.3 性能预算（拟定验收目标，尚未测得）

以同一设备、同一微信构建、相同聊天内容、相同其他插件配置，比较“合并关闭”“当前实现开启”“重构后开启”。分开测量合并本身和气泡绘制组合。重复至少三轮，固定亮度/刷新率、控制温度和网络负载，记录中位数及尾部情况。

| 指标 | 目标 |
| --- | --- |
| 稳定滚动时插件附加 CPU 工作 | 每帧累计 P95 不超过 1ms，P99 不超过 2ms；以支持的低性能设备确认可达性 |
| 帧体验 | 60Hz/120Hz 对应 16.67/8.33ms 预算；hitch 指标不比关闭合并基线出现可重复劣化，不以平均 FPS 代替卡顿分析 |
| 无消息、无交互停留 | 合并模块 0 周期唤醒、0 主动重绘；宿主原生动画不计作插件新增工作 |
| 连续进出聊天 100 次 | 上下文/Cell 覆盖对象可释放，缓存有界，无持续保留增长趋势 |
| 能耗 | 固定脚本至少 10 分钟重复 A/B，Energy/CPU 时间及可用功率指标不出现可重复的 >5% 增量；低于仪器噪声时报告不可区分，不声称绝对省电 |

Time Profiler、Hitches/Core Animation、Allocations/Leaks、Energy/Power 工具按设备及 Xcode 支持情况选用；模拟器或静态检查不能替代功耗验收。用户已确认目标微信为 8.0.78、Rootless；设备型号与功耗测量尚待实机验收记录。

## 11. 实施顺序与完成定义

1. 核实目标微信的运行时布局入口、真实继承/签名、主/后台测量时机和数据事务顺序，建立支持能力表。不能验证的能力默认关闭。
2. 提取配置、纯策略、身份与上下文，完成边界和复用测试。此阶段替换头像/身份区状态管理，不提前启用未经验证的压缩。
3. 接入受支持类型的原生测量、唯一间距调整和滚动锚点，分别验证私聊与群聊，完成长文本/动态内容/菜单协同；统一防撤回导航并修正 margin/offset 混用风险，保证合并开关两种状态均能定位。
4. 修正头像与消息时间的必要联动、绘图缓存和日志，清理旧查找函数、Map、同步队列及旧高度修正，确保没有两套合并逻辑同时运行。
5. Logos 转换、arm64/arm64e 编译；根据原设备注入方案制作对应包，不自行切换方案或覆盖既有包。
6. 在用户既有微信/账号/数据环境安装已授权产物并完成上述实机验收，保留原插件包以便回退。发布记录写明实际构建、支持类型、回退类型、测量数据与未覆盖边界。

# 1.6-26：切组回到“全部”与 90% 手势区域

## 视频与回退路径

用户提供的 9.45 秒录屏可见 Service/Friend 之间切换后，标题、指示器和列表内容一起回到 Whole，说明选择状态被整体改写，而非单独的动画位置偏移。视频本身没有回调日志，不能据此断言手机上触发了哪个具体 selector。

代码中存在多条会主动设置 `nativePresentation=YES`、随后将显示选择替换为 `preset_0` 的路径：

- `forwardInvocation` 遇到未适配的可选回调或菜单查询时调用 `deferNativePresentation`。
- 行身份映射失败时也请求同样回退；被删除或已过期的索引并不意味着用户要看全部会话。
- `deferNativePresentation` 在下一轮主队列执行，可能晚于一次新的分组选择。
- 原生 `selectRow`/`scrollToRow` 恢复的行不属于当前分组时，通过 `revealNativePath` 切回原生完整列表。
- 原生预览探测以及暂时无法构造有效会话快照，也会触发完整列表回退。

真实偏好模型的连续写入/重新读取回归能够保留 Service/Friend/Group 的稳定 tabId，因此本次优先修复这些越过用户选择的回退路径。

## 修复

1. 投影状态下，代理不声明支持未适配的可选回调。即使 UIKit 缓存了旧能力并继续调用，未知/不安全回调只返回中性结果，不执行原生索引操作、不切换分组。已支持的滚动、行选择及传统侧滑编辑继续转发。
2. 旧行身份失效时仅安排当前分组刷新，保持按身份校验的保护，不退回旧索引操作其他会话。
3. 删除 `deferNativePresentation` 及其异步回退；过滤列表中的预览探测保持返回 nil，不再顺带切到全部。
4. 删除分组外行的 `revealNativePath` 回退。普通原生恢复选择/滚动只在该会话属于当前分组时转换坐标执行。“下一个未读”“按名称定位”等明确的原生导航入口继续使用独立的原生展示路径。用户随后重新切组时，取消较早排队的原生导航。
5. 原生快照暂时无效时，为所选分组发布安全空投影，约 50 ms 后有限重试一次；不把全部会话显示在过滤分组名下。持续失败不会忙循环，后续有效的原生更新可恢复列表。重试带账号和代次校验，数据已恢复、账号变化或新的重试代次会使旧请求失效。
6. 会话列表可视宽度左侧 90% 起手横滑切组，最右侧 10% 起手左滑保留原生菜单；正好 90% 的边界归菜单区域。仍按起点锁定归属，保留纵向滚动、控件排除、菜单打开期间禁止切组等规则。设置说明与当前使用文档已同步。

## 验证

- `verify-group-selection.sh`：30 项通过，执行生产回调分发、可选接口判断、原生选择/滚动 Hook、快照恢复方法，并编译真实分组投影和偏好模型。
- 对照仓库 HEAD（1.6-24）中与 1.6-25 相同的旧回调回退分支：23 项运行，5 项失败，复现代理声明不安全回调、未知/菜单探测及旧行索引触发全部回退。对照只替换适配器方法，表格 Hook 仍为本次版本；不声称整个旧包在手机上执行过测试。
- 指示器回归 23 项、原生表头回归 46 项、视口回归 66 项、编辑/标题/90% 手势边界回归 40 项通过。总计 205 项、零失败。
- 手势测试覆盖 80%、85%、89.9% 的切组归属，90%、95%、99.9% 的菜单归属，以及 bounds 原点偏移后的判断。
- 所有偏好写入使用 UUID 隔离 suite，结束后清理；没有操作微信真实会话或数据库。
- Rootless 包验证见 `session-groups-selection-1.6-26-validation.json`。保留 1.6-25 的删除收尾、回顶、分组标题及此前顶部空白修复。

本轮未在手机上安装。安装后重点复核 Service → Friend、Group → Service、连续点击/横滑、轻微斜向拖动和分组栏附近长按探测，确认标题、内容和指示器一直对应最后选择的分组；从最右 10% 打开菜单后复核删除与正常点击。未适配的新式预览/带捕获索引的菜单回调仍不执行，传统会话侧滑菜单继续走已有的身份映射路径。

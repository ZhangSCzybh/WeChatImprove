# 1.8-23 连续消息紧密布局

2026-10-19，在既有 checkout `/Users/zhangshichao/Documents/Workspace/WeChatImprove` 完成用户批准的紧密布局调整，并沿用 Rootless 流程编译打包。安装包版本、插件内版本和内置更新说明均为 **1.8-23**。既有 1.8-22 等安装包及符号文件完整保留。

## 实现

紧密档改为按实际占用边界规划行高：组内每侧以 1pt 为目标，普通相邻气泡合计约 2pt，并按屏幕像素向外取整。已有原生边距不足 1pt 时不强行增大。单条消息保持原生布局；合并组首条保留原生顶部留白、中间条收紧上下留白、末条收紧顶部并保留原生底部留白。最后一条不再因没有 `joinsNext` 而漏掉组内收紧处理。

布局仍只在 table 的最终行高出口修改行高，不覆盖微信模型的内容尺寸缓存。渲染时平移整个消息视图，保留子视图尺寸、位置、transform 和原生交互区域；复用时只恢复插件自身仍拥有的位移。上一条邻居变化也会使布局决定失效。

固定的“最多减高 25pt”策略和通用的 15pt 昵称附加预算已移除。真实视图出现后，收集当前可见直接子视图的占用范围，包含实际头像、昵称、气泡和附加视图，将原生坐标缓存到消息状态。后续原生行高请求优先使用这份边界。缓存不包含视图强引用，随消息状态释放；原生布局重置、消息身份或邻接关系、配置、内容尺寸、宽度、屏幕比例、昵称显示及辅助内容标记变化时失效。

首次行高请求可能早于 Cell 创建，因此仍需一个有明确范围的首次布局预设：**仅微信 8.0.78（含其补丁版本）且精确类型为普通 TextMessageViewModel 时使用已有布局数据**。该预设保留了头像 44pt 的保守占用，以及已验证的普通正文 y=8、带昵称正文 y=17 等原生位置。44pt 不再作为真实视图出现后的通用预算。它仍是兼容边界，不能宣称所有几何假设已彻底消除。

未知微信版本和其他消息类型没有这份首次预设：先保留原生高度，待实际视图边界可用后，供后续原生测量复用。为避免停滑后突然收紧，获取到更紧的真实尺寸不会主动发起第二次表格刷新；因此这些布局首次显示时可能较松，也不保证在没有新原生测量时立即收紧。

实际内容超出计划时，使用真实占用补回必要空间；无法验证的越界、变换或特殊内容恢复原生高度。空间恢复继续使用已有前后台、滚动、原生更新事务和菜单保护，并保留滚动锚点。没有新增计时器、全表扫描、相邻 Cell 测量依赖或离屏探测 Cell。

气泡透明边距通过 `CSBubbleStyleVisibleInsets` 复用现有图片分析缓存。仅对已解码、朝向正常、可拉伸且显示方式/尺寸保留边距的图片提供数据；同时保护正常图和高亮图的可见范围。未解码、动画、方向不匹配、缩放方式不匹配或不能验证的图片使用完整视图边界。只有被识别为气泡背景的直接子视图扣除透明边距，未知容器继续保守计入占用。

新增及更新的回归覆盖：

- 两条、三条、四条合并消息的全部接缝，包括末条；私聊和群聊，首条/末条头像，正常/紧密模式。
- 普通组内接缝达到 2pt，整组顶部和底部留白保持原生；重复渲染、复用不累积位移，不改变正文 frame。
- 1x、2x、3x 像素对齐，以及非法、非有限、超出原生行高的边界拒绝处理。
- 实际头像为 38pt、60pt、74pt 时使用真实尺寸；需要补回空间时仅产生一次额外刷新，较小尺寸不触发主动收紧刷新。
- 昵称及正文相对位置变化时，精确补回所需空间；翻译状态变化即使内容尺寸不变也会使缓存失效。
- 未知版本先保留原生高度，再复用真实几何；没有因采样而产生额外刷新。宽度变化重新校验。
- 透明图片边距、未适配高亮图保护，以及连续 100 次可见边距查询不增加像素扫描。
- 原有分段长文本保护、时间布局、手势、跳转和前后台检查继续通过。

测试采用 macOS 主机与 UIKit 替身，不能替代微信真实 UIKit 渲染和交互验收。没有测量真机 FPS 或耗电。

## 真机验收

进入插件设置的“气泡样式”，启用合并消息，将“连续消息间距”设为“紧密”。分别检查两条和多条连续消息，尤其是倒数第二条到末条的接缝；对比首条/末条头像以及私聊/群聊。

2pt 是普通组内气泡的目标。头像高于短气泡、昵称显示在末条、头像下时间、大字号和附加内容可能需要更大间距。末条昵称位于正文上方时，昵称本身的空间不会被压掉；希望群聊视觉更连贯时，可比较现有“头像位置：首条”的效果。

继续检查快速滚动、加载历史、切后台恢复、消息删除和替换、展开翻译、字号变化、长按菜单、消息手势及撤回跳转。重点确认首次显示与复用没有重叠或裁切，停滑没有额外收紧跳动。

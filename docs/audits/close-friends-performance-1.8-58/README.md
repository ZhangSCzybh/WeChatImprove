# 1.8-58：密友性能优化与移除自动免打扰

2026-10-21，基于 `codex/close-friends-148` 的 `08a087e2`（1.8-57）实施。继续使用开发目录 `/Users/zhangshichao/.codex/worktrees/close-friends-148/WeChatImprove`；安装包交付到原项目 `packages/`。原项目源码分支、账号、配置、历史安装包保持原状。

用户授权落实性能审查中的六项优化，并明确将第三项改为删除自动设置微信免打扰及对应开关。

| 项目 | 实现 | 保留的行为与失效条件 |
| --- | --- | --- |
| 搜索密码校验 | PBKDF2 放入串行后台队列，移出主线程和策略同步锁；合并同一输入的待处理回调；最多缓存 32 个普通查询的未匹配结果，使用临时随机密钥 HMAC 标记，不缓存正确密码的快速验证材料。 | 保留原有 210,000 轮校验；完整密码在进入原生搜索／历史之前被识别、清空并停止加载。普通联想与网络结果保留。新输入、清空、输入法组合、账号／凭据／认证变化使旧结果失效；切换账号后释放待处理原生回调。 |
| 朋友圈滚动 | 删除作用域退出时对全部动态的点赞布局缓存清理；只在确实过滤点赞的布局调用前后清理该动态缓存。动态列表每个原生调用范围校验一次；点赞／评论分别使用最多 128 项的缓存。 | 原生源数组保持完整；缓存核对策略、账号和数组内容，可变数组原地增删会失效。正常滚动不清整批点赞缓存；关闭／解锁后直接走原生读取。保留现有出现时刷新与重入保护，不新增布局／reloadDataWrap 刷新钩子。 |
| 自动免打扰 | 删除 `CSCloseFriendMuteAdapter`、启动注册、设置项及记录写入接口。 | 微信免打扰完全由用户手动设置，升级不自动改变微信已有状态。旧 `autoMute` 配置允许读取但不再生效；旧 `muteRecords` 仅作为兼容数据保存，不执行恢复。静默通知、拒接和挂断回复继续由各自开关控制。 |
| 锁定／策略刷新 | 已锁定时继续使认证失效，但不重复变更展示版本；同一轮合并策略通知；搜索按页面去重。可见页立即刷新，离屏页在再次显示时应用最新刷新。 | 延迟刷新使用捕获的原始 IMP，保留原生生命周期并避免递归。表格刷新止于所属 UITableView／UICollectionView，避免额外重载其内部媒体列表。锁定保留当前页面，仅退出密友聊天的既有逻辑保留。 |
| 列表／角标 | 搜索 section、通讯录、状态卡片复用投影；聊天角标按账号、数据／策略版本和折叠成员缓存；发现页同一次原生更新内共用互动统计。 | 数据更新、账号／策略改变时重新计算；角标读取仍先通过原生快照有效性检查。未启用、已解锁或相应保护关闭时跳过无效成员遍历。 |
| 到期调度 | 将常驻每秒计时器改成有授权期限时的一次性计时器；锁定时撤销。 | 使用单调时钟，保留 common run-loop modes；拖动页面时也能到期锁定。策略读取先发现过期时仍执行锁定和必要导航，避免刷新撤销到期计时器后遗漏动作。 |

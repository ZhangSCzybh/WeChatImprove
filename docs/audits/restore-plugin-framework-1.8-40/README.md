# 恢复原插件框架 · 1.8-40

用户要求在“再也不会”原有框架内优化重置和备份设置，实际却出现整个插件入口/功能不可用。排查确认：1.8-37 引入的升级备份前置条件，在 1.8-39 版本变化时再次触发；缺失图片导致保护备份失败，启动屏障随之不放行 33 个功能初始化回调，同时 CustomEntryHooks 将原插件入口标题和控制器替换成“备份与恢复”。这条运行路径不能用“功能 Hook 文件与上一版相同”来排除，1.8-39 验证遗漏了此场景。

## 本次修正

- 我页面、设置页面均恢复到 CSNativeSettingsControllerClass / CSCustomViewController 的完整原插件框架。入口显示位置、自定义标题、默认“再也不会”和原授权流程都保留，备份状态不再改写入口。
- 版本号变化和缺少版本备份不再阻止插件初始化。版本更新备份在正常初始化后通过独立 I/O 队列尝试，失败保存到备份设置的状态提示，并允许修复后重试。
- 版本备份不再承诺迁移前状态；需要升级前配置时，用户应事先手动备份。
- 真正待执行或中断的恢复事务仍保留启动核验、账号交接、回滚和禁止向运行中功能应用配置的约束。
- “重置设置”“备份配置”继续位于原插件的原设置项中。主设置页、原生容器和公共设置单元格均未重写。本轮备份子页仅更新与故障范围相关的重试入口和说明。

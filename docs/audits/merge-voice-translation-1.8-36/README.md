# 1.8-36：转文字语音的合并间距

基于用户本轮开始时的 **1.8-35 工作区**修复 `IMG_7445.jpg` 中两种状态：带“转文字”按钮的未读语音、已展开转写框的语音。消息之间仍以 **2pt 逻辑距离**计算，不按屏幕倍率换算。已完成主机回归、Rootless arm64/arm64e 编译与包验证，未在手机安装或进行真机视觉、帧率、温升测试。

## 原因与改动

原 `CSAuxiliaryContentFlags` 将 `bShowingQuickTranTips` 与 `canShowTranslateText` 都作为附加内容，`CSCanCompact` 只接受零标志，因此这两种语音状态都会保留较大原生间距。

1. **带按钮的语音**：已适配微信的按钮容器高 20pt，位于普通语音主体的竖直范围内，显隐仅改变 alpha。对精确 Voice 模型，将这个只影响横向显示的标志排除在高度变化判断之外，避免按钮显隐单独引发行高失效。真实按钮容器仍参与既有子视图边界与变换检查，没有忽略其占位。
2. **完成转写的语音**：微信缓存的 `contentViewSize` 已包含转写框和内部间隔，直接复用完整测量结果。允许该已确认的状态参与首次紧密规划，下边界使用转写框底部，不再减去上方语音气泡的透明底边距。上边界仍使用语音气泡的可见边界。
3. **稳定与性能**：继续在首次行高请求确定高度和内容位移。按钮显隐、未读转已读、缓存通知、图片就绪及停止滚动不触发二次收紧。展开、收起、文字变长等实际输入变化可更新布局；真实越界保留安全扩展，之后不会因子视图变小再次收紧。没有新增轮询、递归扫描、图片解码或富文本重复测量。

语音主体与自身转写框之间的原生 **4pt** 内部间隔保留；**2pt** 用于相邻消息之间。首次几何适配仍限于微信 8.0.78，未确认版本或派生模型保持安全回退。加载中、二次语言翻译、方言反馈及其他未经确认的附加内容继续保留必要空间。

本次运行逻辑只修改 `Controllers/CSMessageMergeAdapter.m`。气泡渲染器、Hook、合并决策策略保持本轮基线内容，保留样式、颜色和既有图片生命周期修复。其余修改为两个测试文件和四个版本/说明文件，总共七个既有文件，详见 [changes.patch](changes.patch)。

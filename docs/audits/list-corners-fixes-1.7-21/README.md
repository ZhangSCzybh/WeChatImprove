# 1.7-21 发现页未读提示修复

基于 `d7b32daa / 1.7-20`，继续在 `codex/list-corners-refactor-1.7-17` 工作树修复。包含 1.7-20 的通讯录标题/字母索引背景、分割线和个人资料卡片圆角修复。

## 原因及处理

IMG_7398.PNG 显示视频号、直播的未读文字覆盖标题，头像与红点错位。旧 DiscoverAdapter 把全部 UILabel 放到同一标题坐标，把提示容器中的任意 UIImageView 当作左图标，并重设容器宽度。这会覆盖微信已有的组合布局。

新实现优先读取原生标题 tag（1000 + rowType），兼容旧布局的领先文字位置。完整行结构容器保留坐标系；左侧图标、标题及标题角标保留相对间距，右侧内容按卡片右边距整体移动。长文字不足时仅收缩文字区；普通提示容器里的头像/红点保持尺寸、间距及原生纵坐标。修剪普通容器时暂时关闭其 autoresizesSubviews，避免系统再次偏移子项，处理后恢复原值。保留负坐标角标、hidden/alpha、触摸归属；不对业务控件新增遮罩。

未知复杂容器若不能安全压缩，保留该次原生布局并仅画背景。只遍历最多两层完整行包装和一层已验证提示组合，不触发 layoutIfNeeded/reloadData，不新增业务 Hook、表格代理或持久缓存。现有 frame 状态用于防止累计偏移。

## 原生静态依据

REA open_binary 确认分析对象 `/tmp/wechat-8.0.78-inset-analysis/WeChat` 的 SHA-256 为 `0b3cd1e2ed1da493a6fe12c9ef6e9b9421c95bcac63417c677f309536f7c1c8e`，结束后关闭会话。

本轮复用离线 Mach-O 解析器，用 LC_FUNCTION_STARTS 确定两个方法边界并用 Capstone 有界反汇编，记录于 native-discover.json；inspect-native.py 为复现脚本。仅把落在 __objc_selrefs 区间的直接加载标为 selector 引用，不声称解析了所有动态接收者。

- makeEntryCell:rowType: `0x101b46b80`：title sizeToFit、1000 + rowType tag、独立右侧容器与头像、红点布局，以及 makeFindPageRedDotAlignmentWith:... 的调用引用。
- getCellAvailableRect:rowType: `0x101b4ad6c`：按 1000/2000 + rowType 查找标题/标题角标，结合安全距离与实际内容宽度计算提示可用区。

静态代码与截图支持修复方向；没有手机实时视图树或实际 UIKit 动画/光栅化证据。新增用例是依据原生角色和截图构建的主机结构模型，不是手机运行抓取。

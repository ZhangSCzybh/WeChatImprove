# 1.8-32 合并消息稳定布局

目标：在已适配微信 8.0.78 的标准消息布局中，紧密模式的组内可见接缝为 **2pt 逻辑点**。同一内容、配置和宽度下，滚动、停止滚动、图片解码、按压态就绪、缓存清除不得导致二次收紧。保留现有合并范围、头像首末位置、样式、底色、文字颜色、通话背景、引用、手势与时间设置。

本次在用户确认可重构后实施，以本次开始时的 1.8-31 工作区为基线，不使用 Git HEAD 覆盖历史未提交工作。`baseline-sha256.json`、`work-path.txt` 记录基线与备份目录。此前 deb、dSYM、录屏、崩溃日志和分析记录全部保留。

## 实现

- 在原生 row-height 回调完成测量后，一次提交 `height` 和 `originDelta`；布局始终使用同一对值。实测内容变小不再修改已发布结果。
- 在首次计划时通过签名检查后的 `BubbleInfo getBubbleImage:isDarkMode:useCache:` 读取普通态和按压态的缓存 UIImage，复用现有有界透明边距缓存。禁止调用 `YYImage.originImage` 或其他延迟解码 getter。接口严格限定于微信 8.0.78、已知 BubbleInfo 类及正确 ABI，未知结果保留原生。
- 模板不同状态取可见范围的并集以保护按压态；标准模板具有一致边距时，普通态与按压态接缝均为 2pt。若第三方模板的两种状态边距不同，较小图形可能有额外空白，优先不发生覆盖。
- 头像与气泡分开计算。标准 38pt 头像在独立横向区域内作必要的纵向调整，使头像完整落在既有行内，不再撑开首条接缝；不缩放、隐藏或裁剪身份行头像。异常头像尺寸、重叠区域或变换仍进入安全验证。
- 引用消息保留正文 + 4pt + 引用内容与上下内边距的完整占用。照片、视频和表情保留测得的内容容器范围；不扫描媒体像素或动画帧。
- 识别 `BaseMessageCellView.m_contentView` 这一层原生容器，检验其直接子视图，而不把透明容器的整行 frame 当作内容。只增加一个已知层级，无递归遍历。
- 缓存 epoch 仅提示验证；比较邻居、账号、会话、配置、尺寸、主题与辅助内容，再决定失效。原生 reset 暂时暴露的 `{0,0}` 不被当作真实内容缩小。
- 安全边界只向外扩展。回退状态与扩展结果保持到真实输入变化，防止反复收紧/放宽；有效输入改变仍允许正常重排。
- 深色边距读取优先使用当前主题的已解码图片；缺失的消息元数据作为暂未就绪处理，后续普通 Apply 即可恢复。就地变更消息类型、方向、引用类型也会更新样式资格。

## 性能约束

首次模板查询每条计划最多两次（普通/按压态），后续同输入行高查询不重复访问该接口。透明边距和样式图片使用现有有界缓存，布局阶段使用保存的边距。辅助状态的 selector 只初始化一次，测量不重复检查同一组辅助状态。没有新增定时器、逐帧轮询、离屏 Cell 测量、递归视图扫描或整段历史扫描。

联合回归在拖动、减速、停止、原生图片就绪、按压态就绪和无变化缓存通知中验证：不出现行高收紧、不增加表格 begin/endUpdates；模板就绪后重复布局不增加像素扫描次数。此类主机计数验证算法行为，不代表真实设备 FPS、功耗或温升测试。

## 明确边界

2pt 适用于没有额外内容占据接缝的标准合并消息。群聊接收方把头像/昵称放在最后一条时，昵称本身仍需要空间；头像下时间、翻译、特殊提示同样保留，不能通过覆盖这些内容强制背景之间为 2pt。异常头像、未知微信版本、缺少可靠首屏指标时保持稳定安全间距，不在滚动停止后尝试重新变窄。

本次主机回归与二进制核验不能替代 iPhone 真机渲染/滚动/发热验收。建议在用户原设备和原微信配置验证：私聊收发各 3 条、群聊发送方 3 条、文本/引用/文本、快速滑动与停止、长按、返回重进、明暗切换；关注首条接缝、引用前后、头像完整、菜单操作与持续滚动温升。

# WeChatImprove

面向 iOS 微信的 Theos 插件，使用 Objective-C / Logos 接入微信原生界面，提供聊天分组、气泡与列表样式、消息操作和配置管理等功能。各项功能可在插件设置中按需开启。

**当前版本：`2.0-18`** · **编译架构：`arm64` / `arm64e`** · **最低编译目标：iOS 15.0**

[功能概览](#功能概览) · [安装与入口](#安装与入口) · [使用说明](#使用说明) · [配置与备份](#配置与备份) · [源码编译](#源码编译) · [开发与验证](#开发与验证) · [常见问题](#常见问题)

## 安装与入口

### 环境与兼容性

| 项目 | 说明 |
| --- | --- |
| 运行方式 | 需要能够向微信加载插件的 iOS 注入环境，直接构建产物为 `.deb` |
| 近期适配参考 | 微信 `8.0.78`；部分原生布局分析基于 `8.0.78.34` |
| 系统目标 | Makefile 的最低编译目标为 iOS `15.0`，不代表所有系统与微信组合均已验证 |
| Rootless | 本地已生成 `2.0-18` 安装包；尚未真机验收 |
| Rootful | 本地已生成 `2.0-18` 安装包；尚未真机验收 |
| Roothide | Makefile 保留构建入口；当前版本没有对应的运行验证结论 |
| 注入依赖 | `control` 声明 `mobilesubstrate >= 0.9.5000`，实际加载取决于设备的注入环境 |

微信私有接口会随版本变化。主机回归和成功打包只能验证相应代码与产物，真实设备上的显示、交互及其他插件组合仍需实际确认。

### 安装步骤

1. 获取与设备注入环境匹配的 `.deb`。本地构建产物包括 [2.0-18 Rootless 安装包](packages/com.wechat.improve_2.0-18_iphoneos-arm64.deb)、[Rootful 安装包](packages/com.wechat.improve_2.0-18_iphoneos-arm.deb) 和 [调试符号](packages/com.wechat.improve_2.0-18_symbols.zip)。
2. 使用设备上适配该环境的包管理器或安装工具安装，并按工具提示重新加载注入环境。
3. 完全退出微信后重新打开，进入 **微信 → 我 → 设置 → 再也不会**。
4. 按页面提示完成公众号关注验证及首次使用声明，然后按需开启功能。

默认入口名称为“再也不会”。在 **入口设置** 中可以修改名称，并选择显示在“我”、微信设置页或已有的插件管理入口；插件管理入口需要宿主环境提供 `WCPluginsMgr`。

仓库未提供可直接安装的 IPA、现成的重签名流程或 `install.sh`。

## 使用说明

以下路径均从插件设置首页进入。

### 聊天分组

进入 **聊天分组**，打开“启用聊天分组”，返回聊天列表即可使用顶部标签栏。

| 分组 | 内容 |
| --- | --- |
| 全部 | 完整会话列表 |
| 群聊 | 群聊会话 |
| 私聊 | 普通联系人会话 |
| 服务 | 公众号、订阅号、服务号及可识别的服务聚合入口 |
| 自定义分组 | 手动选择的会话，同一会话可加入多个自定义组 |

在设置页点击“添加自定义分组”创建分组，点击分组管理成员，通过右上角“排序”调整顺序。左滑分组可重命名、隐藏预设分组或删除自定义分组。删除分组只移除分组配置，不删除会话或聊天记录。

`2.0-18` 的自定义组成员菜单仅有“私聊 / 群聊 / 标签”。私聊、群聊使用原生全屏多选器；标签使用微信原生标签列表批选，再回到原生好友页搜索、调整勾选，最终点完成保存。取消保持原名单；已有群聊、服务号和无法解析成员不会因编辑好友类别丢失。移除的是选人菜单的“全部”，顶部预设“全部”及旧自定义组成员集合均保留。弹窗与全屏显示都等待菜单和原生页各自转场结束，不使用固定延时。详见 [改动、原生证据与验收记录](docs/audits/group-tags-folded-2.0-18/README.md)。

“折叠的聊天”跟随当前分组：内容按同一成员及密友隐私规则过滤，入口显示“折叠的聊天（N）”；确认当前组无可见折叠会话时隐藏。原生数据暂不可读时保留无数量的中性入口，不显示虚假的 0，也不显示其它分组的最后消息。折叠状态仍是微信全局的一份：在某组中取消折叠，会影响其它包含同一会话的组。折叠页不增加分组栏，随当前选中组更新，不为每组另存折叠标记。

“过滤重复联系人”开启后，已加入自定义分组的普通群聊或私聊会话会从对应预设组中移除。“全部”仍保留完整会话；服务号按服务归属显示，也可以手动加入自定义分组。无法可靠识别的其他业务入口可能保留显示。

**搜索与外观：** “显示分组栏搜索按钮”默认开启，使用标签栏右侧按钮进入微信原生搜索，同时收起整块原生搜索头部及其占位；关闭后恢复原生搜索区域。标签字号默认 `18 pt`，支持 `12–28 pt` 及系统动态文字缩放；可配置角标、选中颜色、触感，以及下划线、胶囊包裹或关闭三种指示器动画选项。主列表顶部标题跟随当前分组名称，搜索页保留原生标题。

**横滑操作：** 开启“分组切换手势”后，按手指起始位置区分用途。

| 起手位置 | 行为 |
| --- | --- |
| 会话列表可视区域左侧 `85%` | 左滑切到下一组，右滑切到上一组 |
| 会话列表可视区域右侧 `15%` | 左滑展开微信原生会话菜单 |
| 分组栏标签区域 | 横滑切组；标签超出宽度时优先滚动标签 |

滑动中途跨越分界线不会改变用途，分组首尾不循环，搜索时暂停切组。关闭该手势后恢复原生会话滑动范围。这里的切组手势与聊天内的“消息手势”分别配置。

### 气泡样式与连续消息合并

进入 **气泡样式**，打开“自定义气泡”后，可以选择经典圆角或连续圆角、调整圆角大小，并分别设置浅色/深色下发送方与接收方的背景和字体颜色。页面顶部提供预览，字体颜色也可恢复为跟随微信。

自定义样式覆盖普通文本、引用文本、语音及语音/视频通话记录；链接保留原生文字样式。连续圆角根据消息在组内的位置调整连接处，通话记录保持独立气泡。

“连续消息合并”可独立开启，支持群聊、私聊或全部会话范围。同一发送者的连续消息可保留首条或末条头像，组内间距提供两档：

- **正常**：保留原生间距。
- **紧密**：以相邻消息间 `2 pt` 逻辑距离为目标，头像、昵称和附加内容仍保留必要空间。

当前版本支持带“转文字”按钮及已展开转写内容的语音参与紧密布局，语音与自身转写框之间保留原生内部间隔。加载中、二次翻译等未确认的附加布局，以及未适配的版本或模型，可能保留原生空间。实现与验证范围见 [1.8-36 修复记录](docs/audits/merge-voice-translation-1.8-36/README.md)。

### 列表圆角与悬浮底栏

**列表圆角**可调整卡片圆角、左右边距、置顶/普通会话顶部距离及浅深色背景。与聊天分组同时开启时，卡片首末行依据当前分组实际显示的会话确定。

**底栏样式**复用微信原生按钮、图标、文字与角标，支持悬浮布局、图标导入、文字隐藏、背景、描边、位置和触感设置。描边动画包括扩散呼吸、扩散心跳、经典呼吸、经典心跳和无动画；系统开启“减弱动态效果”时停止动画。修改后返回主页查看效果。

### 消息操作与辅助功能

在 **消息手势** 中，可分别为己方/对方消息的左滑和右滑选择引用、删除、转发、收藏、撤回、复读或禁用；具体动作仍受微信原生能力和消息类型限制。**语音转发**与**复读功能**提供对应的消息菜单能力。

**后台模糊**默认关闭。开启后，微信失去活跃状态时显示模糊，返回后恢复清晰；控制中心、通知中心或系统认证也可能触发该效果。此功能与“后台运行”分别配置。

**后台运行**在开启且微信进入后台时，通过无声音频尝试延长执行；返回前台或关闭开关时停止。2026-10-23 重构改用应用／场景生命周期与音频事件驱动，移除周期检查、后台时间续期循环和“触发间隔”设置；原开关及旧备份中的间隔值保留，间隔不再参与运行。音频数据由插件生成，不依赖微信的 `blank.caf`。微信接管音频会话或系统中断时让出，明确释放或允许恢复后再尝试；启动失败不会持续重试。设置页显示当前状态、上次后台结果及当前微信包是否声明后台音频能力。持续播放仍有基础耗电，iOS 可能挂起或结束进程，不能保证永久运行或后台自动领取必达。未越狱签名 IPA 仍须由原注入／签名流程集成，手机上的运行时间和功耗需实测。详见 [重构与验证记录](docs/audits/background-run-2026-10-23/README.md)。

**版本控制**修改微信返回的版本信息，不执行安装或降级；**更新控制**针对微信内部热更新，App Store 更新由系统管理。

### 密友保护

入口是 **插件设置 → 账号与安全 → 捉迷藏呀**。当前账号首次默认隐藏；在插件主设置页长按顶部头像 **2 秒**，轻震后显示入口并按账号记住，后台和重启后保留。已有密友密码的账号沿用原入口与隐藏偏好。头像手势只负责首次发现，不启用保护或解锁内容，也不覆盖“隐藏密友设置”。开发分支及验证见 [手势入口记录](docs/audits/close-friend-entry-gesture-2026-10-26/README.md)。进入后先设置独立密码、选择密友或密群，再启用；默认临时显示 300 秒，后台、账号切换及重启后重新隐藏。“首页长按解锁”默认开启，长按微信首页顶部导航栏 1 秒触发临时解锁；开启“生物识别解锁”后需通过系统面容／指纹验证，不可用、取消或失败时转密友密码，关闭时保留直接解锁；可在密友的“账号保护”中关闭，或将“长按触发时长”设为 **0.5–2 秒**，保存后生效。在首页原生搜索框输入完整密友密码也可解锁，不受长按开关影响。**密友隐藏时，搜索不显示“解锁后查看”占位行；原生实时联想、“搜索网络结果”和普通搜索照常工作。** 完整密码匹配后立即清空输入并停止本次搜索。解锁期间恢复隐藏的密友设置入口，不修改隐藏选项。临时解锁期间可正常接听和拨打密友语音／视频通话；重新锁定后恢复来电拒接设置。消息通知和朋友圈可见范围图标继续按各自开关处理。“隐藏全部朋友圈可见范围图标”覆盖朋友圈动态流、我的朋友圈列表（含缩略图）和动态详情，关闭后按原始动态恢复图标，不修改实际发布权限。开启图标隐藏时使用已适配的微信原生朋友圈页面；1.9-9 隐藏详情范围图标时保留原生占位及换行，删除按钮保持原位；入口隐藏、生物识别、摇动锁定、长按解锁和时长设置仍归入“账号保护”。详见 [1.9-9 修改与验证记录](docs/audits/close-friend-position-1.9-9/README.md)。开启“摇动立即锁定”后，临时解锁期间轻摇手机即可重新隐藏密友；仅在微信前台检测，锁定或进入后台即停止。

**独立重置**：在密友页底部点击“重置密友”，输入当前密友密码并再次确认，清空当前账号的密友／密群名单、全部选项、密码、生物识别记录及入口发现记录。完成后退出密友页，“捉迷藏呀”恢复首次隐藏；重新长按插件页头像 2 秒可再次发现并设置新密码。该操作不随普通“重置设置”执行，不删除微信好友、聊天记录或其他账号数据，也不改变微信原生免打扰。已确认的重置若中断，下次进入当前账号时继续清理，完成前不允许重新配置。详见 [独立重置记录](docs/audits/close-friend-reset-2026-10-26/README.md)。

功能保留真实好友关系、消息、未读、标签和发布权限。“谁可以看”保持原生可用，在部分可见／不给谁看／提醒谁看的候选列表过滤密友，并保留原有隐藏成员的发布权限。锁定时资料页沿用原生页面与“添加到通讯录”按钮；朋友圈入口保持微信原生页面，密友个人朋友圈仅隐藏下方动态并显示原生横杠；自己的动态详情过滤密友点赞和评论，发现页朋友圈数字角标扣除密友互动。部分消息搜索及状态仍需要临时显示。自 1.8-58 起，自动设置微信免打扰及对应设置项已移除，原生免打扰由用户手动管理。**升级保留微信已有免打扰状态；需要关闭时请在对应好友／群聊中手动调整。** 1.8-44 补齐普通单人 ilink 与旧版单聊的提前拒接入口；「挂断回复」默认关闭，启用后在提交拒接请求后私聊回复对方，同一人 5 分钟内最多一次。1.8-45 修正原生消息创建签名，发送任务独立于通话对象；服务短暂不可用会重试，明确发送失败后最多自动重试两次，复用原消息记录。状态未知时不重复新增消息，最终失败可在临时解锁后的原生聊天中手动重试。部分群广播、进程被杀后的通知及系统 CallKit 首帧仍需真机验证。详见 [密友交付与限制](docs/audits/close-friends-1.8-42/README.md) 和 [挂断回复修复记录](docs/audits/close-friends-1.8-45/README.md)、[1.8-46 搜索修正与复验清单](docs/audits/close-friends-1.8-46/README.md)。

### 定时任务与图片添加到表情

**功能增强 → 定时任务**：总开关和各任务开关默认按账号独立保存，可创建单次、每 N 分钟（1–1440）、每 N 小时（1–168）、每天或每周任务，向一个私聊、群聊或文件传输助手发送文字。列表和编辑页沿用公共设置样式，私聊/群聊使用与密友相同的微信原生选择器，每个任务只接受一个目标。执行前记录去重状态；重启后不会自动重发结果未知的消息。微信被挂起、强退或设备关机时不能保证准点。可选择跳过错过的时刻，或只补发最近 10 分钟内的最后一次。

`2.0-16` 修复弹窗样式下，定时任务选择私聊/群聊时整个插件退出的问题。等待会话类型菜单自身关闭后打开原生选择器，取消回到原编辑页并保留未保存内容；同样覆盖全屏/push 显示。见 [修复与验收记录](docs/audits/scheduled-picker-dismiss-2.0-16/README.md)。

## 配置与备份

聊天分组的成员、排序、隐藏项和选中状态按微信账号保存；多数外观与功能开关使用微信进程内的 `NSUserDefaults`。切换账号后，如果出现“导入旧分组到当前账号”，可确认账号后手动导入，旧配置不会自动复制到所有账号。

进入 **备份配置**，可以创建完整备份、从文件导入、预览恢复和开启自动备份。新快照保存在微信应用容器的 `Library/Preferences/WeChatImprove/BackupV2/`，统一使用 `.wcbak` 二进制 Property List；旧 `Library/Backup` 不再读取或转换，原文件保留。

- **备份内容**：三个实际配置域中登记的插件设置、自定义图片、已存档账号分组，以及当前账号的定时任务（名称、会话、消息、时间规则与任务开关）。日期、二进制颜色和“未设置”状态均保留。图片导出包含实际字节，恢复时重建当前容器路径。
- **恢复流程**：选择模块与原所属账号 → 查看差异 → 保存恢复前保护备份 → 准备计划 → 手动退出并重新打开微信 → 校验和应用。准备完成不表示已恢复；可以取消待执行计划。准备后配置或账号变化会阻止旧计划覆盖新修改。
- **账号范围**：默认恢复全局模块和当前账号分组，其他账号需主动选择，始终保留原账号 ID。未选账号和备份之后出现的新账号记录保留。定时任务仅可恢复到备份原所属的当前账号，恢复后总开关关闭，手动开启时从下一个未来时刻开始；旧备份没有定时任务模块时保留现有任务。联系人/群关系仅允许同一本机来源、同一当前账号恢复。
- **自动备份**：沿用原开关；配置静默约 30 秒后尝试，持续编辑约 5 分钟检查一次，前台补偿并按内容去重。默认保留 20 份自动快照、5 份操作保护快照；手动、导入、收藏和当前事务依赖的快照不自动删除。收藏保护记录保存两份并校验；缺失、损坏或不一致时保留备份并提示“保护待确认”，重新确认后才按规则管理。历史清理先记录候选再删除，结果在备份状态中显示。
- **导入与分享**：导入不会自动应用。仅支持当前 `.wcbak` 二进制格式；旧 `.wechatbackup`、JSON 和旧本机目录不再支持。导出使用系统文件分享，无法读取的快照仍显示并可导出可读取的原件。
- **重置设置**：先选择模块和原所属账号、查看变化，再准备重置并手动重新打开微信。仅删除已登记且被选择的插件配置项。已丢失的图片会在预览中提示，不再阻断重置；保护备份保留其余可读配置和图片，无法找回已丢失文件。事务日志保留原始配置引用，供执行中断时回滚。现存但损坏、过大或不可访问的图片仍需先修复，普通备份继续要求资源完整。
- **故障修复**：版本更新备份因旧图片缺失等原因失败时，原插件入口、完整设置页及其他功能仍正常加载。可在原有“备份配置”页面查看错误，通过“修复当前配置”重新选图或移除无效引用，再点“重试备份与恢复”；活动恢复事务需先取消或完成回滚。

备份不包含微信聊天记录、登录凭据、授权缓存、支付去重账本或支付累计统计，不包含定时任务执行记录或待发送状态（任务配置及添加到表情的开关均包含在配置备份内）。文件可能包含联系人标识、分组成员和自定义文字，当前格式未加密。版本更新备份在插件正常初始化后检查，不作为插件启动条件，也不保证保存迁移前的状态；需要升级前配置时，应先手动创建完整备份。真正待执行或中断的恢复事务仍在功能初始化前校验。

## 源码编译

### 准备工具

- macOS、Xcode，以及可用的 iPhoneOS SDK。
- [Theos](https://theos.dev/docs/installation) 与目标打包方案所需的工具链、签名和打包工具。
- 完整的 `Headers/`、`HeadersFile/`；其中包含项目与微信私有接口声明。

```bash
git clone https://github.com/ZhangSCzybh/WeChatImprove.git
cd WeChatImprove

xcrun --sdk iphoneos --show-sdk-path
```

Makefile 内包含开发机的固定 Theos 路径。下面显式使用 `THEOS` 覆盖它，假设本机安装在 `$HOME/theos`；请按实际位置调整。打包版本直接读取 `control`，避免示例版本号与源码脱节。

### Rootless

```bash
make package -j4 THEOS="$HOME/theos" SCHEME=rootless \
  PACKAGE_VERSION="$(awk '/^Version:/{print $2}' control)"
```

当前版本默认输出：`packages/com.wechat.improve_2.0-18_iphoneos-arm64.deb`。

### Rootful

```bash
make package -j4 THEOS="$HOME/theos" SCHEME=rootful \
  PACKAGE_VERSION="$(awk '/^Version:/{print $2}' control)"
```

当前版本默认输出：`packages/com.wechat.improve_2.0-18_iphoneos-arm.deb`。本地已生成两种方案的安装包。

| 方案 | 动态库安装目录 |
| --- | --- |
| Rootless | `/var/jb/Library/MobileSubstrate/DynamicLibraries/` |
| Rootful | `/Library/MobileSubstrate/DynamicLibraries/` |

两种方案均配置 `arm64` 与 `arm64e`。包名中的 `iphoneos-arm64` / `iphoneos-arm` 是打包方案的架构标识，应按设备注入环境选择。Roothide 可通过 `SCHEME=roothide` 指定，需要匹配的 Theos 方案支持，当前未验证其打包与运行。

> **清理前保留产物：** 项目的 `make clean` 会删除整个 `.theos/` 和 `packages/`，包括其中已有安装包与调试符号。普通打包直接运行 `make package`；需要清理时，先将要保留的文件备份到这些目录之外。

### 版本与产物核对

发布新版本时同步维护：

| 文件 | 内容 |
| --- | --- |
| [`control`](control) | Debian 包版本与依赖 |
| [`Headers/CSUserInfoHelper.h`](Headers/CSUserInfoHelper.h) | `kPluginVersionString`，插件内显示版本 |
| [`Controllers/CSReleaseNotesViewController.m`](Controllers/CSReleaseNotesViewController.m) | 当前版本的内置更新说明 |

`PACKAGE_VERSION` 只覆盖当次打包版本，不会更新插件内显示版本。安装了 `dpkg-deb` 后，可以检查包元数据：

```bash
dpkg-deb -f packages/com.wechat.improve_1.8-56_iphoneos-arm64.deb Version Architecture
```

插件内通过 **关于 → 版本信息** 查看随包提供的离线更新说明。

```text
WeChatImprove/
├── Controllers/        # 设置界面、业务策略、原生适配与渲染组件
├── Hooks/              # Logos Hook 与微信生命周期接入
```

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 准备恢复后设置尚未变化 | 手动退出并重新打开微信后应用；准备完成只表示计划已保存 |
| 升级后版本备份提示图片缺失 | 在原插件的“备份配置”中查看和修复，其他功能继续正常加载；不要删除恢复日志或清空偏好域 |
| 找不到插件入口 | 默认在微信“我 → 设置 → 再也不会”；修改过名称或位置时按实际设置查找，并确认安装方案与注入是否生效 |
| 开启聊天分组后没有标签 | 检查开关、登录状态与微信版本，退出搜索/编辑状态后返回聊天列表，必要时重新打开微信 |
| 原生搜索框不见了 | 默认改用分组栏右侧搜索按钮；关闭“显示分组栏搜索按钮”可恢复原生搜索区域 |
| 横滑只能切组，无法打开会话菜单 | 从会话列表最右侧 `15%` 区域起手左滑，或关闭“分组切换手势” |
| 换账号后找不到自定义分组 | 分组配置按账号保存；旧版无账号归属的配置需在设置页手动导入 |
| 紧密间距下仍有较大空隙 | 昵称、头像、附加内容及未适配布局可能保留必要空间，不能假定所有消息都压到 `2 pt` |
| 包版本和插件显示版本不同 | 核对 `control`、`kPluginVersionString` 与打包参数 `PACKAGE_VERSION` |
| 编译找不到 Theos 或微信头文件 | 显式传入本机 `THEOS` 路径，确认头文件目录完整，并核对 `xcrun` 使用的 SDK |

反馈问题时，请提供插件版本、微信实际版本、iOS 版本、注入环境、相关功能开关及复现步骤。界面问题可附遮挡个人信息后的截图，崩溃问题可附对应日志。项目问题可在 [GitHub Issues](https://github.com/ZhangSCzybh/WeChatImprove/issues) 反馈。

本项目用于学习和研究 iOS 界面定制与 Runtime Hook。感谢 Theos 等开源工具，以及贡献代码、测试和问题反馈的使用者。

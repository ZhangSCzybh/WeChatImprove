# 1.8-56 密友列表、锁定导航与搜索头像修复

基线：`26a91d89`（1.8-55）。开发目录继续使用 `close-friends-148/WeChatImprove`，分支 `codex/close-friends-148`。原项目 `main` 源码不变，安装包交付到原项目 `packages/`。没有连接真机、安装插件或写入微信账号/数据库。

## 修复内容及原因

1. **通讯录 → 群聊仍显示密群**：该页面是 `ChatRoomListViewController → MemberListViewController`，使用 `MemberDataLogic`，不经过原有 `ContactsDataLogic` 过滤。新增仅属于这个页面的展示适配器：分组、行数、联系人、总数和页内搜索使用一致的过滤结果；原始成员数据保留，解锁及原生数据更新后重新生成展示。点击使用同一映射，策略变化后的旧点击被拒绝。编辑密友及红包名单的原生选择器不套用此适配器。

2. **重新隐藏密友时错误退回首页**：旧 `returnSafe:` 无条件关闭弹窗、清空所有导航栈并切到第一个页签。现在根据可见页面和 `BaseMsgContentViewController.GetContact` 的真实会话身份判断：普通页面、普通聊天及普通弹窗留在当前页；仅正在查看隐藏的密友/密群聊天时，退出该聊天并回到已识别的微信聊天列表。从通讯录或弹窗进入聊天也按相同规则处理。返回栈里旧的密友聊天再次出现时会执行同一保护。摇动、超时、切后台及立即锁定共用此规则。状态卡片、转发多选和设置选择器的失效处理不再自动退页；授权失效的设置选择器隐藏内容、禁用完成，仍保留原生取消入口。旧授权不能因稍后解锁而重新提交。

3. **搜索群聊及关注的视频号头像缺失**：旧群聊遮挡层隐藏所有原生子视图，并将头像换成未必已加载完成的截图；它只在少数搜索分区重新渲染时撤销。微信 8.0.78 的群聊、联系人与视频号本地搜索都复用 `FTSContactCell`，视频号分区不会调用旧撤销逻辑。删除整个截图/遮挡层，在原生 `updateContact:matchTip:asTopHit:` 前仅移除群成员匹配摘要；群头像、视频号头像及其异步加载、原生显隐和复用交还微信。群名使用公开群名，没有群名时使用“群聊”，避免生成群成员姓名标题。普通联想、网络搜索、视频号匹配提示保持原生；完整密码匹配解锁的输入清理逻辑未改变。

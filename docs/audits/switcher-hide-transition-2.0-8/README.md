# 2.0-8：切换器密友隐藏闪空与转场

> 此方案已由 [2.0-9 静默隐藏修复](../switcher-silent-hide-2.0-9/README.md) 替代。用户澄清要求无动画，2.0-8 的抖动、缩放与文字占位已撤除；本文件保留当时的分析和测试证据。

2026-10-24。输入为用户提供的 2.0-7 真机录屏；修复与打包在原 WeChatImprove checkout 完成。测试使用 macOS 临时目录和宿主替身，没有连接或改写真机数据。

## 录屏与根因

已查看用户提供的拼图、白屏原图，并从原始 `docs/feedbacks/2026-10-24-switcher-white-flash.mp4` 重新解码连续帧。原视频为 592×1280、30 fps、130 帧、4.333 秒。

[`video-frames-42-84.png`](video-frames-42-84.png) 按行排列原视频零基帧号 42–84：第 49 帧（1.633 秒）开始，整张会话表消失；第 75 帧（2.500 秒）恢复表头和一条普通会话。空白帧里顶部“私聊”和底栏仍在，分组栏、搜索/提示头和会话行一起消失；恢复后密友行已经被过滤。该证据对应表级隐藏，不是新 push 空白页面，也不是整窗灰色遮罩。

修改前源码保存在 [`before/Controllers/CSGroupListAdapter.m`](before/Controllers/CSGroupListAdapter.m)：

1. `closeFriendPolicyChanged:` 原第 201–202 行保存可见性后直接设置 `adapter.table.hidden=YES`。普通会话和整个 table header 也被一起隐藏。
2. `refresh` 原第 455 行在 App 非活跃时返回；只有刷新完成后的 `finally` 原第 560–561 行才重新显示表格。
3. `applicationActivityChanged:` 将 `WillResignActive` 和 `DidEnterBackground` 都作为非活跃处理，取消待执行刷新，直到 `DidBecomeActive` 才恢复。

因此，进入切换器的 `WillResignActive` 已足以触发问题，不必等到真正后台：密友锁定通知隐藏表格 → 非活跃门禁拒绝更新 → 表格一直隐藏 → 回前台完成过滤后才重现。这也解释了为什么前台单独锁定通常只是极短同步刷新，而切换器能出现约 0.87 秒的空表。

2.0-7 移除关闭后台模糊时的整窗密友遮罩，使这个既有表级隐藏过程直接可见。修复落在会话列表隐私刷新链路。

## 修改与动画行为

生产逻辑修改为 `Controllers/CSGroupListAdapter.m`，新增 `Controllers/CSCloseFriendListTransition.h/.m`；另同步版本与发布说明。

- 策略变化不再改变 `table.hidden`，保留表头、分组栏和普通会话。
- 仅“待处理隐私刷新 + 当前策略要求隐藏”可以在非活跃时完成一次安全发布。普通消息、未读、草稿更新以及后台解锁仍延后；非活跃时不执行待处理导航动作，离屏列表仍遵守原生命周期。
- 微信正在原生列表事务中时，使用已交付单元格的不可变身份遮住敏感行；身份未知、账号不匹配或策略不可读时从严遮住对应行。遮挡是有文字的“不含姓名和消息”的行内视图，不清空整个列表，不创建全窗背景遮罩，也不截图保存私密内容。
- 更新前同步释放旧单元格的遮挡/交互/无障碍归属，再执行原生重用和数据发布，防止覆盖新单元格的状态；发布异常在退出当前调用前重新遮住敏感行，账号未就绪的原生回退也保持保护。
- 成功发布后，对已过滤的安全列表执行 **0.24 秒**转场：横向 `0 → -5 → +4 → -2 → 0 pt`，缩放相对原比例 `100% → 98.5% → 100%`。模型层 transform 保持原值；清理不依赖动画 completion。
- 真正进入后台、离开会话列表或解除 adapter 时停止自身动画；已经后台、表格不可见、未挂窗口或系统“减弱动态效果”开启时直接完成。重复锁定通知在敏感行已消失后不会打断本次动画。

这次的“摇晃隐藏”是**安全列表的轻抖与收拢反馈**。原有“摇动立即锁定”只有传感器触发，没有视觉抖动；它仍使用原锁定链路，新转场会在成功发布后生效。密友原文字段立即进入隐藏保护，不保留原文画面做淡出动画。前台可观察完整反馈；iOS 可能将切换器中途动画截成静态卡片，不能保证系统卡片播放完整 0.24 秒。验收重点是始终保留普通列表/表头且没有私密残影。

## 真机验收

1. 用原注入/签名流程更新后完全退出并重开微信，设置页确认 2.0-8。保持原账号和数据。在“私聊”分组准备至少一条普通会话和一条密友会话，关闭后台模糊并临时解锁密友。
2. 慢速拉起切换器、取消手势返回、再次打开切换器，然后真正返回桌面。各过程录屏确认分组栏和普通会话始终保留，没有“只有标题和底栏”的空白帧，卡片不保留密友原文。
3. 回前台重新解锁，开启“摇动立即锁定”，轻摇手机。应看到已过滤列表短促左右抖动、轻微收拢后回位；普通会话可立即点击，不应留下占位、遮罩或缩放偏移。
4. 在列表滚动/侧滑菜单/有新消息到达时重复隐藏，检查没有全表闪空、卡住或密友内容回闪。列表更新中的短暂敏感行占位可出现，完成后应退出。
5. 正在查看密友聊天时切后台，回前台应已退出敏感聊天，列表仍有普通会话。测试分组开启/关闭各一次。
6. 开启系统“减弱动态效果”重复，隐藏立即完成且不抖动；打开后台模糊检查其原有模糊行为，再关闭检查没有全窗遮罩残留。

本次没有连接真机，包已编译和校验；iOS 切换器采样时序与动画观感需以上步骤确认。若仍有闪空，提供 2.0-8 新录屏、系统版本、分组开关状态，以及当时是普通列表、搜索还是密友聊天，便于对齐具体生命周期。

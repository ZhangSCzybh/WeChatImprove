## 已实现的使用流程

1. **创建备份**：明确登记三个实际偏好域的 313 个固定字段及受约束账号键，保留日期、颜色二进制、空值/缺失状态、已存档账号分组以及图片字节。未知字段、微信自身设置、授权缓存、支付统计与账本不进入恢复范围。
2. **导入/导出**：`.wcbak` v2 使用带类型摘要的二进制 Property List；导入先校验再保存，不改变当前设置。支持旧 JSON 两种扩展名与旧本机 UUID 目录，保留原 ID、时间、名称和原件，明确提示旧格式不可恢复的内容。导出通过系统文件分享。
3. **预览/准备恢复**：选择模块及原账号，查看变化，保存恢复前保护快照，再记录待执行计划。此时配置尚未应用；配置或账号变化会使旧计划失效。账号分组仅合并选中切片；联系人/群关系仅允许同一本机来源与同一当前账号。
4. **重启后应用**：插件消费者初始化前处理日志，核验身份及 revision，应用图片/字段，检查同步及回读结果，最后确认交接。应用或回滚被中断时，下次启动继续处理 before-image；未完成事务不会释放功能 Hook。
5. **自动保护**：保留原自动备份开关；静默约 30 秒后尝试，持续编辑约 5 分钟检查一次，失败约 60 秒后重试，后台不承诺执行。按内容及来源账号/安装标识去重。保留 20 份自动快照与合计 5 份升级/恢复保护快照；手动、导入、收藏和活动事务依赖不会自动删除。
6. **重置/修复**：重置共用模块选择、保护快照和恢复事务。首次升级保护因缺失图片失败时，备份页提供“修复当前配置”，允许进入原图片编辑页修复后重试；有活动事务时先取消或完成回滚。没有整域清空、自动删除旧数据或进程强退。

新快照与事务文件位于微信容器内 `Library/Application Support/WeChatImprove/BackupV2/`；原 `Library/Backup/` 只读保留。资源仍归原插件目录 `Library/Preferences/WeChatImprove/`，恢复时仅写所选登记项拥有的文件。相同内容图片的恢复路径按所有者区分，避免一个编辑器删除另一设置使用的图片。

## 关键实现边界

| 组件 | 职责 |
| --- | --- |
| `CSBackupRegistry` | 精确域/键、类型、模块、账号/关系归属和资源登记 |
| `CSBackupCodec` / `CSBackupAssets` | 类型摘要、格式/对象/资源图校验、图片捕获和路径重建 |
| `CSBackupLegacyReader` | 旧格式的有界、只读转换 |
| `CSBackupStore` | 不可变快照、原子发布、紧凑列表、元信息、保留策略及日志 |
| `CSBackupEngine` | 双次一致性采集、差异、账号切片、保护快照、准备/应用/核验/回滚 |
| `CSBackupManager` / `CSBackupScheduler` | 串行后台工作、UIKit 回调、文件导入分享和自动调度 |
| `CSBackupBootstrap` / `BackupLifecycleHooks` | 初始化屏障、原生账号代次、恢复入口与最终交接 |

格式限制为文件 32 MiB、单图片 4 MiB、图片总量 24 MiB、256 个资源、单图 1600 万像素、32 层嵌套。before-image 唯一图片限制 48 MiB，事务日志上限 80 MiB；超限拒绝，不截断后声称完整。备份未加密，系统文件权限与 iOS 文件保护不等于导出文件加密。

大型文件、图片、哈希和日志在串行后台队列处理；必要偏好副本及账号读取在主线程完成。**最终恢复交接有一个明确例外**：主线程持有原生账号边界锁时，写入不超过 4 KiB 的 `activation.plist`，再同步释放初始化回调；后台队列在交接期间等待，避免取消/新计划插入。该上限约束字节数，不能保证设备 fsync 时延。

`committed` 与已交接分开记录。交接前终止进程，在下次启动核验或回滚；已交接后用户的正常修改则保留。取消未交接提交会先回滚，新的计划也不能丢弃它。若确认文件已重命名成功但目录同步返回错误，仍在锁内回读精确事务/账号/安装标识；确认已可见则完成交接，否则失败并回滚。证据覆盖普通进程终止与注入的 I/O 失败，**不承诺任意断电、文件系统损坏或 NSUserDefaults 的跨域原子事务**。

## 对其他功能的控制与核对

- 33 个功能 Hook 文件只做必要的初始化屏障接入；正常已保护版本且无日志时仍同步执行原构造顺序。旧文件中隐式 Logos `%init` 改为显式初始化，以免绕过屏障；防撤回原条件分组保留。`CSAvatarShape` 构造函数移到 Hook 定义后以满足生成声明顺序。
- `CustomEntryHooks` 和新账号边界 Hook 始终可用，恢复等待时可从微信原生入口访问备份。资源编辑器仅增加一致性代次及必要缺失图片修复处理；触摸图片替换保留原图直到原子写成功。
- 分组、消息执行、红包/收款、气泡及合并等业务核心没有随本轮重构。对原工作区文件哈希核对，**187 个既有 Controller/Header 文件保持一致**，没有范围之外的修改或丢失。
- **1,623 个既有 docs/packages 文件保持原哈希**，包括历史安装包、符号和分析材料；原有 `.DS_Store` 修改也保留。未执行 `make clean`，未切换工作区、启动服务或操作实际数据库。

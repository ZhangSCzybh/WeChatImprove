# 密友 1.8-44 真机反馈修复

交付版本：`1.8-44`，Rootless，`arm64 + arm64e`，最低编译目标 iOS 15.0。基于当前 `codex/close-friends` 的 `b2b5ca19` 开发，保留既有工程、配置和旧安装包；没有安装到手机或修改真实微信数据。

## 本轮修复

1. **朋友圈提醒谁看**：识别 `WCNewCommitViewController → ContactsSelectorController → MultiSelectContactsViewController → ContactSelectView` 的原生选择器链，补齐候选列表及搜索过滤。通过 common setup 绑定编辑器身份，兼容被会话选择器承载的分支。复用显示投影，不删除真实已选提醒对象、草稿、标签或发布权限。
2. **搜索密码解锁**：调用微信原生 `inputBoxClear` 清空当前可见输入控件，再取消延迟搜索与当前搜索，清除加载尾部。阻止残留回调重新显示加载圈，下一次普通搜索恢复原生流程。输入法未提交文本不会被消费；生产日志与本审计不保存实际密码。
3. **来电提前拒接**：补齐普通单人 ilink 和旧单聊的 `onMonoServiceMsgHandleWithMsg:` / `onMonoServiceMsgStartWithMsg:`，在原生打开语音／视频窗口、响铃及发出来电提示之前提交原生拒接请求。保留原生邀请队列的历史与出队处理，按账号、房间及邀请去重；不会用新邀请重置另一通普通通话。已匹配的子通话仍走其自己的拒接对象。
4. **挂断回复**：新增独立开关和可编辑的单行文案，默认关闭，默认文案“现在不方便接听，请留言。”。开启后仅对自动拒接的单人语音／视频来电私聊回复，同一人 5 分钟内最多一次，同一房间重复回调不重复发送。纯静默、未执行拒接、已取消或过期邀请、群通话不自动回复。发送前再次检查账号边界、名单、拒接选项和回复开关；文本经过微信原生消息发送入口。文案随当前账号的密友配置加密保存。

## 验证与产物

定向验证记录在 `host-results.json`；双架构构建日志为 `build.log`。`validation.json` 记录最终包校验、架构、系统目标、版本一致性、源码哈希、打包动态库与构建产物一致性，以及旧包保留结果。`verify-delivery.py` 可复核本次交付。

只运行受影响的 contacts、social、alerts、core 主机套件及一次完整 package 构建。测试使用内存替身和临时目录，不调用真实微信、不向联系人发消息。静态证据分别位于 `search-native/`、`reminder-native/`、`call-native/`。

## 真机复验

- 锁定状态下进入“提醒谁看”，列表、搜索均无密友；普通好友可选，返回后原有发布范围和提醒名单保持正常。临时解锁后密友恢复显示。
- 首页搜索输入完整密码后，实际输入框立即变空，“搜索中”消失；继续搜索普通联系人可正常完成，返回聊天列表可见已解锁的密友。
- 用密友分别拨打语音与视频：微信内不响铃、不出现来电窗口，主叫侧收到拒接结果。再验证普通好友来电不受影响，以及已有普通通话期间的另一通密友来电。
- 开启挂断回复、修改文案：拒接后对方收到一次正确私聊回复；短时间重复拨打不连续发消息，关闭开关后不发送。临时解锁仍按来电设置拒接和回复。

当前可验证的是 WeChat 8.0.78 静态调用链、主机行为测试和包构建，不是手机上的执行结果。系统 CallKit 首帧、微信进程被杀后由系统展示的通知，以及设备后台调度需要真机复验；不承诺系统层绝对零提示。原有其他版本和群通话兼容性限制继续适用。

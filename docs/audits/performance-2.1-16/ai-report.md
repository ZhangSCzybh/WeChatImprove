# AI 会话入口过滤

本轮在 `CSAIReplyManager` 发布按账号 epoch 隔离的不可变启用会话集合，短锁只负责发布及保留 Foundation 快照。`AIReplyHooks` 和 Manager 的非主线程入口先查询该集合，不读取 Store 或微信消息内容；未知／空会话继续进入主线程原有验证。配置对象未变化时复用已生成的集合。

主线程的账号、配置、会话、消息来源、去重和发送授权检查全部保留。入口结果仅为准入提示，不代替执行时的最终判断。启用／关闭会话的配置保存完成时更新集合，切号或全局不可用时关闭入口。

核心证据：AI 总开关开启后，实际原生入口接收 1,000 条未启用／未配置会话消息，原生接收调用增加 1,000 次，额外主线程投递为 0，消息正文和身份读取为 0。启用会话仍投递；空字符串、非字符串与 nil 仍投递至主线程解析；关闭与重新开启会话更新准入；旧 epoch 回调不读取消息。另有 1,000 次并发快照读取校验。

| 脚本 | 结果 |
| --- | --- |
| verify-ai-manager.sh | 501 项通过 |
| verify-ai-coordinator.sh | 4,496 项通过 |
| verify-ai-native.sh | 86 项通过 |
| verify-ai-credentials.sh | 30 项通过；7 次替身凭据读取，主线程 0 次 |

测试使用独立临时 Store、微信原生接口替身及凭据／模型替身，不访问真实账号、不请求模型、不修改聊天数据库。iOS 两架构完整编译与包核验由本轮统一构建执行。

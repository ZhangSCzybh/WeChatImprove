本次在既有 `/Users/zhangshichao/Documents/Workspace/WeChatImprove` checkout 完成群聊功能，版本为 `2.4-3`。设置入口在“小丑功能”之后，页面沿用项目的 `CSSettingsTableViewController`、设置项、单元格和转场工具；群选择复用微信原生 `GroupSelectContactsViewController` 多选流程。

## 实现行为

| 功能 | 已实现的行为 |
| --- | --- |
| 入群欢迎 | 按群多选；自定义多行模板；`@昵称` 同时生成可见昵称与原生 `m_nsAtUserList`，多人加入合并发送；支持 `@群昵称`、`@时间`、`@群人数`；延迟 0–300 秒，默认 3 秒。 |
| 退群监控 | 按群多选；完整成员名单发生减少时，在原群插入 `10000` 类型本地系统提示；关闭新消息到达通知，不向群内发送；自定义模板，昵称通过专用链接打开微信原生成员资料页。 |
| 自动添加通讯录 | 仅根据新鲜的原生自身入群时间或连续完整名单中的自身重新加入证据，调用 `ShowInContactBook:sync:` 并提交原生 oplog，回读 `isMMContact`；开启前已有群不批量补存。 |
| 批量退群 | 原生群聊多选、完整名单确认、默认不清空聊天记录；资金待办检查；调用原生 `BatchQuitChatRoomLogic`，20 群一批串行执行；逐群显示成功、失败、需处理、未知、跳过；停止只影响未提交的后续操作。 |

自动功能默认关闭。批量退出是单次用户操作，不持久化选择或任务，也不会在启动、恢复配置后自动执行。当前批量适配只开放普通 `@chatroom`；OpenIM 和其他未证明兼容的群类型不提交。

退群提示默认文案：

```text
@昵称 退出了群聊
检测时间：@时间
当前剩余人数@群人数，江湖再见！
点击昵称可进入资料页
```

模板只做一次变量替换，昵称、群名等数据不会被二次解释为模板。系统提示文本进行 XML 转义，仅模块内部产生的昵称链接可成为标签。欢迎里的手写 `@某人` 保持普通文本，只有 `@昵称` 的成员身份会进入原生提醒名单，不生成 `@所有人`。

## 完整成员与生命周期边界

成员事件来自微信原生 `CGroupMgr.OnGetChatRoomMemberDetail:`。接收成功响应后，要求请求群名与响应群名相同、成员数与去重身份数量一致；等待原生方法处理完成，再核对最终 `ChatRoomData.chatRoomVersion` 与响应 `serverVersion`、原生用户名集合与响应完整集合一致。昵称等辅助数据读取完成后再次核对版本、身份和账号边界，最后在主线程发布不可变快照。

实现没有用 `GetGroupMember:` 返回的联系人数量作成员差分，因为本地缺失联系人会造成误报。也不把 `newChatroomData.chatRoomMember` 的部分详细资料当作完整身份名单。`localMemberVersion` 没有用作服务端版本相等门禁：目标版本的完整请求传 `clientVersion=0`，原生会将 `localMemberVersion` 设为常量 5，它不是本次请求的客户端版本或服务端 `serverVersion`。完整性依赖成功全量响应、最终群版本和精确身份集合的联合校验，相关汇编位于 [设计审计](../group-chat-design-2026-11-10/README.md)。

首次完整名单只建立基线。冷启动、切换账号、回前台及配置事务会清除旧欢迎并重建基线；前台会话和配置切换同时推进原子 ingress 令牌，旧的排队原生回调不能跨边界发布。后台不补发欢迎或退群事件。持久化的 `.members` 仅为诊断快照，不在启动时作为可执行基线加载，也不进入配置备份。

欢迎需要新鲜入群证据；无原生入群时间时，仅接纳 120 秒以内连续前台完整快照之间的变化。实际提交前再次检查账号、授权、配置代次、前台会话、期限、群状态及每个待欢迎成员。成员提前离开会从旧待发送任务中剔除；同 wxid 再加入产生新任务，不会复活旧欢迎。原生提交异常或结果未知不自动重发。

自身缺失或群不可用的完整快照保留版本水位，防止迟到旧响应把已退出的群重新引入。自身被移出不会产生其他成员集体退群提示。本地提示若无法插入，设置页显示状态，基线不回退以免重复提示。

## 编译与保留

```sh
python3 docs/audits/group-chat-tools-2.4-3/build.py --build
```

构建使用当前项目源码的冻结快照，在临时目录分别编译 rootless/rootful，不执行 `make clean`，不在既有 `.theos` 或历史安装包中写入产物。交付前校验 control 版本、内嵌版本、包路径、注入过滤器、两种 CPU 架构、新功能符号、既有语音功能符号及 dSYM UUID，再生成 SHA-256 清单与符号归档。

首轮 rootless/rootful 编译与二进制检查通过，但保留门禁发现 Finder 更新了 `packages/.DS_Store`，因此没有发布该轮输出。对比确认既有 `.theos` 和所有实际历史包内容均未改变。构建器保留原始基线，仅把 `.DS_Store` 作为 Finder 元数据单独记录并排除内容保留比较；详见每次构建的 `finder-metadata-changes.json`。最终结果见 [build-result.json](build-result.json)。首轮之后增加的配置不确定写入重读、响应同群校验及延迟欢迎退群/重入取消均在最终构建中重新编译。

交付目录：`packages/2.4-3-group-chat-tools/`，包含两套 `.deb`、rootful 重签用 dylib、四份 dSYM 的 zip 及 SHA256SUMS。版本显示、control、内置更新说明和 README 均为 `2.4-3`。

## 清理结果

检查覆盖 Hooks/ListCornerRadiusHooks.xm、CSListCorner 开头的生产实现/头文件与设置页，交叉搜索 Controllers、Headers、Hooks、Tests 的引用，并检查 Makefile 构建入口。没有发现此范围内的 NSLog、printf、os_log、Logos %log、诊断断言、DEBUG 分支或临时探针；不能把“没有找到调试代码”写成“删除了大量调试代码”。Makefile 已使用 DEBUG=0/FINALPACKAGE=1。

实际清理：

1. CSListCornerFooterHeight 的 section、pinnedGap、normalGap 三个参数从未参与返回值，删除参数及四个调用点的传递；保留原生回调签名、每次一次 %orig、关闭态原始返回值和各页高度结果。
2. CSListCornerLoadColor 与 CSListCornerHideSeparator 只被所属 .m 调用，改为 static 并移除无外部消费者的头文件声明；函数本体继续使用。
3. CSListCornerPageContext 的 cell/table/indexPath/style 仅内部使用，移除四个对外声明，内部状态及其生命周期不变。
4. 三处重复的 object ivar 类型验证和读取统一到文件私有 helper。保留原顺序：无有效 native view 时不读取 cell.contentView。清理中一次提前求值被既有重入测试发现，已修正；没有修改测试掩盖问题。
5. 设置页 ListColorPreviewView 只通过 backgroundColor 显示预览、无 drawRect 实现，删除额外 setNeedsDisplay 请求，保留颜色赋值和全部设置交互。
6. docs/list-corner-radius.md 原先指向失效文件/命令，改为当前文档入口；历史记录仍在 Git 历史。

四页适配器及渲染器与 1.7-22 完全相同；回归用例及基线未改动。保留已验证的兼容分支、未知视图回退、重入保护、原生 frame 状态、配置注入/失效机制及发现页单次异步刷新。它们不是可确认无效的代码。Tests 和 docs/audits 不参与 Makefile 的生产源码 glob，不作为调试代码删除。

## 相比 1.7-17 的实际收益

| 维度 | 1.7-17 | 当前实现与意义 |
|---|---|---|
| 代码职责 | 1371 行 Hook 文件混合四页布局、设置读取和分组处理 | Hook 文件 233 行，配置、纯高度策略、上下文、四页适配各自独立；修单页时更容易约束影响范围。这是职责拆分，不等同于总行数或二进制体积必然下降 |
| 配置读取 | 绘制路径分别调用 defaults 获取开关、边距、颜色 | 不可变快照缓存，设置改变后失效；重复布局不重复读持久化配置、构造同一批颜色。现有测试验证缓存命中不增加读取次数 |
| 页面与视图归属 | 控制器类名、父视图遍历、固定 tag 查找背景 | 验证实际主表；关联对象持有专用背景，重新验证真实 contentView；减少误处理同控制器搜索表、误认原生 tag 和复用后旧背景的问题 |
| 布局稳定性 | 部分偏移基于已经修改过的 frame；发现页通用标签/图片重排 | 区分原生 frame 与已应用 frame，重复装饰不累计位移；右侧提示、头像与红点保留角色与相对关系 |
| 资料卡与裁剪 | 个人资料头部直接 masksToBounds，按屏幕宽度处理并直接调用 layoutSubviews | 使用目标容器宽度，圆角仅裁剪插件背景；保留状态卡片、二维码等原生内容和交互范围 |
| 分组边界 | 已接入 CSGroupCardPosition，但失败就回退原生行数 | 保留分组角色来源；分组活动但路径无效时退出，避免错误回退。分组源码不变，圆角不增加代理/投影/数据源 |
| 高度安全与验证 | 1.7-17 本身没有后续失败方案的高度递归 | 当前把高度策略限制为纯值函数，八个 Hook 的单次原调用和无查询/刷新有回归约束，降低未来重引入已知递归问题的风险；不能说 1.7-17 存在那条递归 |
| 原生细节覆盖 | 通讯录标题/索引/好友数量及资料卡背景存在遗漏，发现提示被通用公式覆盖 | 1.7-20～22 补齐独立元素；本轮保留这些修复并运行原回归 |

圆角路径/CAShapeLayer 缓存在 1.7-17 已存在，属于保留能力，不计为本次新增。当前补充了非法几何检查和 mask frame 复位修复。

## 性能结论的范围

可由源码和主机测试证明的变化：重复配置读取减少，原生 frame 偏移不累加，不必要的设置预览重绘减少，高度函数不查询行数，不主动建立第二套业务数据。当前仍分配页面上下文和部分发现元素临时对象，仍有目标识别及视图遍历；不能据此宣称总 CPU、内存或电量必然更低。

本轮没有真机 FPS、启动耗时、峰值内存或耗电对比，也不承诺“永不闪退”。安全收益来自职责边界和回归约束，性能收益目前仅是明确减少的重复操作。

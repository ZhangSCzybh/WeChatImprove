# 1.8-18 红包模块清理

以实际交付的 1.8-17 源码为基线，继续完成用户要求的红包代码清理。开始前已核对全部 326 个源码、配置及测试文件与上一版 source-manifest.json 一致。

## 本轮改动

- 删除红包设置页 15 处 `[defaults synchronize]`。`NSUserDefaults` 的写入立即更新进程内设置，由系统负责持久化，无需每次切换开关或修改选项时强制同步。原有 setBool/setInteger/setObject 调用、Darwin 通知、设置变更观察和自动回复开关的 reload 调用全部保留。
- 将仅在红包设置页使用的 14 个设置键常量从公共头文件移至实现文件；键名、字符串值、默认值及读写方式均不变，其他控制器无需再引入这些私有定义。
- 同步安装包、插件显示、更新说明和 README 的版本为 1.8-18。

## 检查结论与保留范围

红包 Hook、配置、设置及共用支付生产代码中未发现 NSLog、printf/fprintf、os_log、临时诊断开关或调试分支。旧的 CSReceiveRedEnvelopOperation、CSRedEnvelopParam、CSRedEnvelopParamQueue 和 CSRedEnvelopTaskManager 已在前面的修复中移除，本轮没有重复删除。

除红包设置页的 .h/.m 及版本说明之外，所有生产源码保持 1.8-17 原样。红包领取查询与提交、自动回复、通知、记录更新、金额与次数累计、他人专属红包排除、重复回包去重、账号和超时保护、详情页汇总均未修改。转账核心及账本也保持原样。异常捕获、兼容读取和有效的通知监听不作为无用代码删除。

测试断言及本地审计文件保留，均不参与插件编译、不进入安装包。

## 核心验证与交付

仅运行现有 `bash Tests/verify-payment-core.sh`：2,215 项基础断言、357 项生产桥接与 Hook 断言通过，原生回调保留。覆盖私聊/群聊、红包回复开关、成功记账、重复回包、手动领取观察、他人专属红包排除、串行/延迟/范围设置及转账核心流程。测试使用隔离的配置和临时账本，不读写真实微信数据。

Rootless arm64/arm64e 构建及交付核验结果见 verification.json；源码基线、改前快照、核心测试和构建日志保存在本目录。构建使用独立 Theos 目录，未执行 make clean，原 .theos 和旧安装包保留。

本轮没有安装到设备、发送微信消息或进行真实红包/转账操作。清理主要减少冗余设置保存操作和公共头文件暴露，不据此宣称明显降低 CPU 或发热。

# 原录屏的逐样本数值复核

本目录分析用户提供的两段**修复前录屏**。只保存脚本、数值 CSV／JSON 和源文件哈希，不保存录屏、头像、昵称、正文、原帧、裁剪或缩略图。它不包含修复后真机结果，也不能从屏幕像素推出生命周期、策略读取、cell 交付、重载或 UIKit 绘制次数。

`frame0` 是原视频按显示顺序解码的 0-based 样本号，`frame1=frame0+1`。时间以原始整数 PTS×time_base 计算，不用样本序号除以标称 30fps 代替。FFmpeg 输出使用 `-fps_mode passthrough`，未使用 fps filter，未复制、插入或补足所谓第 119 帧。

小程序视频 174 个相邻 PTS 间隔全为 20 ticks（33.333ms）。会话视频有 116 个 20 ticks 间隔，以及一个 **40 ticks** 间隔：frame0=100 的 PTS=2000（3.333333s），下一个 frame0=101 的 PTS=2040（3.400000s）。其时间戳间隔并非全程恒定；用户给出的 119 帧与文件实际 118 个样本不同。这个间隔位于所分析的 50–55 返回窗口之后，不改变该窗口编号。完整原始 PTS 对照见两个 `*-pts.json`；本目录同时提供两套帧号以避免偏一。

本次原样解码结果是首批可见内容 frame0=104，而非用户文字表中的 103。用户提供的完整 blank JPEG 与本解码 frame0=100 最接近，完整 shown JPEG 与 frame0=104 最接近；不能为凑齐文字表重排或补帧。frame0=104–113 是 10 个原始样本，至下一幅改变画面的 PTS 间隔为 **333.333ms**。只在持续到下一 PTS 的样本呈现解释下给出这个区间，不推断设备上更细的渲染时序。

数值证据：

- 空白上部 ROI 为 x=[25,560)、y=[220,650)，frame0=100–103 的 RGB 标准差为 0–0.0264，亮度<180 的像素比例为 0。它避开下方仍在离场的小程序覆盖层和红色触摸轨迹；因此结论仅是这块已露出的列表视区无业务内容，不能宣称整个屏幕每个像素都空白。
- 两处匿名区域对 frame0=104 的平均绝对 RGB 距离，在 104–113 分别为 0–1.272、0–0.294；frame0=114 突变为 **80.710、60.580**。这些是编码图像区域变化的证据，不包含名称或正文。
- x=[25,28)、y=[340,535) 的白色底板扫描最长连续段，在 104–113 大约为 y=445–521，114 变为 y=356–511；开始位置改变约 **89px**，与人工观察到的首组结构变化相符。这是图像扫描位置，不是 `contentOffset`、cell.frame 或滚动 API 写入值。

该视频可以证明修复前存在可读内容后续被移除的窗口和同时的结构变化；它不能证明小程序是否触发标准 appear 回调，不能给出策略发布次数，也不能证明两者在源码中的因果关系。

## 会话返回：区分遮挡、共同变暗与底板缺失

按实际画面定位顶部卡片：稳定态约 x=21..571、y=212..330。未套用旧录屏的卡片位置。返回时目的列表向右恢复，前景聊天页面仍遮住右半部分；只在人工确认已露出且避开边界阴影的左侧保守视区拟合，不统计视区外像素。

52–54 没有达到 RGB 255，**不能据此认定白卡底板漏绘**：卡内与卡下灰底仍保留 19／19／21 个亮度级的差值，二者共同由暗变亮，文字与底板在同一配准和亮度拟合下残差很小。按这些位移，卡片左侧外缘约为 -92／-52／-13px；右侧还被聊天页面遮挡，不能用未露出的圆角来认定卡片缺失。该数据支持转场横移／共同遮暗可以解释这段可见差异；**不能确认究竟是哪一 UIKit 层造成，也不能排除画面未捕获的内部重绘或更短的异常。**

55–98 共 44 个样本的最佳水平位移均为 0。相对于第 56 帧，固定顶部 ROI 的最大平均绝对 RGB 差为 **0.248166**，最小 RGB 完全相同像素比例约 **85.93%**。因此几何和文字位置稳定，但有少量压缩像素差异，不能将其写成原始 RGB 每个像素完全一致。稳定态结果也不能代替过渡期方法计数。

## 复现

当前主机已具备 NumPy／Pillow 的 Python 为 `/opt/homebrew/Caskroom/miniconda/base/bin/python`；默认 Python 未必有这两个库。脚本记录实际 Python、NumPy、Pillow、FFmpeg 和 ffprobe 版本以及脚本本身哈希。

```sh
/opt/homebrew/Caskroom/miniconda/base/bin/python -B \
  docs/audits/release-2.1-30-miniapp-return-and-top-flicker/frame-evidence/analyze-frames.py
```

输出为 `video-metadata.json`、`numeric-summary.json`、`miniapp-timeline.csv`、`chat-timeline.csv` 与两个 `*-pts.json`。CSV 数据单元只有数值或空值；未观察到／不适用的指标不填 0。源码不读取隐私名单或账户数据。

独立输出目录的第二次原样解码与分析已完成，以上六份数值文件全部逐字节相同，见 `reproducibility.json`。这只是同一工具链的可复现检查，不新增真机验收或修复验证结论。本目录文件校验见 `SHA256SUMS`。

可选 `--private-output /tmp/某个本次目录` 生成核对图；脚本拒绝将图像写在 checkout 内。图像只供本地检查，不随 GitHub 交付。没有运行微信、附加设备、改动数据库、设置、账号或生产构建。

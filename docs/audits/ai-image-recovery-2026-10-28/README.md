# AI 图片本地文件不完整时的一次下载恢复

用户反馈部分图片在「回复记录」中显示处理失败，没有点开过大图；随后提供的另一张新截图能正常回复。本次在原 `main` 工作区修复取图恢复，并为新失败记录增加固定的阶段说明。版本维持 `2.1-4`，独立修复候选包位于 `packages/2.1-4-image-recovery/`，原发布包保持原样。

## 已确认的问题与证据

三张用户附件在主机上通过生产 `CSAIImagePreparer` 的本地读取和 ImageIO 编码流程：

| 对照样本 | 输入字节 | 编码后字节 | 单次处理时间 |
| --- | ---: | ---: | ---: |
| 第一张失败样本 | 376,910 | 54,143 | 0.024 秒 |
| 第二张失败样本 | 682,007 | 221,030 | 0.018 秒 |
| 随后反馈成功的截图 | 8,299 | 8,474 | 0.024 秒 |

这些结果排除了附件副本直接触发当前尺寸、格式或编码限制的情况。剪贴板 PNG 副本不等同于手机微信当时的缓存文件，也没有调用真实模型，不能凭此确定设备端或服务端失败原因。附件未写入仓库或上传。

源码中可确定的缺陷：任一路径读到非空文件便标记为 `found`，即使解码失败也不再调用微信下载器。微信缓存文件仍不完整时，操作会直接失败。新增合成用例在旧逻辑下失败于等待原生下载启动的断言，修复后通过。

## 修改范围

- 所有候选路径都无法得到有效图片时，最多请求一次微信原生静默下载；匹配成功回调后重新读取。再次无效则失败，不循环下载或请求模型。
- 已完整本地图片保持直接编码路径。保留文件、像素、输出上限、串行后台处理、账号与消息身份、取消、超时和同会话串行规则。
- 图片准备与模型请求通过明确阶段区分，历史只保存固定本地提示。图片下载失败、超时、解码失败与网络、模型响应失败可分别识别；错误原文、图片路径、模型响应体和凭据不进入历史。
- 认证失效仅接受模型阶段的已知客户端错误域 401/403，防止图片或其他错误域的同码值撤销连接验证。
- 不增加定时任务、扫描或轮询，原约 30 秒后台同步和音频行为保持原逻辑。新增开销只发生在当前图片无法解码时的一次按需恢复。

## 安装与真机验收

按设备环境安装独立候选 [Rootless 包](../../../packages/2.1-4-image-recovery/com.wechat.improve_2.1-4_iphoneos-arm64.deb) 或 [Rootful 包](../../../packages/2.1-4-image-recovery/com.wechat.improve_2.1-4_iphoneos-arm.deb)。版本仍为 `2.1-4`，需要选择该目录的修复包；[SHA-256](../../../packages/2.1-4-image-recovery/SHA256SUMS.txt) 用于核对。

重启微信后，让对方将先前失败的图片作为新消息重新发送，先不点大图，检查能否自动回复；再验证一张此前成功的截图和普通文字。原有消息已进入持久去重账本，旧失败消息不会自动补发。若新消息仍失败，进入「人工智能 → 回复记录」，点击最新失败项查看固定阶段说明。图片链路依然受原私聊、群 @/免 @、开关及资格规则约束。

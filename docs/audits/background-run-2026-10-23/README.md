## 实现

`CSBackgroundRunManager` 统一管理公开 UIApplication／UIScene 生命周期、设置和音频事件，初始化会读取当前状态，重复通知不重复创建播放器。有前台场景时不启动后台音频。跨线程通知异步投递并合并配置刷新，避免让微信音频／服务线程等待主队列。

`CSBackgroundRunAudio` 生成并复用 256044 字节 WAV 数据（256000 字节 PCM，8 秒、16 kHz、单声道、16-bit），循环播放不依赖宿主音频文件，无周期检查、后台任务续期、网络心跳或轮询。返回前台／关闭时停止播放器；仅在会话仍由本模块持有时停用并恢复原 category、mode、options、route policy。

`BackgroundRun.xm` 观察 7 个公开音频会话方法。所有参数、返回值和错误沿用原生行为，异常仍透传；线程局部作用域排除自身／嵌套调用，原子代次使其他线程上的宿主修改立即使原配置归属失效。宿主接管后只停止本模块播放器，不恢复或停用宿主的新音频会话。只有明确的原生停用事件才能在当前后台周期再次尝试；不把一次 category 修改当成释放。

系统中断开始停止播放器；收到配对的结束事件且允许恢复时再尝试，拒绝恢复则等待下次前后台周期。过期／未配对结束事件被忽略。音频服务丢失／重置也由事件处理。播放失败或路由导致的停播不无限重启；自身产生的路由通知不会覆盖真实启动错误。没有修改输入设备、采样缓冲偏好、微信前台状态或私有进程权限。

设置页保留原 defaults suite `com.cyansmoke.wechattweak` 和 `BackgroundRunEnabled`，移除无效的间隔输入；原 `BackgroundInterval` 数据及备份登记保留，不参与调度。展示当前状态、上次后台结果及安装包后台音频声明。结果仅进程内保存，不新增周期写盘或诊断日志。

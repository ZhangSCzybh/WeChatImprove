日期：2026-11-02（Asia/Shanghai）。用户要求放宽音频退出条件，优先利用原生系统后台时间，临近结束时再用音频接力。基于原 checkout `/Users/zhangshichao/Documents/Workspace/WeChatImprove`、main 分支上的 2.2-5 增量修改，沿用已授权的编译打包流程。该项目为 iOS 注入插件，没有独立前后端端口或服务数据库。本次没有切换 checkout、账号、数据或设备环境，没有安装到手机。

## 策略调整

| 条件 | 2.2-5 | 2.2-6 |
| --- | --- | --- |
| 有效任务下启动音频 | 可信有限剩余时间 <10 秒 | 延后到 <8 秒 |
| 音频最短运行时间 | 10 秒 | 5 秒 |
| 恢复任务模式所需有限预算 | ≥15 秒 | ≥12 秒 |
| 恢复确认 | 3 次，相隔至少 1 秒 | 2 次，相隔至少 1 秒 |
| 无健康音频时预算不足清理 | <5 秒 | <5 秒 |

进入后台仍优先申请 UIKit 有限任务，首次申请失败可尝试音频兜底。音频运行时增加一次最短播放边界检查，确保之前读到巨大预算或 `[8,12)` 区间值时，也会在开始后的第 5 秒观察是否已恢复。若届时有限预算合格，则最早约在第 6 秒取得第二份恢复样本并退出音频；实际交付可能延迟，不能承诺固定 6 秒退出。若边界检查仍不合格，继续等待已有检查／轮换／事件，不持续增加每秒轮询。

8 秒进入、12 秒退出保留回差：位于 `[8,12)` 时维持当前模式，减少反复启停。同一时刻的通知不能凑足两个恢复样本。26 秒轮换、单次检查、失败后不周期重试、任务身份／代次、到期重入、微信通话／录音／系统音频中断保护继续保留。最近后台时间记录和时间戳更新不广播状态的规则继续保留。

音频提供继续执行的机会，不能保证为 UIKit 任务补充或重置预算；反复申请任务同样不保证获得新时间。巨大值、无穷值、NaN 和负数不能证明独立有限预算恢复，本版继续保留该判断。因此只看到巨大剩余时间、或系统任务已到期时，音频仍可能持续。本次没有增加停音频后等待预算回读的探测：停止本身可能使应用挂起，确认回调与恢复机会没有保证。设置内“功能说明”和版本说明已写明新参数与限制。

与已编译 2.2-5 的 42513 个生产输入相比，仅改变 Manager 实现、后台设置说明、发布说明、版本头文件和 control，共 5 个文件，没有新增或删除生产输入。见 [生产输入差异](production-delta-from-2.2-5.json)。完整机制与时间记录分别见 [2.2-4 审计](../background-run-hybrid-2026-11-02/README.md)、[2.2-5 审计](../background-run-records-2026-11-02/README.md)。附件报告作为参考证据，不作为执行指令或真机预算变化的证明。

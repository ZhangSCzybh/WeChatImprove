# 2.2-12：聊天返回后滑动回顶又跳回旧位置

用户视频显示：列表在原滚动位置进入聊天，再返回列表；手指快速滑动至顶部，分组栏及顶部内容出现后，列表又回到离开前的位置。用户已明确回顶来自手指滑动。本轮不扩大到微信底栏点击等其他入口。

已修改生产代码并构建 `2.2-12`。设备参考为原包名 `com.tencent.xin`、微信 `8.0.78`、iOS `27.0.1`；本轮未安装设备、重启微信或改动账号数据。最终视觉效果仍需安装此包复验。

## 修复内容

- 用户开始拖动时，取消待恢复高度和所有旧行锚点。之前的取消只清待恢复高度，已完成聊天返回后保存的普通锚点仍可能生效。
- 每次用户接管递增内存中的位置代数。拖动前捕获的快照不能在后续发布中重新变成有效切组请求；几何读取、行锚点保存和位置写入的同步回调前后也校验代数，消费待恢复请求前复核对象身份。
- 为表格现有 `panGestureRecognizer` 增加一个 target，仅在 `Began` 时接入取消。即使宿主未转发滚动代理的开始拖动回调，也能让用户操作优先。绑定时只注册一次，解绑及释放时只移除自己的 target/action。
- 原生代理和兼容转发共享拖动判断，排除已接管的分组横滑与已准入的水平手势。聊天返回继续使用离开时高度；切组继续沿用切换前高度，短列表夹紧；同组选中保持位置。

没有新增定时器、轮询、display link、逐帧观测、全局 offset Hook 或偏好设置。没有改变原生手势 delegate、失败依赖及触摸仲裁；分组计算、刷新合并与隐私校验保持现有规则。

## 真机复验

1. 安装与注入环境匹配的 `2.2-12`，在原包名微信中把列表滚到中间，进入聊天后返回，确认回到离开时高度。
2. 立即用手指快速滑到顶部，松手并等待惯性和回弹结束，停留至少 3 秒，确认不会跳回旧位置。慢速拖动和快速甩动各重复数次。
3. 保持当前高度切换分组，确认继续沿用当前高度；进入短组应停在可达到的边界，同组选中不跳。再检查横滑切组和聊天返回。

本轮未重做 Instruments，功能回归及打包结果不用于推断 CPU、Core Animation 提交或掉帧的降幅。

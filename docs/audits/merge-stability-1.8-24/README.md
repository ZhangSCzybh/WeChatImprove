# 1.8-24 合并气泡间距与滚动稳定性

在既有 checkout `/Users/zhangshichao/Documents/Workspace/WeChatImprove` 修复 1.8-23 的两项用户反馈：私聊首条与第二条合并气泡间距偏大、滑动历史时气泡间距改变。沿用 Rootless、arm64/arm64e、iOS 15 最低编译目标；没有更换工程、安装设备、访问数据库或重启服务。

## 根因与修复

1. **普通短文本首条多留了头像预算。** 8.0.78 预设仍以 44pt 头像占用计算首条，已有设备布局记录及对应回归使用 38pt 普通正文/头像。因此 55pt 原生行首条被压到 53pt，与第二条之间留下 8pt；后续接缝为 2pt。本版将这个明确版本范围内的头像预设校准为 38pt，首条规划为 47pt，同一回归中的所有组内接缝均为 2pt。实际头像、昵称及其他子视图仍参与防裁切校验。这是范围明确的预设校准，不能声称彻底消除了几何假设。
2. **首次测量和渲染使用了不同结果。** 1.8-23 在 render 中保存新边界、清除 measurementDecided，后续原生查询便采用新高度；同时渲染使用实际采样的 originDelta，而表格可能仍使用预设高度。即使没有主动请求收紧刷新，原生重测本身也会改变间距。本版在测量时一并确定高度与 originDelta，渲染只使用这份结果，真实边界不再参与滚动中的重新压缩。
3. **原生缓存失效会暂时丢掉位移。** resetLayoutCache 与相同尺寸的历史布局 epoch 不再直接清空已提交的位移，也不因 epoch 单独请求表格更新。下一次原生行高请求仍检查正文尺寸、行高、宽度、显示比例、昵称和辅助内容标记，真实变化才重新计算。邻接关系、配置、身份变化继续正常失效。
4. **安全回退不再来回切换。** 真实内容无法放入已规划空间时恢复原生高度。同样的几何输入即使反复复用或清缓存也保持回退，不再因旧预设重新生效而反复压缩。真实尺寸、辅助内容等输入变化仍可重新校验。

未知微信版本、非普通文本没有可在 Cell 显示前确定的紧密预设，本版保持原生间距；不再将一次可见测量转换为后续的紧密高度。透明图片边距继续复用气泡缓存做包含范围校验，但不会改变已经确定的行高或位移。普通文本的 2pt 是标准布局目标，不是对透明素材、较大头像、群昵称、头像下时间或所有字号的像素承诺。

本次没有新增离屏探测 Cell、邻居测量、定时器、逐帧处理或全表扫描。生产代码仅修改合并适配器；气泡绘制、手势和时间模块保持原实现。

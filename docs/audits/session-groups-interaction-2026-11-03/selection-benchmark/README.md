# 切组模型主机对照

这组证据直接编译冻结的 2.2-8 与本轮生产 `CSGroupNativeModel`、`CSGroupProjection`、`WESessionTabItem` 源码，以相同复制会话输入比较切组模型。没有连接或修改手机，也没有使用重写后的模型模拟生产算法。

工作负载为 1200 条普通会话、1 条折叠入口、100 条已复制折叠子会话、24 个自定义组，开启去重，包含隐藏身份与置顶分区。每种工作负载每轮 120 次切组，共 5 轮。同作用域组间切换复用成员关系和角标；跨“全部”切换会从复制值重新构建作用域投影。每轮计时之外，逐个比较全部 28 个目的组的原生数组名称及顺序、置顶数量、成员数、角标、映射行和折叠展示元数据。

`rerun-final/` 是补齐六个异常折叠展示字段比较后的最终源码结果，before/after 文件记录生产源码 SHA256，并核对单次运行期间源码没有变化。

| 受控输入工作负载 | 2.2-8 模型中位数 | 本轮模型中位数 | 2.2-8 每轮主源元数据读取 | 本轮每轮主源元数据读取 |
| --- | ---: | ---: | ---: | ---: |
| 过滤组之间切换 | 6.223 ms/次 | 0.328 ms/次 | 144120 | 0 |
| 往返“全部”作用域 | 8.097 ms/次 | 2.010 ms/次 | 144120 | 0 |

五轮的元数据读取数量一致，全部目的组指纹一致。`0` 指初始化完成后每次切组在原生模型内部没有再次调用主源 `rowProvider`。实际协调器仍会重新读取折叠源并验证源身份，完整链路中的 O(N) 身份/槽位验证继续保留。

计时仅为 macOS 主机上的模型/投影墙钟时间，未包含原生来源捕获、折叠来源读取、协调器、UIKit 发布和真机 Instruments。桌面系统及其他进程没有完全隔离；最终轮开始没有匹配的构建进程，结束发现两条 clang 进程，其中一条报告 53.2% CPU，因此时延应视为主机工作负载证据，不能换算 iPhone 整体 CPU、能耗或帧率提升。具体进程快照见 `rerun-final/host-execution-context.json`。

根目录保留最初与完整构建并发的记录；`rerun-isolated/` 保留构建结束后的一轮记录，其前后均没有匹配构建进程，但它对应严格六字段补充前的源码。不得将这两轮的源码哈希或时延混为最终轮。

重现最终对照：

```sh

```

# 微信原生名单选择器与空底栏图片备份 · 1.8-53

基于 1.8-52（`bf60225a`），处理密友名单、密友群聊、红包白名单群／黑名单群的原生选择器，以及未设置底栏图片时的备份失败。

## 实现

- 密友好友使用微信 `MultiSelectContactsViewController`，三个群聊入口使用 `GroupSelectContactsViewController`，由微信 `MMUINavigationController` 承载。列表、搜索、联系人头像和勾选均使用微信实现。
- 新增一个设置选择适配层，只为插件创建原生控制器的子类，接入完成／取消及空名单保存；不替换微信全局选择器方法。
- 群聊选择器的原生 `initData` 会重新创建已选字典，预选在该步骤之后回填。好友完成操作读取原生 `ContactSelectView` 当前结果，避免保存成最初传入的名单，遗漏搜索／标签选择或撤选。
- 完成后先关闭选择器，再写入对应设置；取消和延迟重复回调不写入。账号变化、密友授权过期会拒绝写入，授权失效通知会关闭密友选择器。无法解析的既有用户名保留，避免因临时联系人缓存缺失丢失已有配置。
- 原生接口存在且签名符合后才打开；接口不匹配时显示失败原因，保留名单。

## 备份原因与修复

完全不存在的底栏图片设置原本可以备份。报错分支要求配置中仍有非空图片路径，因此用户看到原生图标、认为没有设置图片时，可能仍残留已经失效的旧路径。当前无法读取手机偏好文件，不能判定残留由哪次历史操作产生。

底栏读取不到已删除图片时会使用微信原生图标，而备份之前把这个路径当作必须读取的资源，导致整个备份失败。本版仅对已登记的底栏图片字段，在没有路径或文件确实不存在（`lstat` 为 `ENOENT`）时，输出未设置字段，允许备份和导出。备份不会修改当前偏好或删除文件。

有效图片仍保存全部字节；现存但损坏、空文件、非法目录或符号链接仍按原规则拦截。其他模块的缺失资源规则保持原有语义。重置预览仍保留缺失路径记录，供显示差异、失效检查及回滚保护。

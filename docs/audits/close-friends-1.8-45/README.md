# 密友 1.8-45：挂断回复与搜索输入保护

基于 `codex/close-friends` 的 `ac0bd9f0`，交付 Rootless `arm64 + arm64e`，最低编译目标 iOS 15.0。沿用 `/Users/zhangshichao/Documents/Workspace/WeChatImprove` 工程，没有安装到手机、发送真实消息或修改微信数据；原有 deb 保留并校验哈希。

## 本次修复

1. **挂断回复没有发送的确定原因**：当前微信 `CMessageWrap.initWithMsgType:` 的参数是 64 位 `long long`，原来的签名守卫误按 32 位 `unsigned int` 检查，导致所有回复在创建消息前返回。现改为实际 ABI，并用明确的 initializer 声明保证 ARC 所有权正确。详细依据见 [原生发送链路](reply-native/README.md)。
2. **拒接后的发送与兜底**：拒接请求提交后，把账号、来电人、通话身份和回复文案复制到独立任务，退出拒接调用栈后发送，不再依赖会被销毁的通话对象。发送服务短暂不可用时有限重试；首次进入原生发送后不再新增消息。收到成功／失败回调或轮询时，重新核对数据库里的原消息，确认失败且尚无服务端 ID 后，最多两次加入微信原生发送队列，保留原 localID 和创建时间。成功即停止；状态不明交给原生发送队列，避免重复回复。明确失败最终保留原消息供临时解锁后手动重试。每次尝试核验账号和当前开关，保留每通电话去重、同一人 5 分钟限频。
3. **搜索输入过程中不泄露前缀**：凭现有 PBKDF2 校验值无法识别未输入完整的密码前缀，因此密友开启时统一暂停首页输入过程的联想／建议／匹配，普通内容按键盘“搜索”后执行原生查询。完整密码仍自动解锁、清空实际输入控件并停止加载。密码与前缀不写入搜索历史；不增加明文密码或较弱的前缀校验值。中文组合输入保留，兼容大输入框、旧输入框、粘贴和语音回填。详细依据见 [原生搜索链路](search-native/README.md)。

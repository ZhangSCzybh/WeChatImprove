## 设置中如何查看

进入插件的 **后台运行设置 → 最近一次后台**。返回前台时，“当前状态”仍正确显示“前台待机”，最近一次后台记录保留供查看：

| 字段 | 含义 |
| --- | --- |
| 最后状态 | 最近一次后台的状态结果 |
| 进入后台／开始观察 | 真正收到前后台转换时记录进入时间；若在后台中途开启或初始化，则只记录开始观察时间 |
| 最后检查、检查时状态 | 最近一次有效后台检查的设备日期和当时状态；相同状态的有效检查仍推进记录 |
| 返回前台 | 本轮第一次返回前台的时间；重复生命周期通知不覆盖 |
| 停止时间、停止原因 | 已观察到的本轮停止事件；已有到期或关闭原因不会被随后返回前台覆盖 |
| 检查至返回间隔 | 最后有效检查到返回前台的单调时间差；未知时显示“尚无法计算” |

列表显示 `MM-dd HH:mm:ss`，点击任意记录行可查看包含年份的完整记录。时间按设备本地时区显示，重复打开设置不会刷新“最后检查”。每次新的后台进入会替换上一轮记录；同一次后台停留中关闭后再开启保留原进入时间，并重新开始尝试。

记录仅保留当前微信进程中的最近一次，进程结束或重新启动后清空。最后检查证明相应时点执行过检查；检查至返回间隔不能用来精确判断系统挂起时刻，也不是连续运行时长。

## 实现范围

Manager 增加进程内日期、检查状态、停止原因和经过时间字段。Runtime 新增可注入 `currentDate` 供展示日期使用，`uptime` 继续负责调度与经过时间，修改系统时间不影响诊断间隔。旧回调继续受任务身份与代次约束。普通设置刷新、重复生命周期通知和返回后的刷新不推进检查记录；有效后台周期内音频事件触发实际评估时算检查，结束周期后的无关通知不推进。

仅时间戳更新时不广播状态变化，避免同状态检查额外触发 AI 配置刷新；状态和执行能力变化仍通知，设置在返回前台、重新显示时读取最新记录。没有增加记录专用定时器、磁盘持久化或 defaults 键。

与已编译 2.2-4 的 42513 个生产输入相比，本版仅改变 Manager 头文件／实现、Runtime 头文件／实现、设置控制器、发布说明、版本头文件与 control，共 8 个文件，没有新增或删除生产输入。见 [生产输入差异](production-delta-from-2.2-4.json)。原后台任务优先、按需音频、AI 资格与通话／录音保护继续包含在本包中，机制与上轮验证见 [2.2-4 审计](../background-run-hybrid-2026-11-02/README.md)。

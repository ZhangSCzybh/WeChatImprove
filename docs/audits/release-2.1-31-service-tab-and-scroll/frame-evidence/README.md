frame0 61–63 仍含横向返回遮挡；64–66 列表完整露出但两行缺失，67 首次恢复。完整露出后到恢复约 100ms；连同滑入期间，缺失可见窗口更长。用户表格的 70 首次恢复与此输入原始解码帧号不符，故保留两套从零／从一编号及 PTS，不重新标号来迎合判断。

聚合背板 ROI 为 x=280..519、y=450..619；64–66 的每个 RGB 值均为 234，白色占比为 0。蓝色检测 ROI 为 x=40..549、y=450..619：此段为 0 像素，67 帧恢复为 4463。它们支持“两行内容和白色底板一起消失”的现象。

但下方图标并未跟随背板顶边上移 177px：64–66 的绿色像素质心 y=668.6922，67 为668.6661，差约0.0262px（阈值／编码造成的小差异）。x=110..549、y=637..699 的下方文本 ROI 与80帧的平均绝对RGB差在64–66均为0.024398749。白色顶边625→448主要来自上方两个 cell 重新显示，**不能据此认定下方行真实 y 或 contentOffset 发生了相同位移**。

`service-timeline.csv` 记录全部120帧的匿名触点红色像素数与质心；64–66的标记与下方内容同时可见，红色标记存在而内容位置几乎不动。录屏无法判断触点是否真正交给 UITableView、table.contentSize、contentInset、contentOffset、手势 enabled 或 hit-test 链路，这些必须与主机替身数据／后续真机运行数据区分。

# 1.8-21 红包与转账通知

用户确认采用“领取结果 → 到账金额 → 联系人／群聊 → 时间”的通知设计，并要求红包增加总额。此处总额指本次红包的整个红包金额，不是本人的历史累计领取金额。

## 基线与范围

实际工作目录已更新到 1.8-20，Git 基线为 bbb2fca2a65f8072723477f11355d24f46fc3f98。开始前保存了 328 个源码／配置／测试文件的哈希及快照，保留当前胶囊背景颜色、分组设置和此前支付修复。没有使用旧的 1.8-18 快照覆盖当前工作目录。

生产逻辑只修改 Controllers/CSPaymentAutomation.m，另更新现有支付桥接测试、版本和说明。账本格式、统计金额、成功判定、支付提交、账号保护、他人专属红包排除、通知目标和自动回复开关保持原流程。

## 通知示例

```text
🧧 红包已领取
到账金额：¥8.88
红包总额：¥100.00

来自：李四
群聊：周末聚餐群
时间：10-19 14:32:08
```

```text
💰 转账已收款
到账金额：¥520.00

来自：张三
会话：私聊
时间：10-19 14:40:05
```

- 人民币以 ¥ 和两位小数展示，其他币种保留原币种。金额采用整数分格式化，避免浮点精度损失。
- 红包总额只读取成功领取回包的 totalAmount，必须是可解析的正整数且不小于本次金额；缺失、溢出、负数、小数或小于本次金额时显示“未提供”。总额不参与记账，也不会阻断已确认的领取结果。
- 联系人优先使用本地备注，其次昵称；群聊显示本地群名称。红包保留来源消息的发送者身份，成功回包的 sendUserName 与已知来源一致或来源缺失时可补充发送人，并以 sendNick 作为本地名称缺失时的后备。身份冲突时不借用冲突的昵称。发送人不明时省略“来自”行；联系人和群名读取失败时显示明确后备文字，不直接暴露内部会话 ID。
- 名称统一为单行，移除控制字符／换行影响，长名称按完整字符边界截断。确认成功时捕获日期，格式器复用但每次使用当前默认时区，支持进程内时区变更。
- 只有实际成功、账本落盘、去重完成且通知开关有效后才读取名称和生成通知。每个身份至多尝试缓存和普通本地读取各一次；不遍历联系人，不增加支付请求、详情查询、重试或后台轮询。

## 原生字段依据

目标为本任务此前使用的微信 8.0.78 未加密 arm64 文件 `/tmp/wechat-8.0.78-inset-analysis/WeChat`，SHA256 为 `0b3cd1e2ed1da493a6fe12c9ef6e9b9421c95bcac63417c677f309536f7c1c8e`。

使用 reverse-engineer-anything 技能核对：REA open_binary 成功绑定该文件；全量 Ghidra 分析耗时较长，未取得其指令结果，已终止本轮专用临时分析并 close_binary 成功。改用本项目已有 Mach-O 元数据读取方法和 llvm-objdump 的有界静态反汇编，证据保存在 native/，未执行微信程序。

- WCRedEnvelopesReceiveControlLogic 的 OnOpenRedEnvelopesRequest:Error: 在 0x109cb9c84 调用 OnContinueOpenRedEnvelopesRequest:。
- OnContinueOpenRedEnvelopesRequest: 在 0x109cba6b8 读取 totalAmount，在 0x109cba6e8 调用 setM_lTotalAmount:；同方法分别读取 amount、recAmount，表明总额独立于本次领取和累计已领金额。
- 同方法在 0x109cba3fc 读取 sendNick，在 0x109cba474 读取 sendUserName。项目现有详情汇总按 m_lTotalAmount / 100 显示元。
- 这证明字段映射，不能保证每种红包／微信版本都返回这些可选字段，因此实现保留缺省处理。

## 验证

只运行 `bash Tests/verify-payment-core.sh`。2,215 项基础断言、528 项生产桥接与 Hook 断言通过；原生回调保留。新增验证覆盖红包／转账、私聊／群聊、通知关闭／自己／文件助手、自动回复开关、正常与缺省／错误总额、重复回包不重发／不重复查名、手动领取、他人专属红包、备注优先、名称缺失和异常、换行及长名称、整数金额和时区变更。

首次新增时区变更检查揭示了复用 localTimeZone 代理导致格式器仍沿用旧偏移的问题；已改为每次设置当前 defaultTimeZone，修正后的全部核心测试通过。失败记录保留在 regression-before.log，最终结果见 core-tests.log。

Rootless arm64/arm64e 构建、包内 dylib 与 staged/built 文件一致性、dSYM UUID、旧产物哈希及源码范围核验见 verification.json。独立 Theos 目录构建，不运行 make clean。测试使用临时配置域和账本，不接触真实微信账号、交易或历史记录。本轮没有安装到真机或发送真实微信消息。

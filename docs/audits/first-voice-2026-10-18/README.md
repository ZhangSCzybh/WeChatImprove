# 1.8-11 首条语音准备修正

用户确认上一轮语音功能恢复，但私聊、群聊第一条语音仍提示“语音读取或校验失败”，同一条反复操作仍失败，换第二条正常；自己发送和收到的语音都受影响。本轮继续使用 `/Users/zhangshichao/Documents/Workspace/WeChatImprove`，保留此前界面和性能改动，只修改语音准备与最终失败反馈，并运行语音核心回归。

已确认的代码缺口：1.8-10 在普通操作开始时只使用聊天界面持有的 `sourceWrap`；原生 `GetMsg:LocalID:` 刷新只发生在下载完成回调。如果该界面对象持续保留旧时长、下载状态、结束标志或空缓存，用户对同一条语音重复操作仍然使用同一份旧信息。没有下载回调的已完成语音无法从原生记录恢复。读取路径的旧快照也没有在重新获取时清空。

主机用例保留一个始终不更新的界面消息对象，同时提供同一账号、会话、LocalID、ServerID 的完整原生记录，在旧代码上复现失败，见 [修改前失败记录](first-voice-before-fix.log)。**这证明刷新缺口及修正效果，没有取得用户手机失败语音的真实字段和音频字节，不能认定设备上只有这一种原因。** 本次没有放宽 1.8-10 的完整性、格式或时长规则。

本轮实现：

- 语音处于未完成、疑似录制或显式未结束状态时，先获取同一条原生消息记录，重新检查状态，再决定是否需要原生下载或拒绝。已通过准备的常规语音不增加这次查询。
- 本地读取或校验失败时，最多增加一次 200ms 后的准备重试。此前未获取过原生记录时，在该次恢复中获取；已经获取过则更新它的字段快照。延迟是一次性准备任务，不是轮询，不会重新执行上传或发送。
- 重新加载时清空旧路径，拒绝类型、会话、发送方／接收方、LocalID、已有 ServerID 不匹配的记录。会话及账号使用操作建立时捕获的值，避免可变原消息对象改变后放宽校验。
- 重试期间共享同一来源的准备任务；取消、账号边界取消、消息记录不匹配后不再继续。已经尝试读取本地完成语音的操作，不因刷新后的状态变化而调用可能覆盖原文件的下载入口。
- 最终失败反馈细分文件未就绪、信息不完整、数据不完整、格式无法识别、时长不一致等原因。只在本次操作最终失败时显示，不输出日常日志，不记录原语音内容、路径或联系人。

生产变更集中在 [CSMessageMediaProvider.m](../../../Controllers/CSMessageMediaProvider.m)、其失败回调声明与 [CSMessageActionCoordinator.m](../../../Controllers/CSMessageActionCoordinator.m)。原生发送适配器、发送去重、头像、输入框、分组、触摸轨迹、底栏等模块的源码保持 1.8-10 交付状态。相对本轮开始的完整范围见 [change-scope.json](change-scope.json)、[独立差异](implementation-only.diff)。

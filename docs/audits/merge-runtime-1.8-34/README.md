# 1.8-34 紧密间距与快速滑动崩溃修复

本轮针对 1.8-33 的两项反馈：合并消息间距仍偏大；快速滑动历史消息时闪退。目标是标准合并接缝保持 **2pt 逻辑点**，首次发布的行高与内容位移稳定，不在停止滚动后再次收紧。沿用现有气泡样式、背景/字体颜色、通话背景、引用内容与合并规则。

## 三处具体问题

### 1. 布局线程直接持有原生解码缓存结果时崩溃

此次崩溃的 dylib UUID 为 `CCAEA0DD-B19B-30D8-B179-42B6F6F8BEDF`，与交付的 1.8-33 arm64e 一致。加载基址 `0x126b28000`，首个插件帧偏移 `0x4dc9c`，由对应 dSYM 定位到 `CSDecodedImage` 的 `CSBubbleStyleAdapter.m:131`；上层偏移 `0x4ee44` 为 `CSBubbleStyleApply`。主线程在 `objc_retain` 访问 `0x400000000000bad0`，并非此前日志的空指针加偏移。

该指令位于 `object_getIvar` 读取第一个原生图片解码槽后 ARC 持有结果的位置。明/暗主题分别可能为 `_decodeImageLM` / `_decodeImageDM`，日志不足以确定当时主题。原生缓存访问器是 nonatomic，而解码工作线程会更新缓存；直接读出再 retain 不是一个受原生同步保护的操作。证据见 [符号化结果](crash-symbolication.json)、[崩溃点反汇编](crash-CSDecodedImage-arm64e.asm) 和 [原生访问器](native/crash/YYImage-cache-accessors.asm)。

生产适配器已移除这些解码槽以及原始图片槽的直接读取，也不调用延迟解码 getter。标准 8.0.78 消息首先使用已验证签名的 `BubbleInfo` 缓存 UIImage 模板；不能取得模型模板时，仅观察原生显示任务内部已经返回的 `YYImage.decodeImage` 结果。任务局部的线程存储只捕获当前普通/按压图片，持有返回对象后转主线程发布自有快照。回调验证取消状态、Cell/模型/背景绑定、图片身份、设置代次和主题，避免旧结果污染复用消息。快照按明暗主题分别保存，不跨主题借用。

旧代码注入失效缓存槽后的隔离复现触发 SIGSEGV，见 [修复前崩溃复现](crash-reproduction-before-fix.log)。新代码同一断言安全返回“无快照”。这是对失效槽读取的确定性复现，不是完整设备并发调度重放。

### 2. 把原生 38pt 固定区域当作自定义气泡最低高度

1.8-33 仅放宽到目标高度等于上/下固定区域之和 38pt。原生语音高度实际由 `2 * text_message_margin_top + ceil(systemFont.lineHeight)` 计算，没有 38pt 的最低限制。截图中七个短文本/语音可见填充高度为 111px，在 3× 分辨率下是 37pt；相邻起点差 162px，空白接缝 51px，即 17pt。

截图只能证明可见填充高度，不能直接读出原始 UIView frame 或模型高度。因此本轮同时使用原生尺寸算法和模型资格断言，补齐 37pt 场景。旧代码在该断言失败，见 [短气泡修复前记录](short-body-before-fix.log)。

现在自定义模板根据实际目标尺寸重新拟合圆角与固定区域，再验证新模板能否容纳；不再要求原生 30pt + 8pt 的固定区域完整装入。模型边距与初次外观使用同一原生模板来源。原生样式在垂直透明边距为零时允许更短高度；存在不能可靠映射的透明边距时继续稳定回退。2pt 常量不除以屏幕倍率。

### 3. 头像与气泡不在同一父视图

8.0.78 将头像直接添加到 Cell，而文本/语音背景在 `m_contentView` 内。原代码要求二者同父级，导致标准头像无法走独立横向区域的放置逻辑，被算入接缝并触发安全扩展。此前联合替身把二者放到相同容器，遗漏了真实层级。

现在只接受已确认的 Cell/一级内容容器，将头像和气泡统一转换到 Cell 坐标后比较横向区域。真实相交、未知父级、变换、超出标准头像尺寸或容不下头像时仍走安全路径。新回归使用带偏移的真实层级，并验证人为制造的真实相交仍稳定扩展。修复前失败、修复后通过记录分别为 `agent-spacing-before.log` 和 `agent-spacing-after.log`。

## 稳定性与开销

- 合并布局继续复用首次确定的行高/位移，不因图片就绪、按压态就绪或停止滚动缩小已发布结果。确实超出的内容仍允许安全扩展，避免裁切。
- 标准组内文本、语音、引用消息边界按 2pt 验证。引用框内部间隔仍保留原生布局；群昵称、头像下时间等真实附加内容保留必要占用，不把它们当作空白压掉。
- 无新增定时器、轮询或递归视图扫描；沿用有界图像和边距缓存。新增模板查询按绑定身份/尺寸/主题/设置缓存，稳定重复布局不再查询。
- 联合三消息夹具首次测量查询普通/按压模板共 6 次；开启样式后三个初始绑定再查询 6 次，此后重复布局不增长。模板查询使用原生 `useCache:YES`。
- 对没有模型模板、且启用样式前已经完成原生显示的背景，最多请求一次原生显示来获得快照；相同未就绪状态不会每次布局重试。
- 全局 `decodeImage` 钩子只转发原始调用并观察返回值。非目标显示任务的观察入口只检查线程局部指针后立即返回，不建立全局图片索引。

# 2.0-13：表情静默、入口调整与定时任务配置备份

日期：2026-10-26。基于现有工作目录继续开发，没有清理、替换工作目录，也没有提交或推送本轮修改。该版本同时交付本轮连续提出的三个要求。

## 改动与原因

### 图片添加到表情全程只使用微信原生提示

用户的 `IMG_7500.PNG` 显示，微信原生“正在添加”之外仍叠加插件黑色横条。上版只移除了插件的成功提示，进度、失败和重复操作仍会通过适配器反馈。

- 删除 `CSMessageImageStickerAdapter.feedback` 及 coordinator 的绑定。
- 加载、添加、重复请求、并发上限、格式不支持、原生失败、容量超限、超时及取消均只清理操作，不再发插件提示。
- `CSMessageActionAddSticker` 的失效入口也不走公共“操作已失效”提示，其他消息功能继续保留原有反馈。
- 原生单项、批量、待上传和超限回调继续解除委托、观察者及活动操作。只为插件提示服务的额外表情库查询已移除。

先修改测试再运行原实现，`before-fix.log` 中的 `feedback.count==0` 断言失败，证明原实现仍产生插件提示。修复后对应专项通过 190 条检查。

### 首页入口及名称

`CSCustomViewController` 的“定时任务”和“表情功能”入口不再显示右侧箭头；点击路由保留。“图片添加到表情”入口和二级页面标题改为“表情功能”，内部功能开关仍为“图片添加到表情”，继续使用原配置键，升级不重置状态。

### 定时任务真正进入配置备份

缺失原因：任务写在独立账号文件中，原备份引擎只读取三个已登记的偏好域。任务没有被读取、登记或写入 `.wcbak`。旧设置页也明确写着“不包含任务和执行记录”。

`Tests/ScheduledTaskBackupTests.m` 先在临时 `Library/Preferences/WeChatImprove` 建立真实任务库，在调度器持有独占锁时调用备份引擎；原实现生成的快照没有任务字段，见 `scheduled-backup-before-fix.log`。修复后同一入口和完整恢复流程通过。

实现要点：

- 登记文件字段 `scheduled/<原账号>`，模块名为“定时任务”。它不映射到微信 `NSUserDefaults`。任务管理器和备份引擎共用 `CSScheduledTaskFileURL`，沿用 `ScheduledTasks/<账号 SHA-256>.plist`，没有目录迁移或另一份配置副本。
- 捕获当前账号的任务名称、目标会话、文字、单项开关、补发选项、时区、起始时间及单次/分钟/小时/天/周规则。主开关原值保存在备份内，正常恢复时强制关闭。
- 读取为无副作用的普通文件读取，不取得调度器的独占写锁、不创建空任务文件，也不把 `submitting` 改成 `unknown`。大小限制为 4 MiB，校验失败报告错误并保留原件。
- 导出的定义不含执行记录、`nextRun` 或 `lastOccurrence`。恢复预览要求“原账号 = 当前账号 = 已选择账号”，允许原账号换设备，不把其他账号任务迁入当前账号。
- 正常恢复生成暂停状态，清空执行记录及待执行状态。用户显式开启后由原有规则从下一个未来时刻重新计算；过期单次任务停用，不补发关闭期间积压。
- 继续使用既有保护备份、prepared/applying/committed 日志、启动门禁及回读校验。日志的 before 部分保留完整本机任务状态，供失败或进程中断后精确回滚。任务写入使用独占锁、原子替换、0600 权限、原有 iOS 文件保护等级和文件/目录 fsync。
- 恢复日志中的账号决定回滚目标；即使重启后当前账号改变，也不会把原任务回滚到另一账号。
- 选中任务恢复时，执行状态摘要参与计划校验；准备后又发生执行则拒绝旧计划，避免重置本机去重状态。未选择任务模块时，单纯执行记录变化不阻止其他模块恢复。
- 旧备份缺少该字段，或未选中任务模块时，现有任务文件保持不变。重置选择“定时任务”时只清除原所属当前账号的任务库和记录，其他账号保留。
- 任务配置编辑发送 `CSScheduledTaskConfigurationDidChange`，接入现有自动备份调度；单纯执行记录变化不触发该通知，自动备份内容去重也排除运行状态。
- 新增 `restore-write-scheduled-tasks` 审计事件，记录阶段、结果、路径和错误，不记录任务文字或会话内容。审计保持旁观，不阻塞文件操作。

备份预览、任务页说明、创建备份说明、更新日志、README、功能说明和配置登记文档均已同步。恢复后的关闭策略会显示在预览中。

## 编译与产物

版本 `2.0-13` 已同步 `control`、`kPluginVersionString` 和更新日志。沿用既有隔离的 rootful/rootless 编译缓存；未运行 `make clean`，没有修改工作目录 `.theos` 和历史包。编译日志为 `build-rootful.log` 与 `build-rootless.log`。保留的告警来自既有 `UILocalNotification`、`statusBarFrame` 及 linker `multiply_defined` 废弃参数。

最终产物：

- [Rootful deb](../../../packages/com.wechat.improve_2.0-13_iphoneos-arm.deb)
- [Rootless deb](../../../packages/com.wechat.improve_2.0-13_iphoneos-arm64.deb)
- [调试符号](../../../packages/com.wechat.improve_2.0-13_symbols.zip)

两个包均包含 arm64 / arm64e，最低目标 iOS 15。`verify-packages.py` 检查 control 版本/架构、rootful/rootless 安装前缀、代码特征、两架构 dSYM UUID、首个存储迁移初始化器及无测试替身。也检查旧插件提示的特征字符串和 `setFeedback:` 符号不在包中。

`packages.json` 保存最终包摘要；`source-sha256.json` 保存最终源码摘要。最初仅含本轮 UI 修改的 2.0-13 包尚未交付，接到任务备份要求后重新构建；其摘要保存于 `preliminary-packages.json`，验证器只允许替换这些确认为本轮生成的同版本初步产物，保留旧版产物。

`preserved-files.json` 原始基线保留不变。本轮新授权的三个任务文件列于 `authorized-scope-extension.json`；其余 1,124 个基线文件（含原 `.theos`、`packages/.DS_Store`、选择器和公共设置单元格）保持原摘要。汇总结果见 `validation.json`。

## 真机验收

1. 按现有 IPA 注入/签名流程使用匹配环境的包，完全退出微信后重新打开；版本信息应为 2.0-13。
2. 在定时任务中创建一个发给文件传输助手的任务，先保持总开关关闭，手动创建配置备份。点此备份进入恢复预览，应出现“定时任务”模块。
3. 修改或删除这个任务，选择该模块准备恢复，完全退出微信进程并重新打开。确认任务名称、会话、文字、分钟/小时/天/周规则及单项开关恢复，总开关仍关闭；页面显示恢复后的说明。
4. 确认目标和时间后手动开启，下一次时间应在未来，不立即补发旧消息。恢复旧版不含任务模块的备份，或取消选择任务模块时，当前任务保持不变。
5. 当前账号不同于备份账号时，应提示跳过该账号的任务；切回原账号后才可恢复。其他账号任务不应改变。
6. 首页“定时任务”“表情功能”右侧均无箭头，仍可进入二级页。图片功能开关名称、原状态保持。
7. 长按已下载/未下载图片添加表情，检查成功、重复、失败和容量不足过程都没有插件黑色横条，仅保留微信原生提示；原生表情栏正常显示结果。

当前无已连接真机及可运行的 iOS 模拟器。本记录确认宿主机验证、iOS 编译和包校验，不代表微信私有接口、真实发送/上传、后台时机与真机视觉已验收。

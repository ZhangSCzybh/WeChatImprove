# 最小现场采样：样式开/关 × 冷启动/新消息

本轮没有连接设备，也没有执行本脚本。这里提供可选的隔离观察方法，帮助确认报告中的条件机制是否就是用户现场原因；它不构建或安装诊断插件，不修改生产源码/正式 Tests，不生成新包。没有现成 Frida/Objective-C bridge 环境时，可以先回传下方手工信息；本轮不安装或升级这些工具，不更换用户账号、数据库、微信版本或设备插件版本。

## 1. 先确认现场身份和设置

记录微信版本、设备当前插件版本及是否已加载 2.1-6。**回退工作区不会自动回退手机已安装的 2.1-7**；本轮没有替用户安装/卸载任何包。如果手机还加载 2.1-7，这次数据只能标记为 2.1-7 现场，不能冒充 2.1-6。历史 2.1-6 包已经保留，但此文不自动执行安装。

只记录现有开关，不更改密友策略：密友 enabled、隐藏会话 hideSessions、消息静音 silenceMessages、当前是否揭示、会话分组开关、底栏样式档位/文字/图标设置。保护名单只需记录是否非空，不回传联系人名字、账号或会话内容。

先做最小手工对照：保持同一账号、同一密友/分组/图标配置，对“底栏样式关闭 → 冷启动 → 收到普通未读新消息”观察微信数字是否仍消失。**当前这一格未验证**，是最有价值的新增事实。不要为实验清空未读、重置设置或修改名单；开关样式使用插件已有设置 UI。

## 2. 可选 Frida 观察脚本

文件为同目录 `runtime-badge-probe.js`。在已存在的工具环境中查明实际微信 PID，附加到已经初始化的进程；不假定进程名或启动另一份微信。示例命令的 PID、脚本和日志路径需替换为实际值：

```text
frida -U -p <实际微信PID> -l <本目录绝对路径>/runtime-badge-probe.js -o <本次本地日志路径>
```

环境须提供 Frida Objective-C bridge。若提示不可用，不尝试盲目升级或绕过，保留错误类别即可。脚本只经 `node --check` 与只读审查，尚未验证具体设备上的 Frida 版本/API 兼容性。它附加到方法加载时的当前实现，若之后其它插件再次替换实现，可能漏掉后续调用；未报告事件不等于没有事件。

脚本仅用 `Interceptor.attach` 观察自然调用，不替换参数、返回值或 IMP；不主动调用过滤 getter、未读重算或任何 badge setter；没有定时器/轮询、网络及用户设置写入。手动 capture 将视图读取排到主线程。读取显示 getter、遍历对象与控制台日志仍有开销，不能用这份日志判断滚动性能，也不能保证完全无时序扰动。

## 3. 最小四个标记

每次杀进程后重新附加；两次进程的指针不能作“同一对象”比较，只在同一个进程的冷态与消息后比较。

1. 样式开启，冷启动后看到微信数字时，在 Frida 控制台执行 `badgeAudit.capture("style-on-cold")`。脚本没有在启动前注入，此标记只采当时状态，不能还原此前的启动 setter 历史。
2. 保持当前复现方式，不进入新消息所属聊天以免标记已读。收到一条普通、非保护会话的新消息，观察角标后执行 `badgeAudit.capture("style-on-message")`。只记录“普通/保护、普通通知/静音类别”，不回传正文或联系人。保留标记前后自然 setter、过滤、begin/end/refresh 日志，不只截最终快照。
3. 用现有 UI 关闭样式，保留其它开关，杀进程重新打开；重新附加后执行 `badgeAudit.capture("style-off-cold")`。
4. 按同样条件收到一条普通新消息，执行 `badgeAudit.capture("style-off-message")`，记录微信数字和通讯录/发现的视觉结果。

不要求新增账号、给联系人发送消息或修改真实会话数据。若上述普通新消息不符合原本复现来源，可先按原来源重复一次并记录类别，避免为了控制变量改变了触发条件。两次真实未读总数不必相等；需要比较各次实际输入和输出，不能把不同消息状态当完全等值实验。

## 4. 日志如何判断

输出以 `[badge-audit]` 为前缀，有事件序号与线程。只回传一次消息附近日志和四个标记即可，不需要全量消息日志。

| 观测边界 | 用途 |
| --- | --- |
| controller 输入、index 原始 64 位值、root 类/ChatTab 匹配 | 区分微信专属内容入口及原生输入是否本来为 0；不固定假设索引就是 0。 |
| filter-return 的 nil/0/正数、同线程自然 snapshot | 确认是否介入；snapshot 不同于任何时刻都有效的全局“当前策略”。无自然观测或关联不足时记 unknown。 |
| adapter begin/end/refresh 前后、changeDepth、dirty、revision/epoch、cache | 判断失效窗口及刷新之后是否恢复。当前脚本不读取账号，账号比对均为 unavailable；epoch 记录自然 snapshot 入参与 adapter 属性，不主动读取全局 epoch。 |
| 实际 item setter、badge hidden/alpha/frame/父视图与祖先状态 | 区分改零隐藏、透明/祖先隐藏、几何越界。frame 要根据真实父坐标系解读；不是直接与 item 比较任何子视图 frame。 |
| badge 指针、styleOwnership / bar state | 同进程确认同一 badge、实际 applied；仅 defaults enabled 不足以证明 item 被接管。私有 key 被 strip 时 applied 明确不可用。 |
| 原生 getTotalUnreadCount 自然返回 | 区分原生本来为 0 与中途被插件替换为 0；脚本不主动触发重算。 |

脚本尽量显式区分合法 nil、false/0、缺 selector、读取失败和符号不可用。诊断中的 getter 读取不是原子事务快照；跨线程发生变化时要按事件序号、线程和自然调用关联判断，不拼成虚假的单时刻状态。

若原生输入>0 → getter=0 → item 实际写入0 → 同一 badge hidden=YES，且期间主 adapter 处于 changeDepth/dirty/无缓存，则支持首选机制。还需确认过滤后本应有普通可见未读，排除“只有保护会话未读”的合法零值。若 setter 输入输出一致、hidden=NO，则转查真实几何与裁剪/覆盖。

若 count/string 为 0/nil 但输入本来就如此，不能归因为插件覆盖。若过滤结果 nil，则本次未介入。若只有 show-dot 被抑制，不可直接说已隐藏旧数字。若可靠 refresh 后没有重写底部值，须在足够完整、确认探针覆盖的事件窗口内观察；日志遗漏不能证明“永远不重写”。

## 5. 本探针仍不能单独证明的内容

真实 UI 合成、像素遮挡、所有兄弟视图的完整 z 序与动态动画并非 JSON 状态就能完备证明；祖先 clips/mask/z 只是定位线索。snapshot epoch/账号相等性若缺自然样本或可用符号，仍需后续针对性观察。脚本不枚举或输出会话行的真实内容，也没有主动计算投影，因此不能直接给出真实过滤 projection 的 count/redDot 全部构成。

当前版本的账号相等性字段均明确不可用，不应期待日志自动判定账号边界。自然调用入参与保存的 snapshotEpoch 也不是对当前全局 epoch 的原子采样。原生异常可能令 onLeave 缺失，不能使用未配对调用 ID 推断窗口已结束或策略稳定。

现有 Hook 可能叠加其它插件，现场安装的实现链及启动前调用未必全部被捕获。必须先核对版本和捕获范围，不能把 unknown 当 NO 或把没有日志当没有调用。本轮结论会继续保留这些缺口。

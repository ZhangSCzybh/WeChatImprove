## 与 0/nil 内容路径为什么独立

几何探针直接编译真实 `CSTabBarNativeAdapter.m` 与 preference，使用受控 native item 布局，**不编译或调用 CloseFriendNotificationHooks 的数字/字符串/dot block**。非零内容不被该隐私链改写，仍能得到 item 无交集；因此它提供的是几何机制证据。

[内容写入探针](probe/content-probe.md) 则提取真实 getter、ChatTab 和三段内容 block，额外编译真实 policy/projection；其原 IMP 与 frame 是明确的受控替身，**不加载样式 adapter**。在固定 frame、同一对象下，数字输入可变为 0、字符串可变为 nil；因此它提供的是内容机制证据。

两条机制可能同时存在：实际采样若先见进入 item 的内容已经是 0/nil，就要先追溯替换值，不能仅靠移动 frame 恢复内容；若原生输入/最终内容仍是有效非零/非空、hidden 仍为 NO，才应继续检查 frame 转换、裁剪及遮挡。dot block 只抑制调用，不主动隐藏现有对象，不能把它单独写成“将当前 badge hidden 设为 YES”。本次没有据此选择或实施修复。

## 通讯录/发现正常如何影响优先级

用户反馈“微信 tab 冷启动有数字，收到消息后消失；通讯录和发现正常”更贴近只对 ChatTab 生效的内容路径，所以应优先采它的真实决策、输入输出与快照状态；但**这只能降低通用几何作为本次主因的优先级，不能逻辑排除它**：

1. 同一几何算法不意味着所有 tab 输入相同。数字、字符串和纯点的原生锚点及代表尺寸不同；各 tab 的实际 badge 内容与尺寸、图标配置和布局阶段也可能不同，需采样确认，不能无证据假定相同。
2. 消息可能触发微信 tab 的内容/布局更新，其它 tab 当时可能没有经过相同的调用入口或状态变化。是否如此由原生链与现场日志决定，不能凭“通用算法”推断四个 item 在同一时刻一定经过同样流程。
3. 本几何 fixture 给四个 item 人为设置了相同 badge 输入，因而四个对象可一起出现相同问题；这不对应真实通讯录/发现的提醒来源、值或调用时序。它不能要求设备其它 tab 必须同坏，才承认几何有可能参与。
4. item 无交集并不自动等于屏幕不可见；真实父链裁剪、item 间重叠和合成还影响可见结果。其它 tab 可见也不能反推出微信 tab 的同一内容和相同裁剪条件已经成立。

同样，若现场密友过滤根本未生效、无保护名单或内容 Hook 不可达，内容探针的受控零值例子就不能直接用于归因。还需要真实样式开/关 × 冷态/消息后四象限、同一自然消息前后的输入值、getter 决策、cache/changeDepth/dirty、native badge 的内容/hidden/frame 与祖先裁剪链，才能将机制与此次用户现象闭环。

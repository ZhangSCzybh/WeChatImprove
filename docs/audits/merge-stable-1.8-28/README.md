# 1.8-28 合并消息滚动间距稳定性

在当前 1.8-27 工作副本上修复历史消息滑动后接缝再次收紧的问题。录屏证据与旧实现复现见 [前置分析](../scroll-jitter-analysis-2026-10-20/README.md)：同一组三条气泡在第 57→58 帧的第二道接缝由约 8 个录屏像素缩至 2 个；旧适配器在相同输入下允许显示后的行高从 46pt 变成 40pt，且主动表格更新次数为 0。

## 行为变更

- 测量时共同提交行高变化量和内容位移，渲染仅应用这一对结果。真实边界仅用于安全校验，不再清除测量决策，也不提供后续隐式收紧的几何。
- 历史布局 epoch 和原生 `resetLayoutCache` 不再直接清掉当前结果。准备阶段比较消息、账号、会话、邻接关系和配置；每次原生行高查询验证宽度、原生高度、正文尺寸、显示比例、昵称和辅助内容标记。真正的变化仍会重新计算。
- 用已提交的位移校验可见内容是否落在分配空间内。发现越界、未知变换或新增辅助内容后，申请恢复原生空间；到下一次行高查询才共同提交恢复的高度和位移，避免半套结果先变化。
- 同样的输入下，安全回退保持稳定，重复渲染、缓存重置和停止滚动不会再次压缩。正文/宽度等真实变化后可重新判断是否适合紧密布局。
- 未验证版本或没有可靠首轮几何的消息保留原生间距，不再显示后采样、随后突然收紧。现有 8.0.78 普通文本首轮几何及紧密布局目标继续沿用，没有整体恢复曾回退的 1.8-24，也没有修改 44pt 头像预算。

这一轮解决布局结果切换导致的抖动，不保证所有消息都达到最小接缝。头像、昵称及未验证布局可能需要更大的稳定间距。真实内容变化仍允许必要的重排；未知原生内容的最终布局能力由微信负责。

核心改动在 [CSMessageMergeAdapter.m](../../../Controllers/CSMessageMergeAdapter.m)。连续圆角绘制、背景颜色、字体颜色、通话记录样式、设置偏好和合并判断策略均与任务开始时逐字节一致，完整变更见 [changes.patch](changes.patch)。除核心适配器和测试外，仅修改版本号、发布说明和项目 README。

新增场景在 [MessageMergeAdapterTests.m](../../../Tests/MessageMergeAdapterTests.m)：

- 私聊/群聊、收/发、两种头像位置、2/3/4 条消息、无透明边距/有透明边距的组合。
- 拖动→减速→停止，重复缓存重置、历史 epoch、复用和重新绑定；渲染先于再次行高查询时位移也不丢失。
- 逐次检查行高、内容位移、组内接缝、内容尺寸、滚动偏移和表格更新次数，避免仅检查“不主动刷新”。
- 内容占用变大、上沿越界、子视图变换、消息视图变换、翻译辅助状态及无有效可见内容的安全回退。
- 模拟表格更新时的原生高度查询与渲染，验证高度和位移一起恢复、一次更新后稳定；同输入不因重置重新压缩，真实宽度/正文变化能重新规划。
- 原有头像、昵称增长与透明边距用例改为断言稳定结果；未知版本断言持续原生间距，移除旧测试中明确接受二次收紧的期望。

UIKit 替身增加可选的表格更新回调，仅用于复现原生重测顺序；它不执行真实 UIKit 绘制或手势减速。全套宿主回归通过不等同于真机帧率/录屏验收。本次未安装到手机，仍需在微信中重复原录屏操作确认实际效果。

# 1.8-30：合并消息间距统一为 2pt

按用户本次明确更正，“2px”指 **2pt 逻辑点**。在既有 WeChatImprove checkout 和 1.8-29 源码基础上修正单位，沿用首条占位、引用框完整布局与快速历史滑动闪退修复，发布新的 Rootless 包 1.8-30。

## 实现

- 内部接缝的上下两侧各保留 1pt，标准合并布局总间距为 2pt，覆盖私聊收发、群聊发送方首条与中间条，以及包含引用消息的组内前后间距。
- `CSMessageMergePlanLayout` 直接用逻辑坐标计算位移与行高，移除 `displayScale` 参数及 `floor/ceil` 物理像素取整；适配器同步删除屏幕倍率读取和相应缓存字段。分数坐标不再按屏幕像素网格调整。
- 设置提示、当前版本说明和 README 明确使用“2pt（逻辑点）”。1.8-29 的历史更新说明和审计记录保留当时实际实现，不改写历史。
- 保留原生整组外侧间距、内容边界保护。较大头像、群昵称、翻译等附加内容继续优先保留所需空间；接收方群昵称已贴行顶时不额外加留白。
- 气泡图片解码修复的 `CSBubbleStyleAdapter.m` 与任务开始前逐字节一致。首条 38pt 标定、群聊发送方昵称判断和引用消息完整占用算法均保留。

本次没有增加服务、切换工作区、访问数据库或安装手机应用；源码和构建仍使用用户既有项目。

## 验证

先将回归目标改为 2pt，旧 1.8-29 实现在首条高度断言失败，见 `merge-before.log`。修改后定向回归和全部 **31 / 31** 个 `Tests/verify-*.sh` 入口通过，结果见 `regression-results.json` 和 `regression/`。

| 核心入口 | 检查结果 |
| --- | --- |
| verify-message-merge.sh | 235,148 项策略/数学检查、16,979 项适配/生命周期检查通过 |
| verify-bubble-style.sh | 36,979 项策略/渲染检查、2,321 项适配检查通过 |

适配器矩阵仍提供 1×、2×、3× 的不同屏幕信息，但接缝直接断言为相同的 **2pt**，不乘除倍率。覆盖首条/末条头像、收发双方、私聊/群聊、引用消息位于首中末条、不同引用高度、重复布局与拖动/减速/停止。策略回归另覆盖分数坐标下的首中末接缝、整组外侧留白和内容不裁切。已有无效引用数据、特殊内容保护、图片延迟解码安全回归继续通过。

这是主机 Foundation/UIKit 替身测试和交叉编译结果；未进行真机微信滚动、截图或触摸验收。

# 1.6-7：消息合并滚动间距稳定性

目标：微信 8.0.78 / Rootless。基于用户提供的 6084f9f02d00f0fd17a1589362140bff.mp4（约 5.03 秒）以及当前消息合并代码排查。视频用于确认现象，未连接真机采集微信内部布局日志。

## 原因与处理

原实现首次测量不知道可压缩的底部留白，返回原生高度；Cell 布局后计算出留白，排队请求再次测量。拖动或减速期间刷新被推迟，停滑后通过 beginUpdates/endUpdates 应用高度变化。即使补偿第一条可见消息的位置，各条消息内部间距仍会改变，因此存在停滑后向上收紧的视觉问题。

本次将间距决定固定在同一测量周期内：

- 首次测量决定本周期实际间距，后续重复 measure 和 layout 不会因为刚获得留白数据而改变行高。
- Render 仅记录安全留白供后续明确的配置变更使用，不再因首次获得几何数据而请求表格事务。
- 新行初次进入测量不会标记为需要额外刷新；原生 heightForRow 请求完成后消费该行待刷新状态。
- 合并配置和会话没有变化时，重新激活页面、收到共享气泡设置通知都不提升测量周期，不重置模型。
- 未压缩且已有几何记录的行跳过重复子视图遍历。没有新增定时器、逐帧监听或后台扫描。
- 原生布局失效、尺寸改变或会话切换会丢弃不适用的几何记录；插件自身的缓存重置与原生内容失效分开处理。
- 已压缩的行若实际内容超出安全区域，仍允许恢复原生高度，避免内容裁切。关闭合并、昵称策略变更及真实消息结构变化仍可触发布局刷新。

## 负间距的边界

微信现有头文件没有提供经过验证的“显示前全部内容边界”接口。首次未知布局的负间距保守取零；正间距可以在首次测量直接应用。同一模型已验证的安全留白，可在之后修改间距且身份显示状态、布局周期和尺寸仍兼容时应用。仅仅滚动离开再回来、退出重进同一页面，不会主动压缩已显示行。

因此不能承诺所有新出现的消息立即达到设置的负间距。这是有意选择的稳定性边界，避免以估算高度、离屏创建 Cell 或停滑重排换取紧凑效果。真实内容增长导致的防裁切恢复仍是允许的例外。

## 验证

运行 `bash Tests/verify-message-merge.sh`，通过 7,008 项策略/导航数学检查及 717 项实际适配器/导航/时间代码检查（UIKit/显示帧替身）。新增覆盖：

- 群聊/私聊在拖动、减速期间首次测量、20 次布局及复用，停滑时行高、更新次数和滚动偏移保持稳定。
- 无变化的页面激活和共享设置通知不重置已测量模型。
- 明确修改间距后，首次重测即可使用验证过的几何信息；原生重置和宽度变化清除样本。
- 原生高度缓存忽略插件结果时收敛到原生高度，不排队无限刷新。
- 内容增长恢复安全高度；最后头像模式下无后继消息的行，关闭合并仍可恢复身份布局。
- 原有分段文本、原生撤回定位高亮和时间辅助逻辑回归通过。

完成 Rootless arm64/arm64e 构建及包内版本检查。测试替身没有模拟真实 UITableView 渲染；未测量真机 FPS、帧耗时、CPU 或电池消耗。既有气泡与撤回模块本次没有修改，其旧版真机待验项目仍需验证。

## 设备验收

安装 1.6-7 后，在原有群聊、私聊中开启合并，上下拖动历史消息并让惯性自然停止，重点观察同一屏的气泡间距是否还有二次收缩。分别检查首次加载历史和再次浏览，连续滚动至少一分钟。再检查更改间距、关闭合并、多行/分段消息、消息时间、隐藏头像及点击撤回蓝字后的首次原生高亮。

建议与 1.6-6 使用同一会话、相同设置对比。默认不切换账号、不清空数据、不更换微信环境。此前安装包均保留；本次只生成测试包，没有进行设备安装或访问聊天数据库。

# 广告净化

入口：**插件设置 → 界面定制 → 广告净化**，紧接“后台模糊”。页面继承项目的 `CSSettingsTableViewController`，使用统一的 `CSSettingSection`、`CSSettingItem` 和 `CSSettingTableViewCell`。

总开关和七个子项均默认关闭。先打开总开关，再打开需要处理的范围；关闭总开关会保留各范围选择。更改后重新打开相应页面，关闭只影响后续调用，已过滤或已缓存的页面可能需要退出重进。

| 开关 | 实现范围 |
| --- | --- |
| 公众号文章广告 | 文章广告事件、明确的文章广告请求地址及广告处理入口 |
| 订阅号广告 | 普通／Box 列表加载期间的广告整卡丢弃，及广告开关、内容处理和广告 Flutter 插件列表过滤 |
| 朋友圈广告 | 广告有效性、广告推送与专用处理入口、广告素材地址及画布字段 |
| 视频号广告 | 广告模型工厂、当前版本的三个内容 VM 初始化接口、广告路由和专用广告字段 |
| 小程序广告 | 开屏广告开关、广告处理、素材／广告脚本地址及小程序 JS 调用 |
| 搜一搜广告 | 原生广告有效性、专用广告 JS 调用和搜索结果中的明确广告记录 |
| 订阅号推荐内容 | 与订阅号广告分别控制的推荐判断和处理入口，也受总开关控制 |

搜一搜保留普通的前三条搜索结果，不按位置删除，也不因为标题含“广告”就删除。仅处理匹配的搜索事件与处理器返回值，按 `isAd`、`is_ad`、`ad_posid`、`ad_info` 等明确元数据判断广告，保留原顺序及回调字段。无法解析、格式不符或超过遍历预算时保留原结果。

共享的 `JSFunctionDef` 和通用网页调用无法可靠识别所属产品，因此这些通用过滤仅在**六个广告范围全部开启**时生效；可识别为小程序的调用及各业务专用入口按自身开关处理。“订阅号推荐内容”不参与这个全选条件。网页参数采用有界递归和按需复制，不修改原容器或字典键；未发生变化时返回原对象。

`2.6-9-beta02` 针对录屏中“素材空白但品牌、广告标签、文案和占位仍显示”的情况补齐整卡处理。普通与 Box 公众号 API 在同步构造列表前进入线程独立的展示上下文，只有在该上下文内，才在 `BrandTimelineMsgMgr canTimlineMsgDiscard:` 的原判定基础上，调用 `CMessageWrap isBizAdCanvasMsg` 追加广告整卡丢弃。该判别与推荐卡独立，不按文章文案判断。

过滤不修改原数组、消息或缓存源。两个消息转换器及消息增删通知保持原行为；关闭后沿原调用链输出。共享丢弃判定也用于 AFF 迁移，因此在两个 `doDataMigrate` 前驱调用期间暂停展示上下文，并原样返回迁移结果、保留异常，避免同步重入影响历史记录；保护接口未就绪时不启用新增过滤。原 completion 对象保持不变，没有按 NSArray 包装实际承载 C++ protobuf 的 `getBizTimelineMsgListWithCompletion:`。入口及调用分支证据见 [beta02 列表审计](../audits/ad-purification-subscriptions-beta02/README.md)。

## 配置与运行机制

八个设置均为全局布尔值，前缀为 `com.wechat.enhance.ad_purification.`：`enabled`、`articles`、`subscriptions`、`moments`、`finder`、`mini_programs`、`search`、`recommendations`。读取不注册或写入默认值。备份注册表通过 `ad_purification` 模块精确登记这八个键，现有恢复与重置流程继续管理它们。

启动通过 `CSBackupWhenReady` 等待配置恢复完成，再发布原子范围掩码。关闭操作同步撤销对应范围，队列中读取的旧配置不能重新启用它。Hook 首次按需安装；之后各适配器直接读取当前掩码，关闭时转发给安装时保存的前驱。设置变化及微信恢复活跃时重试缺失接口，避免重复安装。

安装前检查类、方法种类、返回类型、参数数量及每个参数类型；不匹配时跳过。视频号 `scene` 使用真实的 32 位整数，广告路由保留完整十参数签名，JS 桥接保留 32／64 位标量及 `SEL`。初始化器使用消耗 receiver、返回保留对象的 ARC 约定，提前返回空值时正确释放原 receiver。

## 参考插件与适配证据

功能依据为用户提供的 `FuckWeChatAdBlocker.dylib` 静态分析；接口依据为微信 `8.0.80`／构建 `8.0.80.34` IPA。证据、样本身份和本项目实际接口覆盖见 [接口审计目录](../audits/ad-purification-8.0.80/README.md)。静态元数据只能证明该版本声明了接口，不能证明广告一定经由该接口到达。

本实现只接入去广告相关能力。参考样本的远程授权／退出、反检测与调试开关不属于本功能；数据库创建、服务构造及宿主标识仍由微信管理。没有复制没有可用 getter 的实例变量，也没有把旧版本初始化器签名直接套到当前微信。

## 核心验证与实际边界

主机测试直接编译并链接生产偏好、过滤器、原生和网页适配器，使用独立临时偏好与接口替身。聚焦覆盖关闭透传、范围隔离、已有 Hook 前驱、参数与返回值、初始化器释放、安装幂等、并发关闭和畸形内容回退；另验证现有备份注册、重置与启动门禁。双方案构建包含 arm64／arm64e，最低目标 iOS 15.0。

本版未安装到手机。实际广告可见性、页面布局、缓存刷新、网络响应和其他插件共存仍需在用户原 Rootless 环境验收；其他微信版本的接口兼容及新增广告形式不在已核实范围内。具体测试结果、安装包和校验值见 [2.6-9-beta02 发布记录](../../packages/2.6-9-beta02/README.md)。

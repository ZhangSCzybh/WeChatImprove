# AI 自动回复

基于现有 Theos / Objective-C / Logos / UIKit 框架实现，使用插件设置样式和微信原生聊天详情分组。功能按微信账号隔离，总开关与每个会话开关默认关闭。

## 使用步骤

1. 打开「插件设置 → 功能增强 → AI 自动回复」。
2. 在「模型连接」选择调用方式，填写完整 HTTPS 请求地址、API Key 和模型名称，点击「保存」。默认「通用兼容」使用 Chat Completions（例如 `https://服务域名/v1/chat/completions`）；「百炼会话」使用 Responses（例如 `https://服务域名/compatible-mode/v1/responses`）。切换方式时，编辑框会替换已有的 `/chat/completions` 或 `/responses` 后缀；域名和地域由用户按服务商配置填写，不自动切换。
3. 点击「测试连接」。测试使用固定短消息，确认返回非空文本；不发送微信消息，也不自动打开总开关。地址、模型、Key、调用方式或 Session 缓存变化后必须重新测试。再次测试失败会撤销旧验证，取消测试保留已有验证。
4. 在「管理预设」新增、编辑或复制多个命名预设。提示词用于定义角色、语气和回复规则。选择全局默认预设；删除预设时选择替代项并更新会话引用，至少保留一个预设。
5. 开启总开关，进入某个聊天窗口右上角「…」的聊天详情，群聊在「查找聊天内容」下方开启「启用 AI 回复」。紧接其下的「免 @ 回复」默认关闭，打开后当前群无需被 @ 即可回复符合规则的新文本；它不会自动开启总开关或会话开关。通过「回复预设」选择跟随默认或独立预设；私聊仍使用「AI 回复」分组，不显示免 @ 开关。

群聊行顺序为「查找聊天内容 → 启用 AI 回复 → 免 @ 回复 → 回复预设」，使用同一个原生分组，复用微信的开关行、右值箭头行、分隔线和默认间距，不另外增加标题或长篇页脚。开启会话后，连接待验证、总开关关闭等状态使用原生行内说明展示。

设置页可查看已开启会话与最近 200 条回复记录。记录展示时间、会话、预设、结果、简短原因、模型、调用方式以及服务商返回的输入／输出／缓存命中／缓存创建 Token；不保存聊天正文、模型回复或 API Key。「已提交微信」只表示微信原生发送调用正常返回，不代表对方已收到。

「回复管理 → Token 用量」汇总最近 200 条已记录响应的实际数字，并注明每项指标有多少条记录提供。缺失指标显示「未提供」，不按字符数猜测，不把输入 Token 与其中的缓存 Token 重复相加。包含生成成功但发送失败的已返回用量，不含连接测试及未取得用量的取消／网络异常请求；该页面不是完整账单，也不估算跨模型费用。

「密友 → 保护选项」新增「隐藏 AI 自动回复」，默认关闭。开启后，在密友功能启用且锁定时，「回复管理 → 已开启的会话」隐藏密友名单及密友群聊名单内的会话，入口数量仅统计可见会话；解锁后重新显示，重新锁定后再次隐藏。已打开的列表随隐私状态变化刷新。此选项与「隐藏聊天会话」「隐藏定时任务」独立，保留每个会话的启用状态和预设。只影响列表和数量展示；即使同时开启“隐藏聊天会话”，已启用会话仍正常自动回复。锁定、解锁或切换隐藏选项不会取消正在生成／排队的回复，也不会清空 AI 上下文。

## 回复规则

- 普通私聊仅处理符合条件的新文本消息。群聊默认必须在结构化 @ 名单中精确包含当前账号；手打 `@名字`、`@所有人` 均不满足默认触发条件。该群开启「免 @ 回复」后，普通文本以及带 `@所有人` 的正文也可触发；仅有 @ 没有正文仍不触发。不同群的开关独立，关闭免 @ 后恢复默认规则。
- 本人消息、历史消息、重复消息、系统消息、公众号/服务号和非文本消息不触发。
- 同一会话同一发送者的连续消息等待 2 秒后合并。同一会话串行处理，全局最多 2 个模型请求，最多等待 20 批；排队批次 120 秒过期，单次请求 60 秒超时。
- 模型上下文仅包含启用之后产生的内存对话，最近最多 10 条、正文总计最多 12000 个 UTF-16 单元；群按群与发送者分开。预设系统提示词另计。回复最多 4000 个 UTF-16 单元，不拆分发送。
- 手动回复与 AI 自动回复可以并行。手动发送消息不会取消或暂停 AI 任务，不会清空 AI 对话上下文；正在生成或排队的 AI 回复会继续处理。
- 关闭 AI 开关、修改 AI 配置或切换账号，会取消尚未提交的任务。密友锁定／解锁及隐藏选项变化只刷新展示，不暂停回复。配置保存统一取消当前待回复任务并清空上下文。已经交给微信的消息无法通过关闭开关撤回。
- 首次启动、重新开启或清空运行状态后不补回复旧消息。由于微信时间戳精度为秒，开关变化所在那一秒的新消息可能被保守跳过。
- 已处理身份在本机持久化，消息服务端 ID 与本地 ID 的后续补齐也会合并到去重账本。生成失败、网络超时和发送结果未知均不会自动重试该消息；百炼明确拒绝已失效的会话引用时，可在同一任务时限内重建请求一次（见下文），不重新发送已提交的微信消息。
- 微信被系统挂起、强退或未完成首次解锁时，不能保证自动回复。本功能不会自动开启后台保活；恢复后已过期任务不会补发。

## 连接与数据

两种调用方式都采用 `Authorization: Bearer`、`model`、`stream:false`，仅支持 HTTPS 完整地址。客户端拒绝重定向，禁用 Cookie 与本地 HTTP 缓存，响应体上限 1 MiB。不包含图片、语音或工具调用。

### 通用兼容

每次通过 `messages` 发送预设系统消息及有界上下文，适用于兼容 Chat Completions 的服务商。稳定的预设始终位于请求前缀，支持隐式提示词缓存的服务商可自行命中；客户端不承诺命中率。旧配置缺少新字段时继续使用此方式，保留已验证连接，无需迁移或重新填写 Key。

### 百炼会话与 Session 缓存

首次请求把预设放入 `input` 的 `system` 消息，并发送有限历史及本次用户消息，使用 `store:true`。收到完成的有效文本且微信原生发送正常返回后，才在内存保存 `responseID`。后续同一会话请求通过 `previous_response_id` 续接，仅上传本次用户消息。预设不用逐条重传，模型继续使用服务端上下文；不使用不会被续接继承的顶层 `instructions`。

引用按微信账号、聊天会话以及群内发送者隔离，不写配置、回复记录或备份。重启微信、切换账号、保存 AI 配置、修改预设或开关会清空内存引用；手动回复、密友隐藏／解锁不会清空。百炼响应 ID 有效期为 7 天，过期后以当前预设和有界上下文重建。只有明确的 `previous_response_id` 拒绝错误会额外重建一次，仍遵守原任务 60 秒／排队 120 秒时限；普通 404、认证失败和网络超时不触发重建。

远端引用不会绕过原有「最近 10 条、正文最多 12000 个 UTF-16 单元」限制。准备请求或保存回复时发现本地窗口需要裁剪，就放弃该远端引用；下一次重新上传预设和保留的窗口。因此短会话更容易连续复用；窗口满后，持续对话可能每次都重新上传。发送失败或结果未知不会推进引用，不把未确认提交的 AI 回复带入后续上下文。

「百炼 Session 缓存」为可选开关，默认关闭，仅在百炼会话方式下可用。开启后请求携带 `x-dashscope-session-cache: enable`。这与 7 天会话引用有效期不同：当前官方文档规定显式缓存最短前缀为 1024 Token、有效期 5 分钟，命中后续期；低频或较短预设不保证节省。`qwen3.8-flash` 支持相关能力，但属于缓存计费特殊模型，不套用其他模型的通用折扣。减少上传不等于免收输入费用，缓存创建也可能收费；以实际 Token 返回和服务商账单为准。

选择百炼会话意味着启用服务端对话存储。本地清空引用或关闭功能不会主动删除已存于服务端的对话。改用其他服务商时可选择通用兼容、保存连接并重新测试。

实现依据（2026-10-27 查阅）：[百炼 Responses 接口](https://help.aliyun.com/zh/model-studio/compatibility-with-openai-responses-api)、[Responses 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)、[上下文缓存](https://help.aliyun.com/zh/model-studio/context-cache)、[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。

每个微信账号的配置、去重账本和结果记录位于插件 `Library/Preferences/WeChatImprove/ai-reply-<账号 SHA256>.plist`，采用原子写入和文件保护。损坏文件保留并停止回复，不自动覆盖为默认配置。

API Key 保存在本机 Keychain，按账号与凭据版本隔离、不同步到其他设备；首次解锁后可在后台读取。新 Key 写入成功且配置保存成功后才启用；替换文件前保存失败会保留旧连接并清理新 Key。如果文件已替换、但目录同步失败，系统会保留前后两版 Key 并暂停使用配置；重新读取后无论落在哪一版，凭据都保持有效引用，新连接仍需重新测试。历史凭据版本仅保留在本机，供已有恢复事务精确回滚；停用当前 Key 会解除活动引用。配置导出不包含 Key 或凭据版本。

备份增加「AI 自动回复」模块，只导出预设、连接地址／模型／调用方式／缓存选项和会话规则（含免 @），不导出 API Key、连接验证、远端响应 ID、去重账本、队列或结果记录。仅在备份原账号恢复，恢复后总开关关闭，需重新填写 Key 并测试连接。旧备份没有此模块时不会改写当前 AI 配置。事务回滚恢复原始本地状态。

所有自动化回归使用临时目录、URLProtocol 或原生替身，不调用真实模型、不读写主机真实 Keychain、不发送微信消息。除既有双重开关、去重、合并、并发、账号与凭据保护外，新增覆盖请求协议、用量解析、引用续接／失效重建／过期／上下文裁剪、迟到回包、免 @ 的原生行与独立开关、隐藏群聊免 @ 及手动发送保留远端引用、备份保留选项并去敏。Theos 编译验证 `arm64` 与 `arm64e`。

仍需目标微信真机验收：原生聊天详情类与选择器是否匹配当前版本、实际页面排版与键盘操作、真实服务商响应、锁屏/后台调度及微信发送结果。构建通过和替身测试不代表这些真机流程已经验证。源码与新安装包已纳入 main，未安装或替换用户设备上的原环境。

# 定时任务与会话图片添加到表情

版本：2.0-16。更新日期：2026-10-26。已完成宿主机核心回归、iOS 编译和包校验；尚未完成微信真机验收。原生图片接口的静态依据为 WeChat 8.0.78.34。

## 定时任务

入口：插件设置 → 功能增强 → 定时任务。总开关初始关闭，独立保存于当前微信账号；右上角“+”新建任务，点击任务编辑，左滑删除。新任务默认启用，只有总开关也开启时才会调度。

任务列表和编辑页使用与其他功能相同的公共设置单元格、图标、分组背景和默认行高。点击“消息内容”进入多行文字编辑，点击时间行进入系统时间选择；子页点“完成”回到任务，再点“保存”持久化修改。点击执行记录可查看完整结果。

开发分支新增「密友 → 保护选项 → 隐藏定时任务」（2026-10-27），默认关闭。开启后，密友功能启用且锁定时，任务列表隐藏收件人为密友或密友群聊的任务，包含已停用任务；解锁后恢复显示，重新锁定后再次隐藏。与「隐藏聊天会话」「隐藏 AI 自动回复」独立。过滤只生成展示列表，保留任务定义、启用状态及时间规则；编辑与删除使用同一份可见列表，并在执行操作前重新校验隐私。已打开列表会随隐私状态变化刷新。发送仍遵循原有密友保护规则。

私聊/群聊选择复用密友的 `CSNativeContactPicker`：由微信原生好友/群聊列表提供搜索、勾选与完成按钮。定时任务只接受一个会话；更换时先取消原勾选。空选择或搜索/标签产生的多选不能完成，不会默取第一项。取消、账号变化或选择期间隐私状态改变时保留原目标；密友/红包名单继续使用原来的多选模式。文件传输助手保留快捷选择。

每个任务指定一个私聊、群聊或文件传输助手，以及一段不超过 4,000 字符的文字。最多保存 100 个任务。当前只支持文字，不包含图片、语音、附件、群成员 @、多会话批量发送或服务器代发。

| 规则 | 行为 |
| --- | --- |
| 单次 | 在所选未来时间执行一次，执行时刻被处理后自动停用 |
| 每 N 分钟 | 1–1440 分钟，从“首次时间”按固定间隔计算 |
| 每 N 小时 | 1–168 小时，从“首次时间”按固定间隔计算 |
| 每天 | 按创建任务时保存的时区，在每天所选时分执行 |
| 每周 | 可选多个星期，按保存时区及所选时分执行 |

更改手机时区不会改变已有任务的时区。夏令时跳过的时刻取当天下一个有效时刻；秋季时钟回拨造成同一时刻出现两次时只取第一次。定时器不会每秒轮询：只设一个最近到期的一次性定时器，开启、编辑、前台激活、显著时钟变化及账号变化时重新计算。多项同时到期时每次处理一项，间隔至少 1 秒；大量任务不宜集中在同一秒。

迟到不超过 30 秒视作当前时刻可执行。超过 30 秒时，默认跳过；任务打开“允许补发最近一次”后，只补发最近 10 分钟内的最后一个时刻，绝不补发全部积压。总开关关闭期间不补发，重新开启从下一个未来时刻开始。单项任务关闭后重新开启也从下一次开始。

发送前会依次检查任务存储、账号及代次、插件授权和会话状态。密友处于隐藏/保护状态时不会向该敏感会话发送。创建全新的文字消息，经现有 ABI 校验适配器提交给 `CMessageMgr AddMsg:MsgWrap:`，不复制历史消息，也不依赖当前显示的聊天页面。

### 执行记录与后台限制

任务库位于：

`<容器>/Library/Preferences/WeChatImprove/ScheduledTasks/<账号 SHA-256>.plist`

文件内容含账号标识、会话标识与任务文字；哈希文件名不等同于加密。文件权限为 0600，iOS 写入使用 `NSFileProtectionCompleteUntilFirstUserAuthentication`，与需要锁屏后执行的用途一致。库文件采用原子替换及文件/目录 fsync，另有独占文件锁。

先持久化执行意图、推进下一次时刻，再交给原生发送；因此同一时刻不会因重启自动重复发送。如果保存失败，停止调度并显示原因，后续前台/生命周期刷新可重试读取；异常原文件保留。提交期间进程退出，记录为“结果未确认”，不自动重试。最近保存 50 条记录，页面显示最近 10 条。

“已提交微信发送”只代表原生调用正常返回，不是送达回执。设备离线后的发送/重试由微信原有队列负责，插件不另起重发循环。

未越狱签名 IPA 中，微信被 iOS 挂起、用户强退或手机关机时，插件无法自行准点唤醒。此功能不会擅自开启后台音频保活；可由用户使用现有“后台运行”设置，但仍受 iOS 限制。回到可运行状态后按以上错过规则处理。

从 2.0-13 起，配置备份包含当前账号的任务名称、目标会话、文字、任务开关、补发选项、时区及单次/分钟/小时/天/周规则；不包含执行记录、已领取的执行时刻或待发送状态。备份预览可单独选择“定时任务”。只能恢复到原所属的当前账号，支持同账号换设备；总开关恢复为关闭，确认后手动开启，从下一个未来时刻开始。旧备份没有该模块或未选中模块时保留现有任务。配置重置可选择清除当前账号的任务库与记录，其他账号不受影响。

任务配置变更会通知现有自动备份调度器，单纯执行记录变化不触发重复备份。恢复使用原有 prepared / applying / committed 事务：日志保留精确的本机原始状态供异常回滚，含当时的开关、去重状态和记录；正常恢复的外来执行状态不参与调度。若准备恢复后任务又执行，计划会因状态变化被拒绝，需要取消后重新预览。

### 选择发送会话（2.0-16）

“文件传输助手 / 私聊 / 群聊”菜单保持原样。选择私聊或群聊时，只处理该菜单的关闭；正在关闭时等待其转场完成，已关闭时直接检查当前编辑页，未关闭时在该菜单自己的 dismissal completion 中继续。打开前检查主线程、窗口、导航栈顶和父容器是否被其他页面占用；保留原有账号和隐私校验。取消联系人/群聊选择回到同一个编辑页，任务名称、消息、规则等未保存内容保留。没有固定延迟，也不对承载插件的编辑页调用 dismiss。

本轮仅运行原生选择器脚本的定时任务展示分支（278 项）、原生选择器既有分支（196 项）以及定时任务核心脚本（102 项），共 576 项。失败复现及分别覆盖弹窗和全屏的验收步骤见 [2.0-16 修复记录](../audits/scheduled-picker-dismiss-2.0-16/README.md)。

## 图片添加到表情

入口：插件设置 → 功能增强 → 表情功能 → 图片添加到表情开关。首页的“定时任务”和“表情功能”与其他功能一样不显示右侧箭头，点击仍进入对应二级页。页面使用公共设置组件，原有开关值沿用同一个配置键，不因升级重置。开关默认关闭，开启后在普通会话图片的长按菜单中显示“添加到表情”。该开关作为“消息操作”设置参加原有配置备份/恢复/重置。

1. 菜单保存账号、代次、会话及消息身份，沿用微信菜单顺序和原生过滤，避免同一项重复出现。已有原生同名菜单时保留原生项；原有表情消息继续使用微信自己的保存入口。
2. 从原消息的高清/中图路径读取实际文件，不读取会话缩略图。路径在主线程获取，文件读取在媒体 IO 队列进行；最多读取 32 MiB 的普通文件。
3. 图片缺失时，用 `MMContext` 的 `IDownloadImageExt` 协议对象注册本次观察者，调用原生图片下载，校验返回消息的会话与本地/服务器 ID 后再继续。过期、失败、超时则静默收尾，不补充插件提示。
4. 静态图片通过 ImageIO 校验并限制解码内存，再创建 `EmoticonCreateImageUploadTask initWithImage:`；实际拿到的 GIF 字节交给 `initWithGifData:`。如果微信原先已经将动图转为静态图片，本功能不能还原动画。其他多帧格式不会静默压成单帧。
5. 原生任务负责表情转换、MD5、重复检查、容量限制和上传。微信的图片任务会关闭自动成功提示；2.0-14 在成功回调中、清理委托前调用微信的 `showSavedTips`，沿用原生文案、样式和语言。单项结果必须成功；批量结果按原生字典逐项检查 `uploadSuccess`，失败、待上传、超限或未知结果不显示成功。主线程执行并防止重复回调；原生已自行显示时不重复，操作取消或账号/上下文失效后不补弹。加载、添加、重复点击、成功、失败、超限和超时全过程均不显示插件自制提示，其他原生提示保持原样。

同一图片正在处理时重复点击不会再次提交；同时最多处理 4 张，90 秒未确认则静默结束等待。切账号、关闭开关、离开前台、隐私状态变化或消息被复用后，未提交操作停止；只移除自己的观察者，不取消微信共享的下载。已经交给微信的上传可能继续完成，插件不会声称能够撤回，也不会自动重试。

接口签名不匹配、格式不支持或原图不可读时静默停止；不会直接改写微信表情数据库。详细原生证据见 [原生链路调查](../evidence/image-to-emoticon-native-2026-10-26/findings.md)。

## 核心代码与回归

- `CSScheduledTaskStore`：规则、持久化、错过处理及重复保护。
- `CSScheduledTaskManager`：最近到期定时器、账号/授权/会话门禁、原生文字提交。
- `CSScheduledTaskSettingsViewController`：统一设置样式的任务列表、文字/时间编辑和执行记录。
- `CSNativeContactPicker`：复用微信原生好友/群聊选择器，定时任务增加单目标约束，已有调用继续多选。
- `CSImageStickerSettingsViewController`：“表情功能”二级页，保留“图片添加到表情”开关。
- `CSMessageActionMenuAdapter` / `CSMessageActionCoordinator`：新增菜单入口及现有上下文校验。
- `CSMessageImageStickerAdapter` / `CSMessageMediaProvider`：原图读取、下载观察和原生表情任务生命周期。

2.0-14 仅运行 `CS_TEST_IMAGE_STICKER_FEEDBACK=1 bash Tests/verify-message-actions-execution.sh`，254 项图片表情/原生菜单/共享反馈检查通过。新增原生成功提示失败复现，验证同步/异步成功、批量状态、去重、取消/账号/开关边界与 ABI 不匹配；不执行真实上传。详见 [2.0-14 修复记录](../audits/sticker-native-success-2.0-14/README.md)。

## 真机验收

建议先用文件传输助手验证定时任务，避免把测试文字发给其他人。

1. 保持微信在前台，创建“每 1 分钟”任务，首次时间设为未来一分钟并启用总开关；观察连续两次消息与执行记录。关闭总开关，跨过下一次时刻，确认没有新增消息；再开启，确认不补发关闭期间的记录。
2. 单次任务执行后检查自动停用。创建每天及多星期任务，检查“下次”时间与保存时区。编辑、关闭单项及删除后，确认下一次计划更新。
3. 到期前退出微信，分别用默认跳过和“允许补发最近一次”进行测试；重开后只按规则处理最近一次，不出现积压连发。同一账号重启不重复发送，切换账号只显示该账号自己的任务。
4. 检查插件首页“定时任务”“表情功能”右侧均无箭头，仍可点击进入二级页，图片开关状态升级后保持。对照“复读功能”等页面检查图标、行高、文字起点、深浅色与滚动复用；长任务名/会话名不应覆盖标题或开关。私聊/群聊打开的应为微信原生选择器；测试搜索、取消、重新勾选和空选/多选禁止完成。再回密友名单确认仍可多选并清空保存。
5. 如需验证私聊/群聊，使用事先约定的测试会话各建一个任务，核对接收者与正文；密友锁定时检查记录为未发送。没有真机回执前，不将记录里的“已提交”当成送达保证。
6. 打开“图片添加到表情”，分别长按自己/他人发送的已下载图片，检查菜单只出现一次，观察原生“正在添加”结束后出现一次原生“已添加表情”，再到微信自定义表情栏查看，确认全程只有原生提示，不再叠加任何插件黑色横条。再检查透明 PNG、HEIF 以及实际仍保有 GIF 原始数据的消息。
7. 对尚未加载的图片操作，确认正常加载后交由微信添加，连续点击不重复提交。断网、图片过期、表情容量满时同样没有插件提示，微信自身提示保持原样。关闭开关或下载中切账号后，不继续新增表情；已有复读、语音转发与原生表情保存仍正常。

8. 创建一个总开关关闭的文件传输助手定时任务，手动创建配置备份；恢复预览应出现“定时任务”。修改/删除任务后选中该模块，准备恢复并完全退出微信进程再打开。确认任务、文字、目标和规则恢复，总开关仍关闭；手动开启后从下一个未来时刻执行。恢复没有此模块的旧备份时，现有任务保持不变。

仍需真机验证的部分：微信私有接口运行时行为、真实发送/上传和离线队列、系统后台调度、图片格式与表情栏即时更新、设置页面显示。宿主机替身测试及 iOS 编译不等同于这些真机验证。

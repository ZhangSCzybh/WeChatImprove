# 外观与快捷面板适配

本次改动沿用 Objective-C / Logos Hook、独立偏好模型、原生页面适配器及快捷面板中央路由。列表底色使用所属表格的当前外观，底栏颜色在原生状态捕获与恢复边界内处理；新快捷入口复用微信原生服务和首页动作。

## 用户行为

- 通讯录、发现和“我”的列表圆角页底、卡片外围、分组标题和页脚随页面的浅色／深色外观变化；卡片本身继续使用列表圆角已有的配色设置。
- 底栏“选中图标颜色”默认跟随原生，可选择自定义颜色或恢复原生默认。上传图标优先保留原色，包括未设置选中图时使用普通上传图的情况；普通未选中图标继续沿用其原有显示。
- 朋友圈卡片的位置标记使用 `mappin.and.ellipse` 地图图钉，保留位置文字和标签布局。
- 快捷面板可选入口从 19 项增至 21 项，追加 `dark_mode` 和 `global_search`。默认已选的 8 项及用户已有选择、顺序保持原样；新入口按需添加。
- 深色模式切换根据微信当前外观取反，并写入微信原生显式深／浅模式；跟随系统可在微信原生深色模式设置中恢复。
- 全局搜索走微信首页搜索按钮原生入口。从其他主页 Tab 使用时，由现有路由交接至同一窗口的微信首页。后续搜索、取消和返回由微信处理。
- 从快捷面板进入插件主页时，与“我”和微信设置中的原有插件入口一致，创建独立导航容器并以表单样式展示；普通入场完成后不再重复重建表格。从详情返回保留原有滚动位置，账号和隐私状态改变时仍刷新内容。
- 长按输入框语音转文字的普通预览气泡随发送方浅深色配色和单条圆角变化；圆点、展开动画及取消、错误、命令状态保留原生处理。发送后的两种专用文本消息复用现有气泡适配。
- 面板全局搜索在共同的原生搜索展示方法开始前准备分组栏状态。搜索返回期间继续显示原分组栏，避免先安装原始搜索框再恢复分组栏。
- 新选中色 RGBA 配置纳入底栏备份与重置；快捷入口白名单支持新增的两项。微信自身的深色模式设置不写入插件备份。

## 2026-11-24 快捷入口转场修复

用户录屏一在推入接近结束后出现资料卡及分类栏整体向下移动，卡片高度基本不变。第一轮通过保存入场滚动距离、同步 inset 的补偿未解决真机反馈，不能视为有效修复。

本轮纠正入口差异：`CustomEntryHooks` 的两个原有入口都将同一个原生设置宿主作为独立导航容器的根页面，以 `UIModalPresentationFormSheet` 展示；快捷面板原先独有地将该宿主推入微信导航栈。现在仅 `plugin_home` 对齐原有模态入口，`panel_settings` 继续原有 push。移除上轮 `homeAppearanceDistance` 和强制布局补偿，布局交还原有容器。保留正常入场不重复重建表格的优化；账号、存储或隐私状态在入场过程中改变时，完成回调仍重新准备内容。

录屏二在搜索返回约 1.85–2.05 秒时露出原始搜索框。微信的搜索按钮经过 `showSearchBar:` 到三参数 `showSearchBar:searchBar:autoStartGreenMic:`，绕过原先的 `onSearch` / `setSearchBarActive:` 准备入口。新增共同 presenter Hook，在原生方法移动搜索视图之前保存分组栏状态。搜索对象仍由微信的 `self.searchBar` 提供，不改变全局搜索路由。

主机回归执行生产插件路由和真实主页生命周期，覆盖独立导航容器、原微信导航栈、面板设置 push、已有滚动位置以及入场中账号或隐私变化。搜索回归仍覆盖搜索状态提前／延后结束、有／无 native-index scope 的返回顺序。UIKit 导航、布局及原生方法体使用夹具重放；这些检查不能替代同设备重新录屏验收。

## 2026-11-24 语音转文字气泡

新录屏中，输入框长按出现的圆点展开为绿色转写预览，发送后“这是”仍为原生绿色。8.0.80 具有两个独立适配边界：

- 列表中的 `VoiceTransTextMessageViewModel` 和 `VoiceTransTextMessageViewModelV2` 均继承普通文本模型；原适配器使用精确类名白名单，漏掉这两类。现在只将其 `type == 1` 纳入自定义气泡，继续检查真实消息包装、方向与 BubbleInfo。未知文本子类和支付消息仍排除。
- `VoiceTransView_ContentV2` 的 `contentView` 是普通 UIView，不经过消息 Cell 的图片适配。静态核对 `layoutUI`（`0x10664299c`）确认普通 state 1、2 直接给该视图设置 LightGreen，state 8 为特殊配色；`prepareForSendCollapse`（`0x10664f718`）将状态置 0，但不重新设置底色。专用 Hook 在正常预览阶段使用同一份发送方主题颜色和拟合圆角，不拦截其他 UIView。初始圆点不改色，展开期间不接管圆角，原生展开完成后再应用单条圆角；退出正常状态和关闭功能时按拥有关系恢复。

预览尚未形成聊天分组，因此两种样式都使用单条四角圆矩形。真正发送进入列表后，再由现有消息合并逻辑决定相邻气泡的连接圆角。录屏特征与 V2 原生路径的对应属于静态判断，尚未通过设备运行时读取类名或重新录屏确认。

## 真机验收

1. 启用列表圆角，分别打开通讯录、发现和“我”；在微信原生浅色、深色及跟随系统状态下检查页底、空白区域、分组标题、联系人总数和“我”头部，切换外观后不应残留旧底色。
2. 底栏选择自定义选中色，逐项切换；上传普通图、选中图分别检查，恢复原生默认及关闭底栏样式后检查原图和原生深浅色变化。
3. 打开朋友圈瀑布流，检查有位置、无位置和长位置文字的卡片，确认图钉、截断、复用和深色对比度。
4. 在面板设置中添加两个新入口，从微信首页、聊天页及其他主页 Tab 执行。深色切换需实际改变微信窗口；全局搜索需出现原生搜索界面，输入后可得到微信搜索结果。重复取消、返回及交互返回，确认全过程保持原分组栏，不闪现原始搜索框。
5. 备份并恢复自定义选中色与新增入口顺序，确认旧入口配置兼容。切换账号或进入后台后，失效的快捷操作不得继续跳转。
6. 从面板进入插件主页，确认与原有插件入口使用相同的表单展示方式，出现及关闭时资料卡和分类栏没有二次位移；滚动后进入详情再返回，确认保留原位置。分别检查隐私认证、授权恢复及入场期间异步诗句更新。
7. 在浅色和深色聊天中长按输入框语音转文字：圆点和展开动画保持正常，展开后的预览与发送后的文字气泡使用自定义发送方样式。检查松开发送、取消、编辑后发送及关闭气泡样式；特殊录音／命令提示不得沿用普通预览配色。

主机回归覆盖偏好、路由调用边界、主题刷新、底栏恢复和备份校验；实际设备外观与搜索结果仍需以上验收。

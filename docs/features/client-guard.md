# 反检测能力

入口：插件设置 → 账号与安全 → 防封检测，页面标题为“反检测”。

本模块包含此前 framework 的 12 类入口，以及选择性接入 JiDe.dylib 已确认行为的 16 项扩展，共 28 项能力，使用项目现有 Substrate 调用链；不加载附件二进制。这是具有明确差异与未覆盖项的项目实现，不代表完整复刻 JiDe。总开关、各项能力默认关闭，“仅检查期间生效”默认开启。诊断区分用户配置、策略发布、接口安装和实际调用，展示实际与支持的签名、资源就绪状态及回退原因；当前正式版进一步区分类缺失、方法缺失、相反方法身份及签名不兼容，并汇总安装能力数量。能力未开启时不会尝试安装其接口，尚未安装不能证明接口不存在；签名匹配、已安装或调用计数均不代表实际防封效果。

## 2.6-7 当前构建接入

针对用户微信 `8.0.80.34` 的真机反馈，核对了同一版本 IPA 的主程序与 20 个框架，向原有两个能力追加四个真实目标。短版本和构建号必须同时匹配 `8.0.80` / `8.0.80.34`，并通过完整 ABI 核验才安装。

- “替换本地环境检测结果”：新增 `+[JailBreakHelper JailBroken]` 和 `-[JailBreakHelper IsJailBreak]`。先执行原方法保留其检查副作用，再按策略替换 BOOL 结果。未证明这两个本地判断位于好友验证链中，不将其解释为账号风险或环境类型枚举的等价实现。
- “屏蔽本地检测结果”：新增 `-[WCSHmdtMgr isHmdtEnable]` 和 `-[WCSHmdtMgr startTask:behaviorID:config:]`。分别影响后续初始化缓存与后续任务启动，包含经过同一入口的直播采样任务；不取消已运行任务，不承诺未知结果查询返回 nil，也不等于拦截全部上报。

旧接口保留，四个新目标显示支持构建；因此能力可显示“部分安装 2/4”。IDFV、指纹、账户风险、策略回调及证书等未找到可靠对应实现的项仍如实显示未安装，不能按近似名称接入。方法身份提示只作核对，不自动把实例 Hook 改成类 Hook。原始元数据、地址与函数体证据保留在本地 `.theos/client-guard-8.0.80.34-20261116/` 审计缓存。

## 运行状态与刷新

28 项能力共用一份元数据，维护页面分组、排序、同步查询范围、依赖、外部资源、重启要求、实验标记和接口身份。设置页据此生成分组与多行状态，避免页面和运行时分别维护能力列表；实验状态同时以文字提示，支持系统字体大小变化。

诊断按当前微信进程展示每项能力的匹配调用次数、实际应用次数、透传次数和最近结果。固定原因包括关闭、同步范围之外、内部旁路、资源不可用、返回值或副本不兼容、完成回调不兼容、查询未匹配和原方法异常。安装重试不算调用命中；Foundation 路径和实验配置查询先核对目标条件，再计入相关能力。好友范围的“应用”只表示建立同步范围，不能表示好友申请成功。并发读取是即时快照，正在执行的调用可能尚未记入结果。

计数通过固定大小的原子内存结构记录，不在调用中生成诊断字典、写文件或发送界面刷新通知；内容只包括能力、次数和固定原因，不记录好友、请求参数、消息或验证文案。退出微信后计数清空，不进入备份。诊断同时展示当前会话的宿主版本/构建号、实际方法编码与支持的签名族，不预先宣称某个微信版本已通过业务验证。

普通偏好变化先比较本模块的 30 个布尔设置和本机 UUID；相关配置与策略修订均未变化时，跳过资源准备和接口安装。相关变化采用已有资源缓存，仅在需要时重新准备；诊断中的“刷新重检”和返回前台会强制重查接口、备用文件及应急停用标记。没有新增定时轮询。刷新仍检查策略修订与配置快照，防止准备期间的开关变化被旧结果覆盖。

卡顿监控、崩溃监控、安全模式和本地检测启动依赖宿主初始化时机。页面区分“启动时机需验证”和“本次进程变更后需重启”；安装成功不能补放此前跳过的初始化，关闭也不能撤销宿主已作出的决定。手动重检保留诊断阅读位置；诊断页在首次加载视图前设置导航边界并关闭自动滚动边距，保留顶部留白修复。

## 能力与作用范围

| 开关 | 实现 | 边界 |
| --- | --- | --- |
| 隐藏注入环境变量 | 复制 environment 返回字典后移除 DYLD_INSERT_LIBRARIES | 不改 getenv/environ；同时适配当前 processInfo 实例的具体实现 |
| 隐藏 Frameworks 枚举 | 主包 Frameworks 的指定目录查询返回空列表 | 不删除文件，不覆盖 POSIX 枚举和越狱根中的 tweak 目录 |
| 隐藏描述文件路径 | 主包 embedded.mobileprovision 资源查询返回 nil | 只覆盖 NSBundle 的指定方法 |
| 拦截描述文件文本读取 | NSString 指定读取返回不存在错误 | 不拦截 NSData；账号签名页仍读取当前宿主的数据 |
| 替换包信息文件查询 | 指定 Info.plist 路径查询及字典读取使用 siri.plist | 不全局修改 Bundle ID、infoDictionary 或版本 |
| 替换收据查询路径 | 返回用户 Library/StoreKit/receipt URL | 不生成文件，不生成或验证有效收据 |
| 跳过客户端检查 | 按各自 ABI 跳过 checkHook:、checkHookWithSeq:、checkConsistency:、registerAddImageCallBack | 不拦截账号、消息和其他生命周期回调 |
| 过滤检查模块列表 | 复制 ClientCheckMgr.getImageList 返回数组，按末级文件名过滤 | 不改变 dyld 映射；返回值异常时整体透传 |
| 替换检查用 IDFV | 只替换 QIDevice.identifierForVendor，使用独立本机持久 UUID | 不回退 Hook UIDevice，不改系统标识、Keychain 或原有 installation ID |
| 跳过卡顿监控启动 | BOOL 签名匹配时替代 WCCrashBlockMonitorPlugin.start | 不能追溯卸载已经启动的监控；关闭后需重启恢复初始化 |
| 跳过崩溃监控安装 | 替代 KSCrash.install 和兼容类型的 setMonitoring: | 不删除已有崩溃报告；关闭后需重启恢复初始化 |
| 阻止进入安全模式 | 替代 MMSafeModeMgr.shouldEnterSafeMode 的返回值 | 可能影响故障恢复；已选择的启动分支需重启重新执行 |

监控返回值支持 B/c 两种 BOOL 编码；监控参数支持经过完整签名核对的 int/bool。不存在的类或不匹配的接口不安装，诊断中会说明。

## JiDe 扩展

新增能力仍位于同一个“反检测”页面，分为好友验证范围、设备与检测数据、本地风险与策略、检测与日志上报，以及证书校验实验项。每项独立控制，沿用总开关、恢复门禁、原调用链和应急停用机制。

| 开关 | 接入行为 | 边界 |
| --- | --- | --- |
| 好友验证查询范围 | 为 NormalContactVerifyLogic 的两个匹配验证入口建立同步检查范围，原样调用原方法 | 不修改好友请求、操作码、文案、申请频率或原返回结果；异步不自动继承 |
| 替换本地环境检测结果 | 旧接口对匹配的 isJailbrokenDevice、runtimeEnvironmentType 返回 0；8.0.80.34 另接入两项 JailBreakHelper BOOL 判断 | 新目标保留原检查副作用；本地越狱判断不代表服务器风险，旧枚举语义仍需具体版本验证 |
| 过滤设备环境字段 | 对 deviceEnvironmentReport 的字典结果复制后移除 provisioning_type、cert_valid、env_abnormal | 不编造“正常值”，不修改原字典；nil、非字典沿用原结果 |
| 过滤指纹异常字段 | 对 generateFingerprint 的字典结果复制后移除 jb_indicator | 其他字段保留；nil、非字典沿用原结果 |
| 屏蔽基础检测数据 | 对匹配的 MMClientCacheManager.getBasicData 返回 nil | 不影响其他配置检查接口 |
| 替换本地风险结果 | 对匹配的 checkAccountRiskLevel:、currentRiskLevel 返回 0 | 不修改服务端风险状态 |
| 替代安全策略完成回调（实验） | 仅兼容的 completion block 返回成功、无错误 | 回调类型或签名不兼容、缺失时沿用原方法；不证明服务器已同步成功 |
| 拦截扩展检测数据 | 跳过匹配的 WCExtInfo.setCcData: | 不清空或改写 CSyncBaseEvent.setExtSpamInfo: |
| 拦截设备与指纹上报 | 跳过匹配的设备令牌及指纹上报方法 | 只针对已核对名称与 ABI；与其他上报开关独立 |
| 拦截安全日志上报 | 跳过匹配的 uploadSafetyLog: | 不删除已有日志 |
| 拦截异常行为上报 | 跳过匹配的 reportAbnormalBehavior:、flushSecurityEvents | 不拦截一般好友验证与消息处理 |
| 屏蔽本地检测结果 | 旧接口跳过 HMDTManager.startDetection、detectionResult 返回 nil；8.0.80.34 另接入 WCSHmdtMgr gate 与任务启动 | WCS 适配只影响后续初始化/任务（含直播采样）；不取消已运行任务，不替代未知结果和上报 |
| 拦截检测数据上报 | 跳过匹配的 reportDetectionData:channel: | 参数 ABI 不兼容时不安装 |
| 关闭运行时上报配置 | 仅对已核实的两项精确字符串配置键返回字符串 `"0"` | 其他键与非字符串参数沿用原查询 |
| 放宽证书信任判断（实验） | 对匹配的 evaluateServerTrust:forDomain: 返回真 | 可能降低目标连接的证书校验强度，与好友申请是否被接受无直接关系 |
| 停用证书固定校验（实验） | 对匹配的 pinnedCertificates 返回空数组，shouldPinRemoteCert: 返回否 | 只影响指定接口，默认关闭 |

设备报告、指纹过滤是项目基于已确认字段实现的保守处理，并未逐字复制附件中尚未闭合的字段替换值。字典过滤保留原结果的可变性，可变源返回独立可变副本，不可变源返回不可变副本；复制失败、返回自身或不兼容结果时透传。样本中由内部状态控制的部分上报路径，在项目中由用户独立开关明确控制。没有引入样本自行创建的安全类、内部模块扫描，也没有复制仅透传的 spam setter。

运行时上报配置只在 `ExptService.getStringExpt:` 的参数为 NSString，且精确等于 `clicfg_gogwcs_ios_runtime_sdk_dc_dc_report_enable` 或 `clicfg_gogwcs_ios_runtime_sdk_main_cert_chain_report` 时返回字符串 `"0"`。其他键和非字符串参数保留原查询；未核实的其他布尔键、MMContext 配置返回值和签名摘要值不作猜测替代。

对样本第二构造器去重恢复的 39 个安装目标，项目 JiDe 模块包含其中 23 个同名接口适配器；该数字只代表目标交集，不是等价功能数量或效果覆盖率。未覆盖目标包括 `CUtility` 三项、`getBoolExpt:`、`trackEvent:params:`、`MMContext` 配置、`SafeModeMgr` 三项、`MMCrashBlockMonitorMgr` 两项和 `MMTokenService` 三项；另有两层原本主要透传的包装无需为凑数量复制。现有 `MMSafeModeMgr.shouldEnterSafeMode` 与样本 `SafeModeMgr` 的目标不同，监控启动拦截也不能代替全部崩溃上报入口。该比较属于历史样本静态审查，不能据此推断当前宿主已安装或达到相同效果。

## 限定查询与直接检查

“仅检查期间生效”影响环境、资源和 IDFV 查询。四个检查入口在保留原检查时建立同步、可嵌套的线程作用域，结束或 Objective-C 异常时恢复；异步任务不自动继承。内部资源准备通过本模块旁路读取，不在热路径刷新配置或读取文件。

开启“好友验证查询范围”后，两个签名匹配的好友验证入口也可为下游查询建立同样的同步作用域。该项只建立范围，需配合相应环境、资源或设备标识查询能力；单独开启不会替换查询结果。该项关闭时直接沿用原方法；它不会伪造好友申请成功。新的设备报告、本地风险、上报和证书能力直接限定在指定接口，不依赖外层查询作用域。

开启“跳过客户端检查”时，这四个入口直接跳过，内部查询也不会再发生。因此不能将检查屏蔽和内部查询替换的命中次数视为同一件事。getImageList 本身就是检查接口，其列表过滤不依赖外层作用域。监控和安全模式开关是独立行为，不受查询范围开关限制。

取消“仅检查期间生效”会把相应 Foundation 查询替代扩展到进程中的其他调用；主包和资源路径条件仍保留。新作用域固定可增加的能力集合，当前策略仍可撤销已关闭的能力。已有过滤结果、缓存或宿主据此作出的操作不会自动撤销。

## 备用包信息

包信息替换只加载可解析、非空的 plist 字典，按以下顺序查找：

1. 当前主包中的 siri.plist。
2. 当前应用容器 Library/Preferences/WeChatImprove/ClientGuard/siri.plist。

未提供有效资源时保持原查询，诊断中显示原因。本模块不会写入、重签或覆盖宿主 Info.plist，也不会根据别的安装环境生成替代包信息。备用文件应与当前宿主版本对应；切换资源后重新打开微信或刷新设置。

模块过滤使用附件中核实的精确末级名称，并加入当前实际加载的本插件二进制名；不做任意目录或子串匹配。

## 配置、恢复与停用

30 个用户布尔设置（总开关、范围设置及 28 项能力）精确登记在备份与重置模块“反检测”下。独立的 local_vendor_uuid 不进入备份/重置，不随切号轮换，也不复用现有安装标识。本模块不新增远程请求或联系人、消息内容采集。

启动经过 CSBackupWhenReady。恢复事务未完成时不安装；普通启动保留现有构造器顺序。不能覆盖安装前已经发生或被缓存的查询，也不能保证先于其他插件执行。

通过设置页关闭总开关或单项能力时，立即撤销对应策略，后续调用走已有 predecessor 链；开启仍等待正常刷新及资源准备。外部偏好修改或备份恢复通过刷新发布策略。不在运行中强行恢复 IMP，以免切断其他插件；已经开始的调用、缓存结果以及跳过的监控启动不会回滚，完整恢复应退出并重新打开微信。

应急停用文件为当前容器 Library/Preferences/WeChatImprove/ClientGuard/disabled。它存在、无法可靠判定，或宿主/本地容器路径无效时，模块不发布干预策略，也不生成新的替代 UUID。文件在启动及刷新时检查，不是每次调用都读磁盘。诊断分开显示配置总开关和实际发布策略；发布项数不表示对应接口已经安装或命中。该文件不由普通设置备份恢复控制；需要时通过越狱文件工具使用当前真实容器路径处理。也可以由现有注入管理器停用此 tweak。无需删除微信数据或清空偏好域。

## 验证范围

`2.6-7` 正式版清理完整接口快照的冗余缓存、无人使用的调用时间字段，以及诊断末尾重复接口列表；签名记录、最近结果、计数、动态接口和资源状态保持可用。原始状态读取 API 与 fixture 接缝只在测试构建中编译，正式库逐架构排除测试符号及测试输出。正式版实际回归和双方案校验见 [2.6-7 发布记录](../../packages/2.6-7/README.md)。

正式版 `bash Tests/verify-client-guard.sh` 实际通过 **14 个独立进程、2576 条断言**；备份登记通过 **1821 条断言**，恢复门禁通过 **34 项检查**。全部六个防封模块实现文件通过 iOS arm64/arm64e 的严格语法检查。

核心回归使用真实 macOS Foundation 与隔离的测试私有类，Hook 安装边界由 fixture provider 替代 Substrate。覆盖 28 项能力、原参数和返回值、B/c 与整数 ABI、同步范围嵌套和异常恢复、异步不继承、关闭透传、幂等、字典可变性和异常副本、回调签名、计数平衡、无关通知过滤、资源缓存与强制重检、应急停用及同轮关闭后开启。8.0.80.34 专项覆盖精确版本门禁、原方法副作用与异常、任务参数及指针身份，并拒绝未经核实的签名变体。

测试源以 `-Wall -Wextra -Werror` 编译；正式动态库另核对所需模块与四个新目标，并拒绝测试 API、测试宿主状态和 fixture 日志进入任一架构。30 个精确备份设置及恢复门禁的验证由对应脚本维护。

未安装到用户设备；本机测试不能验证真实 UIKit 转场、Substrate/PAC、注入时机、其他插件共存或服务端效果。当前 Theos 缺少 Roothide scheme，本版没有生成 Roothide 专用包。

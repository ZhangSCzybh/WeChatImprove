# 微信会话分组重构方案

日期：2026-10-15。基线：`main` / `3d60e63b`。状态：已确认的设计基线；当前实现和实际验证见 [会话分组实现说明](session-groups.md)，尚未经过目标微信实机验证。

用户确认的范围：保留全部现有分组功能，优先解决稳定性、流畅度和微信原生操作兼容。本文中的类名、性能目标和验证步骤为设计要求；是否已经实现，以实现说明和实际验证记录为准。源码问题表中的行号均对应重构前基线。

## 1. 结论与功能边界

推荐保留微信原生主列表、原生 Cell、会话排序及业务逻辑，在每个主列表实例外增加一个分组投影适配层。UITableView 实际行数等于当前分组包含的行数；筛选后的位置与微信原生位置由同一份不可变快照双向转换。取消隐藏 Cell 和 `0.01` 行高策略。

保留的功能包括：

- 全部、群聊、私聊、服务四类预设，以及自定义分组。
- 自定义分组新建、删除、改名，预设改名与隐藏，分组排序。
- 按群聊、私聊、联系人标签和全部联系人选择成员；标签继续作为选择成员的入口，保存用户名集合，不增加动态标签订阅规则。
- 重复联系人过滤；自定义分组可以重叠，全部分组始终完整，重复过滤保持现有对群聊和私聊预设的作用范围。
- 数字角标、独立隐藏全部角标和其他分组角标，并补齐原生红点语义。
- 列表区域滑动切组、切换触感、指示器与选中文本颜色、滚动灵敏度和滚动特效。
- 分组条的添加、搜索入口；搜索仍由微信原生搜索完成。
- 列表圆角、置顶与普通会话分段样式。

分组筛选微信当前主列表已有的会话，不因联系人被加入分组而创建会话，不展开微信原本折叠到业务盒子中的所有子会话，不改写聊天记录或消息数据库。折叠入口按实际类型保留，不能凭名称推导内部所有成员。

## 4. 方案比较

| 路线 | 优点 | 主要代价 | 决策 |
| --- | --- | --- | --- |
| 保持隐藏 Cell，补缓存、手势和刷新 | 改动最少 | 逻辑行与显示行分离的问题持续存在 | 只适合临时修补 |
| 修改微信 session 数组或全局 Hook 原生计数/查询 | 表面上数据一致 | 改变宿主其他消费者、折叠、搜索、导航和缓存的语义 | 不采用 |
| 每个主列表实例增加分组投影适配层 | 保留原生 Cell 和业务能力，规则可测试，边界可隔离 | 必须完整处理双向索引、更新和异步操作 | 推荐 |

另建整套聊天列表需要复刻微信摘要、业务入口、菜单和无障碍行为，超出本次保留原生兼容的目标。

## 5. 架构和不变量

数据流：微信原生主列表 → 宿主接口适配器 → 不可变会话/行快照 → 分组规则与投影 → 主列表代理 → 微信原生 Cell。原生事件返回更新协调器；分组条、角标与圆角消费同一版本的投影结果。

核心不变量：

1. 微信原生 session 集合、排序、CellData 和业务方法始终保留原生索引语义。
2. UIKit 看到真实显示行数，所有路径始终位于对应显示快照内。
3. 已显示会话的原生/显示路径可以双向往返；未显示行显式返回不存在。
4. 选中分组用 tabId，操作目标用账号和用户名；行号只用于短期定位。
5. 快照不持有可变宿主 session/CellData 对象，不在后台读取这些对象。
6. 当前账号、数据版本、配置版本和适配能力必须匹配后才能发布结果或执行延迟操作。
7. 搜索表、其他控制器的表格、其他插件的未注册表格均不参与转换。
8. 适配失败时在安全边界回到原生全部列表，保留设置与用户数据；不猜测目标。

拟议组件：

| 组件 | 职责 |
| --- | --- |
| `CSGroupPreferences` | 帐号档案、schema、旧配置导入、稳定排序与选中分组 |
| `CSGroupNativeBridge` | 宿主能力探测、账号读取、原生行读取、身份定位、分类信息提取 |
| `CSGroupSnapshot` | 原生 section/行的不可变值、身份及数据版本 |
| `CSGroupProjection` | 分类、成员集合、双向路径表、分组角标和显示行角色；仅依赖 Foundation |
| `CSGroupListAdapter` | 每张主表的 dataSource/delegate/prefetch 代理，明确的回调转换策略 |
| `CSGroupUpdateCoordinator` | 原生重建、UITableView 事务、刷新合并、身份校验、滚动与交互状态 |
| `CSGroupChromeController` | 分组条布局、搜索状态、手势仲裁、动态启停与外观恢复 |

这些是职责边界，不要求一开始拆成大量单方法文件。`SessionGroupHooks.xm` 最终只承担生命周期、已验证的事件入口和表格边界接入。

## 6. 会话范围、分类与快照

以原生主列表的 section 和行结构为权威范围，不把全局 session manager 的数组直接当作表格下标。使用原始 dataSource 的 section/row 数量与逻辑控制器读取结果交叉检查；在重建或事务中途不发布。

每行保存：账号、行身份、原生 indexPath、行种类、用户名、分类、置顶状态、未读数字/红点信息、当前数据版本。快照区分普通会话、聚合入口、Fake 行、业务行与未知行。

普通会话用户名优先来自 `MMSessionInfo.m_nsUserName`，其次来自已确认的 CellData 或 FakeCellData；不要求 m_contact 已加载，也不根据可见标题猜身份。分类优先使用已验证的宿主方法，再使用已知的标识规则；服务分组保留现有文件助手、系统消息等兼容范围。无法可靠分类的行保留为 unknown，不能一概归入私聊。

section 原生语义编号不压缩；筛选后空 section 仍有零行，是否隐藏其装饰表头由显式规则决定。已知业务行按页面角色处理，未知业务行保留原生顺序及操作；无法验证其索引行为则整表回退。

内部重复身份、路径与模型不一致等问题导致本次投影失效，不能用数组下标拼成长期身份掩盖歧义。

成员选择与列表、角标共用分类规则。联系人选择器在不同类型或搜索筛选下保留不可见的已选成员，仅对当前选择范围应用增删，避免编辑群聊成员时丢失原有私聊成员。

## 7. 双向索引与原生操作

例如原生一节包含 A、B、C、D，分组只包含 B、D：UITableView 有两行，显示 0 映射原生 1，显示 1 映射原生 3。点击、行高、Cell 创建、侧滑等调用原生方法前完成转换；原生方法随后向表格查询选中位置、可见行、Cell、行矩形或请求滚动时，表格边界进行反向转换。

只改 cellForRow、heightForRow 和 didSelect 不构成完整方案。需要建立明确的回调清单：

| 边界 | 需要覆盖的内容 |
| --- | --- |
| dataSource | section/行数、原生 Cell 创建、可编辑/可移动、提交编辑、移动目标与结果 |
| delegate | 行高与估算行高、将显示/结束显示、将选中/已选中/取消选中、编辑开始结束、菜单、侧滑 |
| 表格反向查询 | cellForRow、indexPathForCell、命中测试、行矩形、可见路径、选中路径、选择/取消与滚动 |
| MainFrameTableView | 自身 selectedIndexPath、额外 select 方法、tryInsert/tryDelete |
| 原生业务 | logicGetSession/CellData、按用户名定位、删除确认、下一个未读、预览创建与提交 |
| prefetch | 预取和取消预取使用同一快照；版本变化取消旧请求 |

转换上下文必须按表实例和嵌套调用栈隔离，在 finally 中恢复。调用真正的 UIKit 实现前暂时恢复显示上下文，避免 UIKit 内部回调二次转换。cellForRow 与 willDisplay 等同一次交付使用固定快照；Cell 关联其交付时的行描述，didEndDisplaying 不能按新快照解释旧行。

对已知 selector 显式描述参数与返回值的路径语义，单路径和多路径先整体校验再转换。不能仅按方法名含 IndexPath 或参数类型为对象就自动改写；结构体、返回数组、交互 context 和延迟 block 需要各自适配。

dataSource/delegate 被微信重新设置时重新挂接代理，并透传 respondsToSelector 和已知能力。代理在表存活期间被协调器保留，原始宿主对象按其真实生命周期引用；卸载时只有仍然指向本模块代理的属性才恢复，避免覆盖微信或其他插件后续的替换。

### 延迟操作与错误目标防护

侧滑、确认框、长按菜单和预览提交都不能只保存旧 indexPath。保存账号、用户名、行种类及快照版本，执行前重新定位并核对对象。目标已删除、账号变化或无法验证时取消本次操作并刷新。

包装原生 UIContextualAction 的 handler 只能包住执行时机，无法自动修复它内部捕获的旧行号。只有已证明按身份执行或有专用重新定位入口的操作才能在分组下使用；其余在展示菜单前回到原生全部列表。仅延后 UIKit 刷新不能阻止微信模型重排，不能将冻结显示快照当作修复闭包目标的保证，也不冻结微信原生数据更新。不能假设 NSInvocation 或统一代理能修复未知 block。

对 MainSessionEditingLogic 的延迟删除确认，追踪其 confirmingSessionName 等已知身份入口，保证最终委托的用户名与最初选择一致；无法验证则不进入筛选后的危险操作路径。

原生“下一个未读”、搜索结果返回或深链要求定位分组外会话时，临时显示内部全部分组并完成原生定位，不使用最接近的显示行替代。即便用户隐藏“全部”标签，也保留内部安全回退能力，不改写其隐藏配置。

## 8. 更新、事务与滚动连续性

更新事件来自会话重建、会话/未读变更、置顶变化、配置变化、账号变化，以及注册主表的 reload、插删移行、插删移 section、批量更新和 tryInsert/tryDelete。

第一阶段以受控全量快照和合并 reload 为正确性基线，不把微信原生 indexPath 的增删动画直接传给已筛选列表，也不立即引入 diffable data source 替换微信数据源。

- 原生业务逻辑照常更新模型；表格变更转换为“投影需重建”，外层事务与 rebuild 完成后再原子发布。
- 拦截 performBatchUpdates 时保留原始业务更新 block 的执行；其完成回调和 tryInsert/tryDelete 的返回语义必须经宿主验证。验证不清的版本回退，不用无条件 YES 掩盖差异。
- 合并采用从首个事件起算的有界窗口，初始候选 50–80 ms；不能每次消息到达都重设计时器而无限延迟。该值需要实机测量。
- 行侧滑、菜单和预览交互期间延后结构发布；目标消失或账号切换时使操作立即失效，安全结束交互后刷新。
- 拖动、减速期间不强行改 contentOffset；拖动结束后发布待处理更新。角标可在身份和版本可核对时独立更新。
- 纯未读或摘要变化不重新创建分组按钮；布局回调不扫描会话、反序列化 archive 或读取全部配置。

每个分组保存顶部可见会话身份及其相对可视区域的像素偏移；重排或切回时按身份恢复。目标删除时使用相邻候选，均失效则返回顶部。不同账号清除所有锚点和临时操作状态。关闭分组或开始搜索也必须等待当前原生批量更新的安全边界。

冷启动 Fake 阶段只有在用户名、section 和当前账号均可验证时才允许投影；否则先显示原生缓存列表，真实会话就绪后再激活。Fake 到真实列表交接只重建一次有效快照，不复用跨账号缓存数据。

## 9. 未读角标契约

将角标建模为数字和红点两个值，显示规则统一为数字优先，只有红点时显示红点；隐藏开关同时隐藏对应分组的两种呈现。

- “全部”的数字以微信自身经验证的 getTotalUnreadCount 为权威，不用自定义分组数字相加。
- 分类及自定义分组使用同一快照、成员规则和重复过滤规则计算。
- `m_bShowUnReadAsRedDot` 只按已验证的显示语义使用，不能单独推断免打扰并跳过该会话。
- 聚合盒子与子会话的未读覆盖范围必须区分；不同时累加盒子汇总数和已经计入的子会话。无法知道覆盖集合时只表达已知红点，不伪造精确数字。
- 自定义分组允许重叠，同一会话可在多个分组各计一次；所有分组之和不是全局总数。
- 无法获得可靠快照时不把旧账号或旧版本数字继续显示为当前计数。

使用足够宽的计数类型并进行边界处理；99+ 等文本截断只在展示层进行。

## 10. 分组条、搜索、手势和圆角

分组条以稳定 tabId 更新，保留当前选中项；选中项被隐藏或删除时选择确定的可见后继，再回退到可用的默认分组。排序中遗漏的新 ID 必须按确定顺序追加，重复 ID 去重，不允许配置异常造成所有入口失效。

标签使用最小正间距和真实内容宽度，空间不足时横向滚动；长名称、大字体、横竖屏和浅深主题均纳入布局。颜色按当前视图 traitCollection 解析。滚动特效保留其开关，改用可恢复的短暂表现层动画，避免 Cell model transform/alpha 污染复用；遵守减弱动态效果。

分组条作为主列表的兄弟视图。保留原 tableHeaderView、searchBar 和小程序任务栏对象；搜索入口调用原生 onSearch，搜索期间挂起投影和分组手势，返回时恢复之前分组与锚点。

分组条所需空间必须通过单独的布局适配器管理，记录宿主当时的 inset、indicator inset、safe-area 与后续变化，不能反复累加固定高度。采用 inset 占位还是调整内容区域，需要用目标版本验证任务栏下拉的坐标契约后选择；若两者都无法保证原生行为，该版本先回退为随原生内容滚动的分组条。不能仅凭头文件保证固定悬浮布局无副作用。

手势继续支持列表区域横滑，但同一行上同方向的原生侧滑与切组不能同时获得优先权。明确以原生行侧滑为优先：分组条和空白处可直接切组；会话行上仅在没有该方向原生动作且失败依赖可验证时切组。排除搜索、编辑、预览及屏幕边缘导航区域；Cancelled/Failed 均不切组。列表灵敏度选项只影响注册的主表，关闭时恢复宿主值。

圆角模块消费投影中的显示行与首尾/单行角色，不再自行按类型、section、行数缓存另一份筛选结果。现有 ListCornerRadiusHooks 中仅对主会话列表增加共享上下文入口，其他页面行为不在本次重构范围内。移除 SessionGroupHooks 内重复背景和 mask 绘制，复用/禁用时恢复本模块改过的属性。

## 11. 配置保存与升级

分组成员属于账号数据，保存为带 schema 的账号档案，包含自定义分组、名称、顺序、隐藏项、重复过滤和选中 tabId。外观、手势、灵敏度等通用设置沿用已有键；账号 ID 不明时不读取其他账号的成员档案。

旧 archive 没有账号归属，不能自动认领给首次登录账号，也不能复制给每个账号。保留原数据，提供“导入旧分组到当前账号”的显式入口，按 tabId 合并并保证幂等。升级写入新档案前保存原配置字节快照及版本信息；只写插件配置，不改动微信数据库或覆盖整份宿主 Preferences。迁移失败保留旧数据与原始快照。

新格式采用可校验的 property-list 值结构；旧 NSCoding 数据用兼容读取路径逐项校验类型、长度、ID 和成员。损坏数据不通过强制重置全部配置解决。新格式保存成功并读回一致后才更新生效版本；保留上一份有效配置。

设置修改以一次配置事务写入并发布一条事件，协调器在安全边界立即应用。删除强退微信的生效方式，保留原设置入口与含义。

## 12. 性能与兼容性策略

在主线程、原生稳定边界读取宿主对象并提取值。分类每会话每版本执行一次；自定义成员用集合与用户名到分组 ID 的反向索引，避免每一行遍历所有成员数组。目标复杂度随会话数与有效成员关系数增长，而不是每次布局或滚动都执行全量扫描。

快照键包含账号、数据版本、配置版本和能力版本，表实例拥有自己的发布状态；同数量重排也使版本变化。第一版优先同步的小范围纯值计算；只有测量证明必要时才将纯 Foundation 计算移到后台，并在发布时核对账号和版本，后台不持有或读取 UIKit、session 或 CellData。

兼容能力至少区分：原生直通、基础投影、已验证编辑/预览、已验证布局。启用前完成必要能力核对；关键能力缺失的版本不宣传完整支持。未知私有 selector、不可验证的菜单 block、拖放或 focus context 不做通用盲转。

失败回退在事务结束、取消过期交互后执行：停止代理发布，恢复最新宿主引用和本模块布局改动，显示原生全部列表，保留用户配置。提供用户主动开启的诊断开关，记录版本、能力、事件类型和计数；常规日志不输出聊天内容或完整联系人集合。

性能验收使用 1,000、5,000、10,000 条会话和不同成员关系规模，分别测量快照提取、规则计算、UIKit 发布和端到端延迟。目标是在所支持实机上保持滚动帧预算、避免持续消息导致刷新饥饿；具体 p95 阈值以设备基线确定并记录。本文没有声称任何性能指标已经实测通过。

## 13. 实施顺序与交付门槛

1. **运行时契约确认**：记录目标微信/iOS/安装布局，在原生环境检查实际对象与签名、section/Fake/盒子语义、表格更新和异步菜单路径；形成能力表。先验证该方案的关键边界，不一次性铺开所有 Hook。
2. **规则与数据基础**：实现配置、分类、快照、投影、身份和角标纯逻辑；保留现有用户数据。通过模型测试后再接入 UIKit。
3. **原生列表适配**：完成真实行数、双向映射、选中查询、更新事务、搜索与 Fake 交接；在关闭/开启之间可完整恢复。
4. **原生操作兼容**：按动作补齐点击、侧滑、删除确认、置顶、未读操作、长按菜单、预览、下一个未读和深链；逐项做身份验证和能力测试。
5. **交互及样式**：稳定 tabId、配置热更新、手势仲裁、滚动锚点、分组条布局和共享圆角上下文。
6. **完整交付验证**：独立目录构建所需 arm64/arm64e 与安装方案，核对包内容、版本及安装路径；在用户指定真机环境完成验收，记录最终加载版本与配置来源。

各阶段使用独立测试产物与内存/临时配置，不清理用户已有 `.theos` 或安装包，不写入真实微信设置；涉及设备安装、重启或升级时先确认现用微信、安装布局、包路径和数据沙盒，并与共享任务协调服务切换责任。

## 14. 验收矩阵

| 层级 | 必须验证的场景 | 通过标准 |
| --- | --- | --- |
| 纯逻辑 | 多 section、空分组、乱序、删除、重复身份、未知行、重叠自定义成员、顺序遗漏 | 显示顺序与行数正确，双向往返一致；歧义显式失败 |
| 规则与角标 | 红点、数字、隐藏开关、聚合盒子、计数上界、服务分类、重复过滤 | 列表与角标共用规则，全部符合原生权威计数 |
| 配置 | 旧 archive、损坏数据、零分组、隐藏全部、跨账号、重复导入、写入失败 | 无丢失或跨账号归属；失败可恢复上一份有效配置 |
| 桥接与事务 | 嵌套 scope、回调参数和返回值、多路径原子转换、宿主重设代理、批量完成回调 | 无二次转换、错位操作或批量行数异常 |
| 原生操作 | 点击、左右侧滑、置顶/取消、删除确认期间来消息、标记未读、预览创建/提交/取消 | 始终操作最初选择的会话，过期操作取消 |
| 列表更新 | 连续消息、同数量重排、折叠、插删 section、滚动/减速时更新、账号切换 | 不饥饿刷新、不抢滚动位置、不出现旧账号结果 |
| 布局 | Fake 转真实、搜索进入退出、下拉小程序、旋转、大字体、浅深主题、长标签 | 原生对象与入口可用，分组选择和显示角色一致 |
| 启停与回退 | 即时关闭、后台返回、未知接口、其他插件重设 delegate | 恢复原生行为、无残留样式、用户数据保留 |

“编译成功”只确认构建层；“模型测试通过”只确认规则及索引逻辑。目标微信上的完整操作矩阵和数据保留检查通过，才可认定本次重构达到交付标准。

# 后台运行时段、时长及节能策略

状态：已随 `2.1-22` 完成 Rootless / Rootful 编译打包，待本版真机续航验收。日期：2026-10-30。保留原方案文件路径，便于既有链接继续访问；交付与校验见[发布记录](audits/release-2.1-22-background-policy/README.md)。

## 功能与入口

入口为 **插件设置 → 账号与安全 → 后台运行**。总开关开启后，微信进入后台且满足时段、时长、节能和音频条件时，插件通过无声音频尝试延长执行。返回前台或关闭开关立即释放插件保活资源。

| 设置 | 选项与行为 |
| --- | --- |
| 后台运行 | 原有总开关，不自动开启其他功能 |
| 每日允许时段 | 全天，或每天一个时段；支持跨午夜 |
| 每次后台最长运行 | 5、15、30、60、120 分钟或不限 |
| 节能保护 | 低电量模式、电量及系统热状态限制；临界热状态始终停止 |
| 运行状态 | 当前原因、本轮剩余时长、上次后台结果及当前微信包音频能力 |

时段编辑在一个独立页面内同时修改全天、开始和结束时间，点击保存后一次提交；取消或校验失败不写入。最长时长和节能选项保存时合并当前策略，不用打开编辑页时的旧副本覆盖其他选项。保存失败保留原设置并显示错误。

## 新用户与既有设置

| 本机状态 | 有效行为 |
| --- | --- |
| 无新策略，也没有原总开关记录 | 默认总开关关闭、全天、最长 30 分钟、节能保护开启；首次切换总开关时保存该策略 |
| 没有新策略，但已有原总开关记录 | 保留原开关值，沿用全天、不限时、节能保护关闭；临界热状态仍会停止 |
| 已保存有效新策略 | 使用所保存的时段、时长和节能选项 |
| 新策略损坏或无效 | 后台停止保活，提示重新保存设置；设置页用有效默认值供用户修复，不静默覆盖原记录 |

旧用户打开页面、切换总开关、重启进程或收到无关配置通知，都不会被静默改成 30 分钟。首次编辑并保存任一策略选项后，使用保存的完整策略。只把节能保护打开，会保留原来的全天、不限时；需要限时，应另外选择最长时长。

旧 `BackgroundInterval` 值原样保留，仍不参与后台运行。用户可选“不限”，但时段、临界热状态、微信音频优先和 iOS 执行限制仍有效。

## 每日时段与本轮计时

1. 使用设备当前时区和本地日历，开始包含、结束不包含。开始晚于结束表示跨午夜，例如 22:00–次日 07:00。指定时段的起止时间不能相同；全天使用独立开关。
2. 第一次成功启动插件音频时记录本轮起点。允许时段外、等待宿主释放音频或启动失败，不消耗尚未开始的时长。
3. 一旦成功启动，使用包含设备休眠的连续时钟计时。修改系统日期或时区不能延长本轮预算。
4. 系统中断、微信通话/录音、离开时段及节能暂停后仍沿用原起点。例如 10:00 成功启动，10:10 中断、10:20 恢复，30 分钟期限仍是 10:30。
5. 切换总开关、重复后台通知、恢复音频或修改策略不重置起点。改短时长后若已经超时，立即停止；从“不限”改成 30 分钟也从原成功起点计算。
6. 返回前台立即停止音频、结束本轮；随后真正进入后台才建立新一轮。已用完本轮时长后，不会因通知、恢复音频或开关抖动重新开始。
7. 夏令时、时区及显著时间变化后重新计算本地时段边界。重复小时、半小时回拨和跳过的本地时间均按真实日历边界处理。

例如允许 08:00–23:00、最长 30 分钟：22:50 成功启动会在 23:00 停止，10:00 成功启动会在 10:30 停止。07:30 进入后台时不保持音频；即使已安排 08:00 边界，也不能保证届时唤醒已挂起的微信。

## 节能与音频让出

| 条件 | 动作 | 再次判断条件 |
| --- | --- | --- |
| 节能开启且 iOS 低电量模式开启 | 暂停插件保活 | 低电量模式关闭 |
| 节能开启、未充电且电量 ≤20% | 暂停插件保活 | 开始充电或电量达到 25% |
| 节能开启、系统热状态 serious | 暂停插件保活 | 系统恢复 fair/nominal |
| 系统热状态 critical | 始终停止插件保活，关闭节能保护也适用 | 热状态恢复后重新检查全部条件 |
| 微信通话、录音或宿主音频占用 | 沿用音频所有权机制，让出插件持有的会话 | 宿主明确释放且系统允许恢复 |
| 系统音频中断或音频服务丢失 | 暂停/释放插件资源 | 系统允许恢复且服务可用 |
| 音频启动失败 | 保留错误，释放资源 | 新的有效运行机会，不循环重试 |

20%/25% 回差避免临界值反复启停；未知电量 `-1` 不被当成低电量。温度条件来自系统热状态，不代表实测机身摄氏温度。充电不会绕过低电量模式、热状态、时段和剩余预算。

插件只释放自己持有的音频，不能停止微信通话或录音。电量监测仅在启用且处于后台、需要节能判断时开启；退出条件后，仅关闭由插件开启的监测。

## 状态与 AI、定时任务

状态页显示前台待机、后台音频已启动、不在允许时段、本次时长已用完、节能暂停、音频让出及真实启动失败。有限时长在尚未开始时显示“首次成功启动后计时”，运行后显示估算剩余分钟，到期显示已用完；不限时显示“不限”。剩余值在进入页面或状态变化时更新，页面不运行倒计时轮询。上次后台结果仅保留于当前微信进程。

实际音频活跃状态或主要状态变化时，管理器发送 `CSBackgroundRunStateChangedNotification`。运行中的状态文字不附加连续变化的剩余秒数，避免无关事件引发重复 UI 或 AI 刷新。AI 后台兜底沿用对真实 `backgroundAudioActive` 和该通知的依赖，保活停止时停止兜底调度。

策略不会关闭 AI 或定时任务总开关，不清空消息去重、已发送记录或任务记录，也不重新发送已执行任务。到期、离开时段或节能暂停后，微信可能挂起，依赖持续后台执行的 AI 自动回复和定时任务可能无法及时执行。前台和系统实际给予的后台执行机会仍由原功能逻辑处理。

## 调度与配置

实现采用事件通知和最多一个**单次**边界定时器，取下一时段变化与本轮时长截止中的较早者。输入不变时复用现有音频与边界，过期回调用代次校验丢弃。没有每秒/每分钟检查、后台任务续期循环或播放失败自旋。

事件包括前后台、场景、音频所有权及中断、策略保存、电量/充电、低电量模式、热状态、时区及显著时间变化。策略与 UI 状态由主线程管理，来自其他线程的事件先交回主线程。

| 位置 | 职责 |
| --- | --- |
| `CSBackgroundRunPolicy` | 严格版本/字段校验、本地每日时段、下一实际边界及显示文字 |
| `CSBackgroundRunManager` | 总开关、策略兼容、起点/截止、节能暂停、音频协调和唯一单次回调 |
| `CSBackgroundRunViewController` | 时段草稿、时长选项、节能开关和一次性状态展示 |
| `CSBackgroundRunAudio` / 原生 Hook | 已有无声音频、宿主音频所有权及让出逻辑 |
| `CSBackupRegistry` | 新策略的精确字段登记与严格专用校验 |

总开关仍为 suite `com.cyansmoke.wechattweak` 中的 `BackgroundRunEnabled`。新策略保存于同一域的 `BackgroundRunPolicy` 版本化字典，必须包含且仅包含 `version=1`、`allDay`、`startMinute`、`endMinute`、`maxMinutes`、`energySaving`；时间为 0–1439 分钟，时长只接受 0/5/15/30/60/120，0 表示不限，开关为布尔类型。

策略随手动配置备份保存，恢复时严格校验。运行起点、剩余时长、边界回调、当前轮次和音频所有权不进入备份；恢复设置不会导入另一设备的运行预算。原手动备份、恢复事务和账号隔离语义保持。

## 验证范围与系统边界

专项 UI 测试编译执行完整生产控制器，使用记录型 UIKit/Manager 替身验证旧策略不被页面改写、原子时间保存、取消/失败、跨午夜、所有时长、节能开关、最新策略合并、iPad 弹窗锚点、剩余展示和主线程刷新。运行方式：`bash Tests/verify-background-run-settings-ui.sh`。

策略测试和真实管理器测试已覆盖日历边界、连续时钟、音频中断、电量回差、旧设置兼容以及最多一个单次回调，入口分别为 `Tests/verify-background-run-policy.sh` 和 `Tests/verify-background-run.sh`。备份专项验证新策略的手动保存、导入、恢复、显式清除，以及旧待执行事务的校验兼容。完整验证记录见[本轮审计](audits/background-run-policy-2026-10-30.md)。主机行为验证和 iOS 源文件编译不能代替真机后台时序与续航验收。

允许时段只决定微信得到执行机会时是否允许保活，不能定时启动或唤醒已挂起、结束或用户划掉的微信。正在持续播放时可安排停止边界，系统调度与音频能力仍影响实际执行。持续音频、微信原生任务、网络和 AI 请求仍会消耗电量，不承诺固定 CPU 降幅或续航百分比；USB 供电下的 CPU 结果也不能直接等同拔线后的掉电改善。

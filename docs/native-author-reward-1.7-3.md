# 支持作者：固定内容原生赞赏路由 · 1.7-3 历史验证记录

目标流程：点击“支持作者” → 读取内置固定码内容 → 调用微信原生赞赏处理器 → 微信原生赞赏金额选择页。2026-10-17，用户在微信 8.0.78（8.0.78.34）确认已进入原生赞赏金额选择页，诊断同时记录页面可见和原生流程结束。随后用户确认另一微信账号可以直达并完成赞赏。其他微信版本和反复返回重入未单独提供完整验证记录。

## 已取得的实机证据

作者使用 `1.7-2+extract.2` 在微信 `8.0.78`（构建 `8.0.78.34`）手动识别内置图片，捕获来源为 `ScanWXCodeRewardUrlPrefixHandler.handleUrl:`，原始内容为：

```text
m0Ggq8kqRKX/V3Z-Ior(?3
```

作者随后明确确认：识别的是提取页的图片，微信赞赏页显示的作者也是本人“再也不会”。JSON 的 `\/` 解码为 `/`；该值为不透明码内容，不拼接 URL scheme、不做百分号编码、不做前缀匹配。

## 1.7-3 实机直达结果（2026-10-17）

用户明确反馈“可以进入原生赞赏金额选择页”，并提供以下关键诊断：

用户确认与页面观测共同支持原生直达成功。`nativeEnded` 和 `state: 4` 不表示付款成功；后续用户已明确确认第二个微信账号直达并成功赞赏；该付款结论来自用户反馈，不来自 End 回调。

## 实现

- 固定常量位于 `Controllers/CSNativeRewardRoute.m`。点击入口调用 `CSOpenNativeAuthorReward`，创建微信 `MMUIViewController` 宿主，在其首次展示时自动发起一次原生路由。
- 默认初始化 `ScanWXCodeRewardUrlPrefixHandler` 和 `ScanQRCodeLogicParams`，校验 `handleUrl:`、`m_delegate`、`setM_delegate:` 的签名及代理实际绑定，再传入固定字符串。
- 通过声明的 delegate 提供宿主和原生参数对象，来源网页 URL 返回 nil；不自行编造扫码场景枚举，不设置金额、支付渠道或订单参数。
- 初始化采用原生类的默认 `init`。用户已在微信 8.0.78（8.0.78.34）验证：使用该初始化方式可以脱离扫码流程进入原生赞赏金额选择页。诊断标记为 `native-default-init-with-delegate`；此结果不外推到其他微信版本。
- 不读取图片、不初始化相机、不打开扫一扫，也不调用图片识别接口。金额选择、下单与支付确认由微信原生流程处理。
- 请求对象持有本次处理器；重复启动无效。原生异常或 12 秒未观察到页面时提供诊断，不自动发起第二次请求。
- 仅在当前导航/展示链中实际观察到可见的 `WCPayQRCodeRewardPayerDetailViewController` 时记录 `paymentPageObserved`。`handleUrl:` 返回、ScanFinish、End 均不代表支付成功。
- 离开宿主或主动返回时解除代理，只停止本次处理器持有的 `qrcodeRewardPayerLogic`。不操作全局支付控制栈。原生金额页覆盖宿主期间保留请求。
- 失败可复制诊断：包含版本、初始化方式、接口可用性、阶段和超时状态，不采集微信原生错误载荷、订单或账户信息。
- 1.7-3 曾归档旧提取工具，1.7-4 已进一步删除该工具源码、Hook、图片及诊断导出。此文描述 1.7-3 的历史实现；当前清理范围见 [1.7-4](native-author-reward-1.7-4.md)。

## 手机验收

1. 安装 `packages/com.wechat.improve_1.7-3_iphoneos-arm64.deb`，彻底退出并重开微信，确认版本 1.7-3。
2. 进入插件设置 → 关于 → 支持作者，观察是否自动进入原生赞赏金额选择页，是否正确显示作者。不需要选择金额或付款。
3. 返回或取消，确认能回到插件设置，再进入一次，检查无残留加载和重复跳转。
4. 若停留在等待页、收到错误或未进入金额页，复制诊断信息反馈。调用原生路由本身不代表页面已打开。
5. 用户已使用另一微信账号验证直达并完成赞赏。作者更新或重置赞赏码后需重新提取并验证。

# 消息操作第一批精简与表情菜单修复 1.8-3

本次在 `codex/message-actions-refactor-1.7-17` 的既有工作树上继续，基线为 `2c343db2`（1.8-2）。用户批准先实施第一批优化，并明确报告独立大表情、表情包、自定义动图及骰子、猜拳没有“复读”菜单。

## 行为与实现

- 引用、收藏、普通转发完成身份与入口校验后直接交给微信原生动作，不再创建发送任务、接收者集合或 180 秒清理回调。关闭增强语音转发时，语音的普通转发也走此路径。即使已有 32 个待处理复读任务，普通动作仍可执行。
- 删除、撤回使用轻量确认状态，确认界面释放后可回收。取消、消息复用、开关关闭后重新开启、切换账号、撤回权限失效均会阻止旧确认；重复确认不会再次操作。
- 只有复读及增强语音转发继续使用完整操作对象，保留原有媒体准备、收件人快照、逐目标提交和原生取消/留言/清理。
- 菜单先判断功能开关和消息类型，按需读取账号及聊天页面。没有增删时返回原数组；仅移除本插件失效或重复项。保留原生条目顺序、数字菜单 ID 避碰，以及微信后续过滤。
- 大表情优先调用经过 ABI 检查的原生 `getViewController`，仅接受 `BaseMsgContentViewController` 及其子类。返回空值、无关类型、错误签名或异常时，仍回退到有界响应链。已知大表情 Cell 的原生实现经 delegate 获取页面，旧代码只查响应链，可能因此丢失菜单资格。
- 骰子、猜拳的 `GameMessageCellView` 自行构建菜单且不调用公共构建方法，本版新增明确的菜单 Hook。点击复读继续走现有表情发送入口 `AddEmoticonMsg:MsgWrap:`，使用独立副本，交接时保留游戏类型、结果及 MD5。开启游戏辅助时仍会进入原有的结果选择流程。

原生表情发送实现未改写；此轮用户报告的是入口缺失。当前样本的原生工厂存在 `SetGameContentForMsgWrap:`，本版不新增对此方法的调用，也不主动生成随机结果。接收端实际显示的游戏结果、动画和游戏辅助交互仍待设备验收。

## 验证

四组旧版负对照在临时源码副本中运行，分别复现普通动作被任务上限阻止、菜单原数组无法复用、大表情页面查找失败、游戏表情菜单缺失；原工作树未回退。原始结果见发布证据的 `host/baseline-*.log`。

最终主机检查共 **58,370 项**：执行/原生适配/媒体 522，核心策略 1,362，手势/生命周期 272，消息时间 142，消息合并及导航 53,200 + 2,872。测试使用隔离设置域和宿主替身，不发送微信消息。新用例覆盖两种大表情结构、骰子与猜拳、重复构建/原生限制过滤、原消息保留、旧菜单点击拒绝、普通动作在任务池满时执行，以及确认期间的取消和身份变化。

`1.8-3` 使用全新临时 Theos 构建目录生成 Rootless `arm64` / `arm64e` 包；最终源提交、构建日志、包哈希、两架构类与 Hook 注册验证见 [发布证据](evidence/message-actions-1.8-3/README.md)。原有 `.theos` 和历史 `.deb` 按哈希保护。没有更改主工作区、安装到手机、发消息、推送或合并分支。

原生结构依据来自本地微信 `8.0.78.34` arm64 样本，与用户报告的微信 `8.0.78` 手机运行状态区分记录。主机与包验证证明代码路径和产物完整，不能代替手机验收；没有实际耗时/FPS测量，不宣称量化性能收益。

## 设备验收重点

在原有环境安装此 Rootless 包后，开启复读，长按独立大表情、商店表情、自定义动图、骰子和猜拳，确认只出现一个“复读”。普通聊天下点击应只新增一条消息，原消息内容不变；游戏辅助开/关分别检查结果选择及接收端显示。关闭复读后重新打开菜单应不再出现该项。

复查文字引用/收藏/转发，以及删除和撤回确认中的取消；增强语音转发检查选择对象、留言、等待下载、取消和真正收到的语音。微信限制菜单仍保持原有限制。

## 发布后的设备反馈（2026-10-18）

用户确认安装 1.8-3 并完全退出后重新打开微信：普通文字、图片复读能正常发送；截图中的独立大表情仍没有“复读”菜单；自己发送和收到的语音均可播放，但复读和转发均提示“1个目标未提交”。因此本页此前的主机与包验证不能视为这两项问题的设备修复证明。后续确定的语音构造签名修正及表情排查入口见 [1.8-4](message-actions-1.8-4.md)。

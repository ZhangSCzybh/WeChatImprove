# 1.6-40：悬浮底栏动画前台恢复与清理

## 根因与修复

1.6-39 的外观渲染缓存仅检查偏好对象、尺寸、界面风格和原生背景。进入后台或视图脱离后，系统可能清除 Core Animation 动画；返回时这些缓存项不变，代码直接返回，不检查动画是否还在图层上。旧版也没有应用/场景重新激活时的动画恢复入口。

现在通过 UIApplicationDidBecomeActiveNotification 和 UISceneDidActivateNotification 在主线程检查已应用样式、附着窗口且可见的底栏。只补回实际缺失的动画，不重载图标或恢复原生外观。普通布局命中外观缓存时也进行同样检查，覆盖动画在激活后被移除及隐藏底栏重新显示的情况。

扩散呼吸、扩散心跳、经典呼吸、经典心跳均走相同恢复策略。实际动画仍在图层上时不重启，避免重复通知或频繁布局造成节奏中断。无动画、未启用功能、未设置描边颜色、零描边宽度和系统减少动态效果继续遵守原规则。前台通知不会强制显示隐藏底栏。

通知只注册一次，动画键集中定义，无轮询定时器或持续帧回调。

## 清理范围

- 删除仅转发 CSTabBarUpdate 的 CSTabBarVisibilityChanged，调用点直接更新。
- 将观察器安装入口改名为 CSTabBarInstallObservers，与新增生命周期职责一致，并保证幂等注册。
- 删除未使用的 MobileCoreServices 导入以及两个没有引用的默认值常量。
- 删除恢复默认时紧接着会被 loadCurrentSettings 覆盖的重复属性赋值。
- 移除创建图标目录失败时的控制台输出及无用 NSError 中间变量，保留返回失败和界面错误提示。
- 清理历史编辑备注；扫描底栏生产代码，无 NSLog/printf/DEBUG/TODO/FIXME 残留。

保留必要的图标导入、相册/相机授权、颜色选择、配置保存、原生视图恢复以及测试。Tests 目录中的 UIKit 替身、动画记录和通过日志只用于主机回归，不参与插件构建。未删除历史安装包或微信头文件。

## 验证

`bash Tests/verify-tabbar.sh` 通过。除现有几何、偏好、生命周期、原生快照和描边模式测试外，新增：四种模式的动画丢失后应用/场景通知恢复、连续布局/重复通知不重复提交、缓存命中时补回、隐藏期间不强制恢复显示、重新显示后补回、减少动态效果/零描边/无动画/禁用功能不启动动画。

主机无真实 UIKit 窗口，测试记录提交的 CA 动画并模拟移除及查询，实际路径/遮罩仍使用 CoreGraphics 和 QuartzCore。测试验证恢复逻辑，不代表设备真实挂起/恢复和渲染结果。

构建命令：`make package -j4 SCHEME=rootless PACKAGE_VERSION=1.6-40`，包含 arm64 / arm64e。包及哈希见 [validation.json](tabbar-animation-resume-1.6-40-validation.json)。未连接手机，未操作微信配置、账号或数据库。

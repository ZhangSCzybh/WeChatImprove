# 消息时间显示修复（1.6-22）

用户环境：微信 8.0.78.34、iOS 27.0.1、Rootless。用户反馈开启或关闭「点击显示时间」均无时间显示。本次以 1.6-21 为基础修复共同的标签刷新路径，并保留该版本的聊天分组改动。

## 发现与修改

- 原实现只在 `initWithViewModel:` 创建时间标签，依赖 `updateNodeStatus` 更新；其他初始化、绑定或展示路径可能没有标签。现在在模型绑定、布局、重新展示时按需补建并刷新，初始化使用原方法实际返回的实例。
- 文字子模型的头文件声明通过 `parentModel` 提供完整消息信息。原显示逻辑要求子模型自己实现 `isSender`，可能提前返回。现在发送方向、时间戳和分段选择统一使用逻辑父模型。
- 原时间戳回退只接受 unsigned int，而原生 `createTime` 声明为 double。现在按方法签名读取这两种类型，拒绝无效或超出范围的时间。
- 原点击判断把整个内容容器也视为气泡，可能屏蔽气泡外点击。现在优先使用实际背景气泡并转换坐标，不再要求等待所有原生点击手势失败。
- 自动显示与点击显示共用刷新逻辑，复用消息时清除上条消息的点击状态。标签和手势复用，文本与设置未变化时复用样式和测量结果。

未新增定时轮询、历史消息扫描或列表重载。布局会执行轻量状态检查；实际帧率和耗电仍需设备测量。

诊断开启时按视图状态变化记录 `time: missing-sender`、`missing-timestamp`、`waiting-for-tap` 或 `shown`。`shown` 表示代码已设置标签为可见，不代表已验证屏幕像素；记录不包含消息正文或标识。

主机测试从生产 Hook 提取刷新、布局、点击及设置刷新代码，使用 UIKit 替身执行。覆盖跳过旧初始化入口、父模型信息、配置开关、气泡外点击、复用、重复布局及时间戳回退；不模拟 Logos 安装或微信原生手势竞争，不能代替实机验收。

## 实机复核

1. 安装 1.6-22 Rootless 包并重新启动微信。
2. 开启显示消息时间，关闭「点击显示时间」，确认群聊与私聊的文字、图片、语音消息均显示时间。
3. 开启「点击显示时间」，点击消息气泡旁的空白区域；确认再次点击可隐藏，点击其他消息可切换，气泡本身仍执行原生操作。
4. 滚动历史消息并退出重进，检查时间状态、隐藏头像布局和紧密消息合并间距。

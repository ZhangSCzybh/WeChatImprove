## 问题与修复

beta01 主要接入广告开关、素材／网页及广告处理入口，没有覆盖公众号列表组装时的整卡丢弃判断。所提供微信 `8.0.80.34` 的普通列表与 Box 列表都在卡片构造前调用 `BrandTimelineMsgMgr +canTimlineMsgDiscard:`，但配置中的广告排除还存在直接读字段的路径，不能仅凭外层开关方法存在就认为列表受控。

beta02 新增五个经过 IPA 完整 ABI 核验的 Hook：两个列表加载入口、一个共享丢弃判定、两个迁移上下文保护。只在当前线程的列表加载调用范围内，保留原丢弃判定，再使用微信 `CMessageWrap -isBizAdCanvasMsg` 判断广告整卡并跳过。该谓词对应主类型 `10002`／广告子类型 `6`；推荐 Canvas 为子类型 `8`，继续由原流程处理。

这样既能处理已有广告消息，也能处理素材字段为空的广告卡。普通和 Box 两条路径在转换卡片前完成跳过，避免留下空卡；消息转换器和消息增删通知保持原行为。过滤不修改原消息、数组、缓存源或数据库。

共享判定也供 AFF 历史迁移使用，因此两个迁移前驱调用期间暂时停用展示上下文，原工作、对象返回值及异常均透传；正常和异常返回都恢复之前的上下文。任何必备迁移保护缺失或 ABI 不兼容时，不安装新增展示过滤，之后可按现有流程重试。原 completion 对象完整透传，不进行猜测性回调包装。

新增处理仅受 **总开关 + 订阅号广告**控制，不要求开启其他五个广告范围，也不改变订阅号推荐内容的独立开关。默认值及设置页布局沿用 beta01。详细证据见 [订阅流审计](../../docs/audits/ad-purification-subscriptions-beta02/README.md)，设置说明见 [广告净化功能文档](../../docs/features/ad-purification.md)。

## 聚焦回归

对最终五 Hook 源码执行 **614 项检查，全部通过**；未重复与本次修复无关的全量矩阵。

| 检查 | 结果 |
| --- | --- |
| `Tests/verify-ad-purification-subscriptions.sh` | **456 项**新增专项，实际链接生产模块和核心安装器 |
| `Tests/verify-ad-purification-native.sh` | **124 项**现有原生回归，在最终源码上重跑 |
| `Tests/verify-backup-bootstrap.sh` | **34 项**启动门禁及 Logos／Objective-C++ 集成检查 |

| 新增接口静态核验 | 五个完整方法声明、方法种类和参数／返回 ABI 均匹配 |

新增专项实际经过两套列表入口和共享判定，并分别模拟普通列表与 Box 的卡片组装：广告、空素材广告和无素材广告整卡跳过，普通文章、推荐卡及其顺序保留，Box 没有空卡。还覆盖以下核心边界：

- 仅订阅号范围独立生效，关闭恢复原输出，反复 `ON→OFF→ON`，以及判别过程中同步关闭。
- 首次迁移保护签名错误时不安装展示过滤；接口恢复后重试成功且已经安装的前驱链不重复。
- 嵌套列表调用、列表异常、迁移重入、迁移对象返回值与异常恢复。
- 真正后台线程的双向上下文隔离，原始宽整数、两个布尔参数及 completion 对象保持。
- completion 的正常、延迟、空值场景；两个消息转换器、非展示判定、配置 getter 和 BoxVC 接口保持原处理。
- 不支持的对象、错误广告判别签名或异常保留原判定；源消息、素材和数据数组不被改写。

测试使用独立临时偏好与宿主接口替身，不连接微信数据库。旧版 710 项去广告基础回归与 1,929 项备份集成结果仍仅对应 beta01，本轮没有将未重跑的项目计入 614 项。

## 构建与交付核验

从当前源码冻结 **42,606 个构建输入文件**，使用独立缓存构建。Rootless 约 **21.6 秒**、Rootful 约 **24.2 秒**完成。构建后逐文件核对，当前构建源码与冻结输入一致。两方案各有 8 条既有警告，去除终端颜色后与 beta01 消息集合一致，**无新增警告**。

已核验 Debian 包名、版本、包架构及实际安装路径；载荷只含动态库与注入 plist。双架构最低 iOS、Rootless RPATH、逐架构 CodeDirectory 哈希、四份 dSYM UUID、符号 ZIP 内容／CRC、独立动态库与 Rootful 包内载荷一致性及四个附件的 SHA-256 均通过。动态库含新增生产模块和关键选择器，没有测试接口或 fixture。

构建未执行 `make clean`。37 个已有发布文件的 SHA-256、大小及修改时间保持，包含 beta01；本轮仅新增 beta02 交付目录。构建源码快照、日志、回归摘要、警告对比、源码差异及产物验证保存于本地 `.theos/release-2.6-9-beta02/`，不进入安装包。

## 安装后验收

在原 Rootless 环境安装 beta02 后，完整退出并重新启动微信，确认“广告净化”总开关与“订阅号广告”开启，再重新进入公众号列表。重点检查录屏位置的广告整卡与空白占位、普通公众号文章、翻页和返回重进；需要保留推荐内容时，保持“订阅号推荐内容”关闭。

本版尚未安装到手机实测。上述结果证明静态接口、主机行为回归和产物构建通过，实际广告消失、界面交互及其他插件共存仍需设备验收；也不能据此保证所有 AFF C++／Flutter 路径或其他微信版本都经过本次核实的两个 ObjC 列表入口。

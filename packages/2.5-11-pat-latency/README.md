# 2.5-11 缩短后台拍动轮询等待

本版基于已发布的 2.5-10（提交 `d886eb8c`），调整拍动后台补拉的轮询与复查间隔。调整前的源码、测试和版本资料已冻结到本机 `WeChatImprove-local-archive/audits/2.5-11/baseline/source/`；2.5-10 及此前安装包继续保留。

## 行为变化

| 场景 | 本版处理 |
| --- | --- |
| 拍我自动回拍或拍我自动回复开启且名单、文案等配置有效，微信在后台仍有执行机会 | 按约 10 秒间隔尝试原生补拉，缩短此前约 45 秒的插件轮询等待 |
| 原生同步忙碌或账号、授权等条件暂不可用，尚未调用原生请求 | 约 2 秒后复查，不把这一轮当作已经发出的请求 |
| 已调用原生请求，包含返回 NO 或抛出异常 | 仍消耗拍动的约 10 秒冷却，避免连续调用 |
| 仅 AI 的后台补拉 | 保持默认约 45 秒间隔 |

拍动与 AI 继续共用请求记录，按调用来源选择间隔。没有修改微信原生同步标志，没有绕开原生忙碌、暂停或初始化守卫，也没有把微信 8.0.80 加入尚未验证的原生完整同步观察白名单。

账号与授权检查、会话名单、严格消息入站解析和快照、持久去重、发送流程、0–300 秒用户执行延迟及成功回拍后的撤回规则保留。设置的 0 秒延迟表示事件进入处理后不额外等待，不代表后台获取消息和发送完成都没有耗时。

## 安装包

用户当前环境为 **Rootless**，请选择 [Rootless 安装包](com.wechat.improve_2.5-11_iphoneos-arm64.deb)。另提供 [Rootful 安装包](com.wechat.improve_2.5-11_iphoneos-arm.deb)、[Rootful 重签用 dylib](WeChatImprove.dylib)、[两种方案的调试符号](symbols.zip) 与 [SHA-256 清单](SHA256SUMS)。两个方案均编译 arm64 / arm64e，最低目标 iOS 15.0。

新增验证覆盖 10 秒边界、AI 默认 45 秒与拍动混合调用、共享去重、完整同步覆盖、跨账号、时钟与线程边界、原生 NO／异常冷却，以及前台切换和原生回调重入时不恢复旧定时器。在主机夹具中使用真实定时器，确认账号或授权暂不可用、原生服务缺失及 busy 恢复后，无需外部通知即可继续检查；busy 场景约 2.037 秒恢复。0 秒用户延迟场景在完成两次独立持久认领后各提交一次回拍和文字回复，重复事件没有再次提交。这些是主机夹具结果，没有连接微信服务器或实际手机。

源码与基线逐字核对：生产行为修改限于共享预算接口，以及 Manager 的后台同步刷新、调度和两个间隔常量；所有 Hooks、AI 生产代码、拍动入站解析与快照、持久去重和正常动作路径保持不变。没有新增运行时调试或诊断设施。

安装包核验通过：版本均为 2.5-11，Debian 架构、安装路径、arm64／arm64e 切片、最低 iOS 15.0、Rootless RPATH 及注入 plist 正确；符号压缩包 CRC 和四个 dSYM UUID 均与对应包内切片匹配。四份产物的校验和见 `SHA256SUMS`。历史 52 份产物的 SHA-256、大小和修改时间均未改变。

## 验证限制

约 10 秒是插件尝试请求的间隔，约 2 秒是未发出请求时的复查间隔，均不是拍动送达或自动回复的保证时限。网络、微信原生同步与发送服务、账号和授权状态以及 iOS 提供的执行机会仍影响实际时效；系统挂起或进程退出期间插件不能实时运行。

本版尚未安装到手机实测，不能把主机测试或 2.5-7 的历史用户验收写成本版的实际送达验证。更频繁的后台补拉可能增加网络与耗电，实际延迟改善、锁屏稳定性和耗电需在用户原有 Rootless 环境确认。没有更换账号、配置、数据库或运行环境，没有执行数据库迁移。

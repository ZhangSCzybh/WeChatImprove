# 2.6-2 拍动后台兜底补拉独立开关

本版在 2.6-1 的后台运行改造上，为拍动原有的约 10 秒主动补拉增加独立开关。入口为 **插件设置 → 自动功能 → 后台消息 → 拍动后台兜底补拉**，按微信账号保存，默认关闭，同时作用于“拍我自动回拍”和“拍我自动回复”。

| 开关状态 | 行为 |
| --- | --- |
| 关闭 | 停止拍动专用主动补拉，不创建这一路定时器；继续接收并处理微信原生送入的拍动。 |
| 开启 | 拍动模块、会话名单和文案等配置有效且微信有后台执行机会时，使用原来的约 10 秒主动请求间隔；尚未请求时，原生忙碌或临时不可用按约 2 秒复查。实际调用后，返回 NO 或异常仍消耗请求冷却。 |

回拍、拍动回复各自的执行延迟、名单、账号授权、持久去重及回拍撤回规则保留。执行延迟设置为 0 秒且相关条件可用时，原生拍动入站后直接尝试处理，不等待拍动补拉定时器。新增开关只控制主动获取消息，不拦截拍动入站或关闭拍动动作模块。

AI 的“后台兜底补拉”继续由 AI 设置独立控制，约 45 秒规则保持。AI 与拍动主动请求仍共享请求记录；AI 的通用同步可能顺带取回拍动。若要验证完全依靠微信原生消息触发，应同时关闭拍动和 AI 的兜底开关。

后台运行继续使用 2.6-1 已完成的方案：进入后台立即申请有限任务，1.5 秒首次检查，默认 25 秒、可配置 10–30 秒的周期；条件满足时单次播放微信主包的 `blank.caf`。音频接管、通话录音优先、前台清理及多 Scene 生命周期保护继续保留。拍动补拉开关不会自动开启后台运行。

本次生产改动与影响：

| 文件 | 改动 |
| --- | --- |
| `CSAutomationManager.m` | 在拍动后台补拉需求判断中增加开关门禁，复用原有停止、取消及代次保护；原生拍动入站不经过该门禁。 |
| `CSAutomationStore.m` | 新增账号配置字段 `patBackgroundFallback`，默认 NO；旧五字段配置仍可读取，缺少新字段时按关闭规范化；校验拒绝非法值和未知字段。 |
| `CSAutomationSettingsViewController.m` | 增加独立开关；复用原有账号、授权、配置代次和异步保存流程，更新说明。 |
| 版本及说明 | `control`、插件显示版本和应用内发布说明同步为 2.6-2，README 更新到当前行为。 |

新开关随自动功能账号配置备份，旧备份缺字段时按关闭处理。恢复仍按原规则关闭四个自动动作模块，并保留各账号的归属与持久去重记录。开启或关闭补拉不修改现有名单、文案及执行延迟。定时任务、红包、自动收款及其他自动规则沿用现有实现。

本次聚焦回归全部通过。测试使用生产 Store、Manager、预算与原生入站 Hook；时钟、微信服务及发送边界由隔离主机夹具替代，不连接微信服务器或操作真实账号。

新增验证覆盖：两拍动动作均开启但补拉默认关闭时，没有补拉定时器或同步请求；关闭下 0 秒延迟的原生事件仍各提交一次回拍和文字回复；重复入站去重；运行时关闭取消真实定时器，迟到回调不重启；重新开启恢复受预算约束的请求；旧配置和备份缺少新字段时按关闭处理；各账号配置隔离，以及旧五字段 journal before-image 在中断后正确回滚。

Rootless 和 Rootful 均已使用独立构建目录完成 arm64／arm64e 构建，最低目标 iOS 15.0。444 个生产输入在构建前后 SHA-256 一致。包版本、Debian 架构、安装路径、注入 plist、最低系统版本、Rootless RPATH、四个 dSYM UUID 及符号 ZIP CRC 已核验；包内只有插件 dylib 和注入 plist，没有另加静音音源。保留了既有弃用 API 和链接选项警告，本次修改的三个生产文件没有新增编译警告。

本次构建未执行 `make clean`；原有 114 份发布目录文件（包括完整 2.6-1 产物）的 SHA-256、大小和修改时间均保持一致。

用户当前为 **Rootless** 环境，使用 [2.6-2 Rootless 安装包](com.wechat.improve_2.6-2_iphoneos-arm64.deb)。另提供 [Rootful 安装包](com.wechat.improve_2.6-2_iphoneos-arm.deb)、[Rootful 重签用 dylib](WeChatImprove.dylib)、[调试符号](symbols.zip) 和 [SHA-256 清单](SHA256SUMS)。

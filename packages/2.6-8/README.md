## 本次调整

- **确认释放后立即评估交接。** 微信原生音频调用返回后，主线程处理已确认的释放事件时立即评估，不等待普通周期。优先复用可用有限任务；必要时同一次真实释放最多申请一次桥接任务，重复配置通知不增加申请额度。
- **复用有效后台任务。** 普通检查不再无条件申请替换任务；音频跳过、播放失败或正常播放均沿用仍有效的任务。缺少任务且存在实际音频尝试机会时才补申请，任务到期本身不触发循环申请。
- **合并相邻检查的资源决策。** 相邻 1.5 秒内已有成功音频请求时，仅在同次后台、同一有效任务、相同配置版本和媒体代际、实际会话所有权有效、没有失败或待处理恢复／交接，且有限余量足以覆盖下一周期检查及额外 1 秒时复用资源。真正首次检查仍执行原策略，条件失效后保留重试机会。
- **过滤无须恢复的路由通知。** 插件自身配置引起的同步 `CategoryChange`，以及音频资源仍有效时的良性类别、设备和路由配置变化，不再额外安排恢复或重播。输出设备移除、没有可用路由时暂停并保留 0.4 秒恢复检查；唤醒与未知原因继续保守评估。没有实际恢复计时器时不留下阻塞后续交接的等待状态。
- **统一当前音频状态快照。** 占用、在途调用、释放确认、交接编号、配置版本和媒体代际取自一致样本。迟到通知不再覆盖新状态；采样期间发生宿主变化或配置读取失败时保守让出。读取音频 API 时不持有跟踪锁，播放前后的所有权检查继续保留。
- **保护失败调用后的原配置。** 失败宿主调用未改变配置版本时保留原配置快照；启动使用同一初始样本，避免把插件的 Playback 覆盖为原配置。停止时仅在配置版本未变、没有在途调用时，对每处所有权判断最多复核一次。真实宿主接管或媒体服务边界仍阻止恢复旧配置。
- **保留交接和清理补偿。** 有限任务到期后结束旧任务、取消定时检查，保留交接意图与音频监听，等待新的真实执行机会。微信延迟清理撤销刚取得的音频租约时，同次释放最多补偿一次，仅复用当前任务。
- **保留有限次数的短复核。** 只在微信占用音频、有限任务有效且有正的有限预算时读取状态；间隔 1 秒，报告剩余不超过 8 秒时为 0.5 秒，同次后台最多 30 次，到期即取消。复核不重复播放或申请任务。
- **保留原调度与记录边界。** 进入后台的初次申请、1.5 秒首次检查、默认 25 秒且可配置为 10–30 秒的普通周期均保持；迟到周期不补跑。时间线继续保留最近一次后台过程最多 80 条内存事件，记录交接、等待、失败及资源复用原因。

继续使用微信主包的 `blank.caf` 单次混音播放。普通检查仅在有限余量大于 0 且不足 30 秒时尝试；不生成替代音源、不无限循环播放。微信通话和录音优先，电话、Siri 中断及媒体服务恢复保留各自策略。AI、拍动与群聊的功能开关、业务规则和补拉间隔保持。

## 真机边界

本版未自动安装到手机，不修改微信账号、偏好或数据库。主机回归与编译打包不能证明 iOS 一定延长后台执行时间；真实锁屏交接、音频会话清理、其他插件共存、耗电与温升仍需在原 Rootless 环境安装确认。

如果微信业务声音已结束但共享音频会话仍激活，插件继续保守让出。进程已挂起且没有新执行机会时，保留的监听和交接意图不能自行唤醒进程。

# 2.6-1 后台运行采用短音频检查时序

本版在现用 2.5-11 代码基础上，按已确认的方案 B 替换“后台运行”。检查时序参考 WCRefine：进入后台立即申请有限系统任务，1.5 秒后首次检查；周期从进入后台独立起算，默认在第 25、50 秒等时点检查，可设置为 10–30 秒的整数间隔。只有检查时剩余执行时间为有限值且大于 0、不足 30 秒，才尝试短静音播放并续接任务。

音源直接读取当前微信主包的 `blank.caf`，音量为 0、单次播放。插件不生成、不携带另一份静音音频，也不使用无限循环。正常播放结束只结束本次 player，保留本轮会话所有权及快照供下一次检查复用；有效后台任务仍可提供执行机会。资源缺失或系统拒绝播放时显示原因，等待后续实际检查；首次任务申请就被系统拒绝时结束本轮，避免无资源的定时重试。

任务续接保留本项目的句柄保护：先成功取得新任务，再释放旧任务；新申请失败时保留原有效任务。微信通话、录音、其他音频及系统中断优先，恢复时延迟 0.4 秒并重新检查条件；中断恢复要求系统的 ShouldResume。周期检查落在该等待窗口内时可以续接任务，音频仍等待窗口结束。前台、关闭及多 Scene 生命周期继续按真实系统状态清理资源。

本次改动位置与功能影响：

| 位置／功能 | 改动及影响 |
| --- | --- |
| `CSBackgroundRunManager.{h,m}` | 替换旧预算阈值状态机，新增首次、周期及恢复检查；保留 AI 使用的实际后台执行能力接口和群聊共享需求入口。 |
| `CSBackgroundRunAudio.{h,m}` | 改用主包 `blank.caf`，区分正常完成与播放失败；保留宿主音频接管的 epoch 和快照保护。 |
| `CSBackgroundRunViewController.m` | 新增 10–30 秒检查间隔，默认 25 秒；保留最近后台记录，并更新功能说明。 |
| `CSBackupRegistry.m` | 新检查间隔纳入全局配置备份，校验有限整数及范围；旧 `BackgroundInterval` 仅登记以兼容历史快照和恢复事务，不参与运行。 |
| AI、群聊、定时任务、红包、自动收款 | 共享的后台执行机会改由新保活层提供。AI 的能力判断保留；其余功能继续走自身业务条件及原生服务。本次没有修改这些功能的账号、授权、名单、去重、发送或业务规则。 |
| 群聊拍动回拍／回复 | 拍动入站、动作调度及约 10 秒补拉规则沿用 2.5-11。保活替换本身不能证明微信会在后台即时投递群聊拍动，仍需设备验证。 |

打包前已删除旧 26 秒轮转、8 秒介入／12 秒恢复／5 秒最短播放等策略及对应状态、内存 WAV／PCM 生成接口、无限循环播放代码，以及无人读取的群聊能力 getter 和对应发布状态。实际仍被群聊使用的共享需求入口、Runtime 和音频 Hook 保留。历史发布记录、旧安装包和用户配置均保留。

| 主包音源、单次播放、自然完成、音频所有权 | 56 项通过 |

使用现有 Theos 工具链、`DEBUG=0`、`FINALPACKAGE=1`，分别完成 Rootless 和 Rootful 的 arm64／arm64e 构建，最低目标 iOS 15.0。构建使用本版独立输出目录，未执行项目 `make clean`。构建输入核对通过；原有 108 份发布目录文件的内容、大小和修改时间均保持一致。

两种包的版本、Debian 架构、安装路径、两种 Mach-O 切片、最低系统版本、注入 plist 与 Rootless RPATH 均核验通过。包内仅包含插件 dylib 和注入 plist，没有新增音频资源。符号压缩包 CRC 和四个 dSYM UUID 与包内对应切片匹配；四份二进制产物的 SHA-256 见清单。编译保留了既有功能中的弃用 API 和链接器选项警告，本次后台实现没有新增编译警告。

用户当前为 **Rootless** 环境，使用 [2.6-1 Rootless 安装包](com.wechat.improve_2.6-1_iphoneos-arm64.deb)。另提供 [Rootful 安装包](com.wechat.improve_2.6-1_iphoneos-arm.deb)、[Rootful 重签用 dylib](WeChatImprove.dylib)、[两种方案调试符号](symbols.zip) 和 [SHA-256 清单](SHA256SUMS)。

本版已编译打包，尚未安装到手机实测。主机回归验证代码和资源生命周期；锁屏持续性、通话录音兼容、耗电及微信消息实时投递效果，需在用户原有设备和注入环境验证。短音频播放和重复申请后台任务均不保证系统补充执行时间，也不能在系统挂起或进程退出后自行唤醒微信。
